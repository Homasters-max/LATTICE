# RPT-002 — Сессия «старт» — архив pin-v0-8-1 и полный цикл kernel-format

За один прогон сессия закрыла archive-PR pin-v0-8-1 и провела kernel-format от Run specify через три review и impl
до archive-PR #10 — оба Change ARCHIVED; главные потери — разведка дефекта classify/scope-valid (ISS-025, было W-014) и
незамеченная до самого конца невозможность отметить последнюю задачу `tasks.md` до archive.

## Сессия

Протокол старта выполнен первым сообщением: 5 из 5 проверок (`warrant status` сверен с focus, `switch`, `review_by`,
очередь maintainer'а, >7 правил L0 — предупреждено), но само сообщение — 11 строк, не «до 6» (RUL-002 частично).
Коммитов 27, из них 16 трогают `dev/`. 2 субагента `warrant-reviewer` (review 2, review 3). Оба Change ARCHIVED:
pin-v0-8-1 (PR #6, #7), kernel-format (PR #2, #9, #10, gh/9 head abf763f). ISS-003 и ISS-006 проверены по плану:
review 2 субагент сдал `--file` с первой попытки (W-006 → `verified`), junit 0.8.1 подтверждён в impl-PR (W-003 →
«проверен частично», R-L0-08 `retired`).

## Не хватает

- компактного вывода `warrant` — большинство из 159 вызовов Bash сессии оборачивают ответ в `node -e JSON.parse(...)`;
  ISS-021 остаётся главной причиной длины команд;
- доставки правил субагенту через промпт Agent (RUL-013): оба вызова `warrant-reviewer` получили сырой JSON `run
  start` без единой строки правил — сработало только потому, что `--file` уже зашит в сгенерированный
  `.claude/agents/warrant-reviewer.md`, а не потому что RUL-013 выполнен;
- явного способа посчитать активные правила цепочки (агент считает вручную — «на уровне L0 их 9»).
