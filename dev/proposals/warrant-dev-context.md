# Предложение WARRANT: контекст разработки подключённого проекта

Адресат — сессия WARRANT, вход grilling нарезки фазы 5 (`docs/handoff/phase-5.md`): каждый пункт — кандидат в строку
`BL-N`, решение — процессом WARRANT (grilling, ADR). От LATTICE, 2026-09-28. Закрывается ссылкой на ADR или BL WARRANT.

## Контекст

WARRANT-ADR-0032 решил контекст разработки для самого WARRANT (одно место на вид знания, состояние вычисляется
`brief.js` хуком `SessionStart`, передача — файл на поток, долг — реестр, auto-memory — только личное). В продукт фазы 4
вошли hooks guard и `AGENTS.md` из правил; SessionStart и слой контекста — нет. Подключённый проект (LATTICE) держал
состояние, ловушки и правила работы в auto-memory Claude Code — вне репозитория, без проверки в PR, туда же уходили
нерешённые вопросы. LATTICE заменил её каталогом `dev/` ([README](../README.md)) и предлагает WARRANT штатную часть.

## Граница (тест для каждой части)

1. Что разрешено, что доказано, доставка нормы агенту → **WARRANT**.
2. Смысл, связи, история, «почему», обучение → **LATTICE** (согласуется с `docs/handoff/lattice.md`: «WARRANT на
   LATTICE» — компоненты WARRANT, которым нужны объекты и связи, строятся на read model LATTICE).
3. Остальное, специфичное для проекта → проект.

Над Change WARRANT новых понятий не получает: дорожки, фокус, журнал «почему», проблемы как знание — LATTICE.

## Отличия dev/ LATTICE от ADR-0032 — осознанные

| ADR-0032 | dev/ LATTICE | Почему |
|---|---|---|
| долг — одна таблица, закрытая строка удаляется | файл на проблему; закрытая остаётся `verified` | поля (симптом, обход, `close_when`, `review_by`) не помещаются в строку; нет конфликтов веток; LATTICE при переходе загрузит историю повторений |
| файл передачи на поток, перезаписывается | узел с `focus`, шагами `done: <ref>` и журналом «почему» | цепочка `focus` даёт один следующий шаг; шаг закрывается ссылкой, не прозой |
| правила — `CLAUDE.md` / `rule/1` | правила в узлах по цепочке `focus`, формат — надмножество `rule/1` | контекст агента уточняется по мере спуска; перенос в `rule/1` — копированием (P-1, P-2) |
| auto-memory — личное | выключена полностью | личного почти нет; правила работы — в правилах |

## Что LATTICE не просит

Дорожки, фокус, журнал, реестр проблем, переход LATTICE на собственную основу — остаются в LATTICE.
