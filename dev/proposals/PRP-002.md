# PRP-002 — Шаблоны артефактов Change без инструкций в комментариях и без переносов по ширине — предложение WARRANT

Шаблоны `warrant-sdd` (`proposal.md`, `spec.md`, `design.md`, `tasks.md`) — скелет итогового файла с короткими заглушками, а инструкции — один раз в описании схемы, потому что агент копирует форму шаблона в каждый Change.

## Контекст

Агент копирует форму текста из контекста (опыт `wrap-cleanup` D-1: после чтения одного перенесённого документа свежий Sonnet переносит строки сам, 12 раз на документ; без такого контекста — 0). Шаблоны `openspec/schemas/warrant-sdd/templates/` агент читает перед каждым артефактом Change. Сейчас в них: инструкции в HTML-комментариях по-английски (они остаются в артефактах или их переписывают в текст), блок в `spec.md` и `proposal.md` перенесён по ширине, пример id в `spec.md` записан внутри комментария с искажённым `<!- - … - ->`.

## Пункты

1. Шаблон — сам итоговый файл в минимальном виде: заголовки разделов и одна строка-заглушка `<…>` на раздел; необязательных разделов нет.
2. Инструкции «как заполнять» — из шаблонов в описание схемы (один документ на схему), шаблон на него ссылается одной строкой.
3. Комментарии, которые читает инструмент (`<!-- id: REQ-AREA-NNN -->`), остаются — это данные; пример их размещения — в описании схемы, не в шаблоне.
4. Ни один абзац шаблона и описания схемы не перенесён по ширине: абзац и пункт списка — одна строка. Проверка — `md-wrap --check` (инструмент `C:/Users/Xiaomi/.claude/tools/md-wrap/`, описание — его `README.md`) в CI схемы.
5. Приёмка: свежий агент пишет артефакт по шаблону — без переносов по ширине, без оставшихся инструкций, `openspec validate --strict` проходит.
