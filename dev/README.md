# dev/ — состояние разработки LATTICE

Рабочее состояние разработки вместо скрытой памяти агента: где мы, что дальше, что мешает, какие указания действуют,
откуда всё пришло. Всё в git, видно в PR. Модель — объекты LATTICE (тип, id, зерно, связи-факты), чтобы при переходе
T2 dev/ загрузился `source-files` без переделки. Основа — WARRANT-ADR-0032; отличия — [PRP-001](proposals/PRP-001.md).

## Граница и сигнал остановки

| Кто | Отвечает за | В dev/ |
|---|---|---|
| **WARRANT** | lifecycle и принуждение: статус Change, UNK, evidence, gates, `rule/1` | только ссылки |
| **dev/** | навигация и рабочие указания: вход, фокус, шаги, проблемы, правила, отчёты, триггер | хранится |
| **LATTICE** (после T2) | смысл, связи, история, обучение, предложения | — |

Тест новой идеи: (1) разрешено, доказано, доставка нормы агенту → WARRANT; (2) смысл, связи, история, «почему»,
обучение → LATTICE; (3) остальное и только про LATTICE → dev/. dev/ — не LATTICE v0 и не второй WARRANT: новых
сущностей и автоматики до T2 не добавлять без повтора в отчётах. **Сигнал остановиться:** поле или файл dev/ повторяет
то, что знает WARRANT или OpenSpec, либо dev/ растёт быстрее числа Change — пересмотр модели (отчёт, «Итог»).

## Объекты

Пространство `dev`. Файл — один объект (как `source-files`): frontmatter — поля, первый абзац под заголовком —
`summary`. Папка — тип; признаки, которые меняются (дорожка, источник, уровень, статус), — поля, не путь и не id.

| Тип | Вид LATTICE | id | Файл |
|---|---|---|---|
| `dev/state@1` | сущность, одна | `state` | `STATE.md` |
| `dev/idea@1` — **вход**: идея, запрос, тикет | сущность | `IDEA-NNN` | `ideas/` |
| `dev/track@1` — линия работы | сущность, зерно — имя | `infra`, `foundation`, `s0`…`s9` | `tracks/<id>.md` |
| `dev/work@1` — Change WARRANT или работа без Change | сущность, зерно — имя Change | `pin-v0-8-1`, `dev-state` | `work/<id>.md` |
| `dev/issue@1` — дефект, ловушка, пробел | сущность | `ISS-NNN` | `issues/` |
| `dev/rule@1` — правило | сущность | `RUL-NNN` | `rules:` в узле или в стандарте |
| `dev/guide@1` — стандарт: правила одной темы | сущность, зерно — тема | `code`, `quality`, `tests`, `git`, `docs`, `process`, `reports` | `rules/<id>.md` |
| `dev/report@1` — отчёт отладки сессии | **событие**, не правится | `RPT-NNN` | `reports/` |
| `dev/proposal@1` — предложение в другой проект | сущность | `PRP-NNN` | `proposals/` |

**id.** Префикс — для людей: тип задаёт поле `type`, из id он не выводится (design/domains/10-kernel.md:114). Номер —
следующий свободный по префиксу (смотреть `main` и открытые ветки), не переиспользуется. Где есть естественный ключ
(зерно) — id и есть ключ: имя Change, имя дорожки. Переименование — `aliases: [<старый id>]` (как `core/alias`),
ссылки по старому id остаются верными.

**Ссылки** — `пространство/local`, пространство — владелец объекта:

| Вид | Пример |
|---|---|
| объект dev (пространство не пишется) | `ISS-018`, `RUL-012`, `IDEA-002`, `pin-v0-8-1`, шаг — `pin-v0-8-1#3` |
| объект WARRANT этого репозитория | `lattice/pin-v0-8-1`, `lattice/UNK-KR-005`, `lattice/EVID-…`, `lattice/RUN-…`, `lattice/pin-v0-8-1#I-4` |
| продукт WARRANT | `warrant/BL-82`, `warrant/ADR-0042`, `warrant/REQ-VER-003` |
| git и GitHub этого репозитория | `git/b71a490`, `gh/5`, `gh/5#issuecomment-5865888855` |
| файл репозитория | `design/05-slices.md#s1` |

Временные каталоги, чат и проза («коммит в PR») ссылкой не бывают.

**Связь хранится один раз** — у объекта, который создан позже или зависит (в LATTICE — факт с ролями); обратная
вычисляется: сейчас `grep -rn <id> dev/`, после T2 — `lattice explain`.

| Поле | У кого | Куда |
|---|---|---|
| `from` | idea, work, issue | причина: `IDEA-…`, `RPT-…`, решение |
| `track` | work | дорожка |
| `waits` | work | что блокирует: `ISS-…`, `lattice/UNK-…`, работа, шаг человека |
| `found` | issue | где найдено: `<work>#<шаг>` или `RPT-…` |
| `source` | rule | основание: `ISS-…`, решение maintainer'а (`gh/…#issuecomment-…`), `design/…`, `lattice/EVID-…` |
| `session`, `refs` | report | транскрипт; проблемы, найденные в сессии |

Повтор проблемы — число отчётов, ссылающихся на неё. **Цепочка:** `IDEA` → `work` (`from`) → шаги (`done`) →
`lattice/<Change>` → EVID, PR; `ISS` (`found`) → `RUL` (`source`); `RPT` (`refs`) → `ISS`.

## Файл

Frontmatter: `id`, `type`, `title`, `aliases?`, поля типа. Затем `# <id> — <title>`, **первый абзац — одна фраза-суть**,
затем разделы строго по порядку:

| Тип | Разделы |
|---|---|
| state | Журнал |
| idea | Суть · Исход |
| track | Цель · Журнал |
| work | Контекст (≤ 5 строк) · Решения (только те, чего нет в WARRANT: `id \| решение \| ref`) · Журнал |
| issue | Симптом (точный текст) · Причина · Обход · Закрытие |
| report | Сессия · Сбои · Не хватает · Улучшения · Итог |
| guide | Область · Процедуры (если есть) · Проверка; правила — в `rules:` frontmatter, текстом не повторяются |
| proposal | Контекст · Пункты · Исход |

Строка журнала: `- ГГГГ-ММ-ДД — <событие> (<ref>)`. **Журнал и отчёт не правятся:** ошибку исправляет новая строка
«исправление к ГГГГ-ММ-ДД: …» со ссылкой.

## Поля

| Тип | Поля (кроме общих) |
|---|---|
| state | `focus` (дорожка), `switch`, `env`, `rules` (только ловушки) |
| idea | `kind` (idea · request · defect), `by` (`human:<login>` · `agent`), `from` (решение или null), `outcome` (`{to: [ref]}` · `{rejected: причина, ref}` · null) |
| track | `focus` (work), `depends_on`, `done_when`, `rules` |
| work | `track`, `from`, `change` (`lattice/<id>` · null), `branch`, `pr`, `focus` (номер шага · null), `waits`, `done_when`, `steps`, `rules` |
| issue | `origin` (warrant · lattice · env · agent), `kind` (defect · trap · gap · process), `severity` (blocker · major · minor), `status` (open · workaround · upstream · fixed · verified · wontfix), `date` (найдено), `found`, `upstream` (ref · null — не передано), `close_when`, `review_by` |
| report | `session` (id транскрипта), `period`, `focus` (цепочка на старте), `refs` |
| proposal | `to` (проект), `from`, `outcome` |
| guide | `paths` (область, как у `rule/1`), `rules` |

- **Статуса у work и track нет.** Lifecycle — `warrant status`; готовность — `done_when`; шаг сделан — `done: <ref>`.
- **`done_when`, `close_when` — проверяемые:** список `{check, via}`; `via` — `warrant` (состояние из `warrant
  status`), `cmd` (команда и ожидаемый результат), `human` (акт maintainer'а, ссылка). Проза без способа проверки —
  не критерий.
- **Шаг:** `{n, actor: agent|human, do, done: <ref>|null}`. Шаги — только процесс вне `tasks.md` (Run, review, UNK,
  PR, акты человека); реализация — один шаг со ссылкой на `tasks.md`.
- **`focus` — куда смотреть сейчас, не приоритет.** Смена фокуса из-за blocker или решения человека — строка журнала с
  причиной.

## Правила

Поля: `id`, `text` (1–2 строки), `force` (`normative` — нарушение: стоп и вопрос, принуждения нет · `advisory` — по
суждению), `status` (candidate · active · retired), `source` (обязательно), `owner` (`human:<login>`; у ловушки —
владелец её проблемы), `when?` (`{operation, actor}`), `until?` + `review_by` (у ловушки оба), `overrides?` + `reason`,
`enforced_by?` (только если держит WARRANT). Надмножество `warrant://rule/1` — перенос копированием.

- **Где:** общие стандарты — `rules/<тема>.md`; ловушки проекта — `STATE.md`; уточнения — в узле, к которому относятся.
- **Кто создаёт:** `advisory` и ловушки — агент (`active`, с `source`); `normative` — только по комментарию
  maintainer'а в PR, до него `candidate` (в контекст нормой не входит). Без `source` — на пересмотр.
- **Переопределение ниже:** узел может уточнить или отменить общее правило — `overrides: RUL-…` и `reason`;
  `advisory` — агент сам, со строкой журнала; `normative` — только по решению maintainer'а. Молчаливое противоречие —
  стоп и вопрос.
- **Сборка контекста:** `AGENTS.md` → `rules/` по области → `STATE.md` → дорожка → work → шаг; фильтр `when`, `until`.
  Больше 7 на уровне — сигнал поднять общее вверх или сделать формой в WARRANT. Субагенту применимые правила
  передаются в промпте (RUL-013): dev/ он не читает.
- **Жизнь ловушки:** проблема → ловушка → (upstream исправил → `retired`) · (повторяется и проверяема → форма в WARRANT)
  · (нужна везде → уровень выше или `rules/`).

## Протокол основной сессии

**Старт — первым сообщением, до 6 строк:** (1) `warrant status` сверен с цепочкой `focus`; (2) условия `switch`;
(3) сигналы: просроченные `review_by` — строкой, не приоритетом; (4) шаги `actor: human` — очередь maintainer'а;
(5) правила цепочки: конфликты, >7, без `source`; (6) неразобранные сессии — транскрипты без `RPT` (после
`session-audit`).

**Инварианты:**
- цепочка `focus` без разрыва; следующий шаг один — шаг в `focus`;
- каждый ref в `waits`, `from`, `found`, `source` существует;
- dev/ обновляется в момент события, в коммите самой работы — после `warrant run finish` (внутри Run guard dev/**
  запрещает);
- история неизменна (журнал, отчёты);
- **выход из тупика:** если модель dev/ мешает работе — стоп, `ISS-…` с `origin: lattice`, вопрос maintainer'у; обход
  не изобретать.

**Промах агента** — строка журнала; повтор (по отчётам) или заметная цена → `ISS-…` с `origin: agent`.
**`review_by` по умолчанию:** ловушка +14 дней · blocker +3 · major +14 · minor +30 · шаг человека +1.

## Отчёты отладки

Разбор каждой рабочей сессии — отчёт `RPT-NNN`; пишет не рабочий агент, а отдельный субагент по транскрипту. Правила —
[rules/reports.md](rules/reports.md).

## Куда записывать

| Что | Куда |
|---|---|
| новая идея, запрос, тикет | `ideas/IDEA-NNN` |
| решение по Change | UNK (`PROPOSED`/`SPECIFIED`) или `I-N` в design.md Change |
| решение по продукту | `design/` (заморожен) → spec Change |
| норма процесса для всего проекта | WARRANT rule; стандарт с текстом — `rules/`, доставка — WARRANT rule с `paths` |
| где мы, что дальше, почему свернули | узел в фокусе, журнал |
| дефект, ловушка, пробел | `issues/ISS-NNN` |
| разбор сессии | `reports/RPT-NNN` |
| личная память агента | нет: автопамять выключена (`.claude/settings.local.json`) |
