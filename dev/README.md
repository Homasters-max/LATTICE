# dev/ — состояние разработки LATTICE

Рабочее состояние разработки вместо скрытой памяти агента: где мы, что дальше, что мешает, какие указания действуют.
Всё в git, видно в PR. Основа — WARRANT-ADR-0032 (контекст разработки WARRANT); отличия — в
[proposals/warrant-dev-context.md](proposals/warrant-dev-context.md).

## Граница

| Кто | Отвечает за | В dev/ |
|---|---|---|
| **WARRANT** | lifecycle и принуждение: статус Change, UNK, evidence, gates, `rule/1` | только ссылки |
| **dev/** | навигация и рабочие указания: фокус, шаги, проблемы, ловушки, триггер | хранится |
| **LATTICE** (после T2) | смысл, связи, история, обучение, предложения | — |

Тест для каждой новой идеи: (1) что разрешено, что доказано, доставка нормы агенту → WARRANT; (2) смысл, связи,
история, «почему», обучение → LATTICE; (3) ни то, ни другое и только про LATTICE → dev/. dev/ — не LATTICE v0: новых
сущностей и автоматики до T2 не добавлять; идея доработки — проблема `L-NNN` с `close_when: T2`.

## Структура

```
dev/STATE.md                    L0: focus → дорожка, switch, ловушки проекта
dev/tracks/<track>/TRACK.md     L1: дорожка (infra, foundation, S0…S9); файл — при старте дорожки
dev/tracks/<track>/<node>.md    L2: Change или работа без Change; L3 — steps внутри
dev/issues/<W|L|E|A>-NNN.md     проблемы: W — WARRANT, L — LATTICE, E — среда, A — промахи агента
dev/proposals/                  предложения в другие проекты
```

Хранятся только указатели (`focus`), намерения (`do` шага, `done_when`) и ссылки. Состав дорожки — файлы её каталога.

## Поля

**Узел** (frontmatter `STATE.md`, `TRACK.md`, файла узла):

| Поле | Где | Что |
|---|---|---|
| `schema` | все | `lattice-dev/node@1` |
| `kind` | L1, L2 | `infra` · `foundation` · `slice` (L1); `change` · `work` (L2) |
| `focus` | все | id потомка (L0 → дорожка, L1 → узел, L2 → шаг); `null` — узел не в работе |
| `done_when` | каждый закрываемый узел | критерий приёмки ссылкой; готовность ≠ статус |
| `change` | L2 `change` | id Change WARRANT; статус — только `warrant status` |
| `branch`, `pr` | L2 | ветка и номер PR |
| `waits` | все | связи: `UNK-…`, `W-/L-/E-/A-…`, id узла, `H:<шаг>` |
| `steps` | L2 | `{id, actor: agent\|human, do, done: <ref>\|null}`; следующий шаг — шаг в `focus` |
| `rules` | все | правила уровня (ниже) |

Статуса в файлах нет. Lifecycle — `warrant status`; готовность — `done_when` с ссылкой приёмки; шаг сделан — `done`
несёт ссылку (коммит, `RUN-…`, `EVID-…`, URL PR или комментария), не `true`. Шаги — только процесс вне `tasks.md`
(Run, review, UNK, PR, акты человека); реализация — один шаг со ссылкой на `tasks.md`.

**Проблема** (`lattice-dev/issue@1`): `id`, `origin` (WARR · LATT · ENV · AGENT), `kind` (defect · trap · gap ·
process), `severity` (blocker · major · minor), `status` (open · workaround · upstream · fixed · verified · wontfix),
`found` {date, where}, `upstream` {repo, ref} или `null` (не передано), `affects`, `close_when` (проверяемое условие,
обязательно), `review_by`. Текст: Симптом · Обход · Закрытие. Закрытая не удаляется — `verified` со ссылкой.

**Правило** (`lattice-dev/rule@1`, надмножество `warrant://rule/1` — перенос копированием):

| Поле | Что |
|---|---|
| `id`, `text` | как в `rule/1`; `text` — 1–2 строки, подробности — `ref` |
| `force` | `normative` (нарушение — стоп и вопрос; без принуждения) · `advisory` (по суждению) |
| `status` | `candidate` · `active` · `retired` |
| `source` | обязательно: решение maintainer'а (URL комментария в PR), проблема, `EVID-…`, ADR |
| `owner` | обязательно у `normative` и постоянных: `human:<login>`; у ловушки — владелец проблемы |
| `when` | необязательно: `{operation: specify\|review\|implement\|archive, actor}` |
| `until`, `review_by` | у ловушки обязательны оба: условие снятия и дата пересмотра |
| `overrides` | только при `source` — решении maintainer'а |

Область правила — положение узла + `when`, полем не пишется. Принуждение — только WARRANT (`enforced_by`); в dev/ его нет.

## Правила: кто создаёт и как собираются

- `advisory` и ловушки агент создаёт сам (`active`, с `source`). `normative` — только по комментарию maintainer'а в
  PR; до него — `candidate`, в контекст как норма не входит. Правило без `source` — на пересмотр.
- L0 (`STATE.md`) — только ловушки. Постоянное общее правило — WARRANT rule (`.warrant/local/rules/`, factory-change);
  до переноса — ловушка с `until: <Change> archived`.
- Сборка контекста: `AGENTS.md` → `rules` по цепочке `focus` L0 → L1 → L2 → шаг; фильтр по `when`, `until`.
  Нижний уточняет верхний; противоречие — стоп и вопрос maintainer'у, не выбор; `overrides` — только по решению.
  Больше 7 правил на уровне — предупреждение: поднять общее вверх или сделать формой в WARRANT.
- Жизнь ловушки: проблема → ловушка → (upstream исправил → `until` наступил → `retired`) · (повторяется и
  проверяема → форма в WARRANT) · (нужна везде → уровень выше).

## Протокол основной сессии

Субагенты dev/ не читают — у них промпт и Context Pack.

**Старт** — отчёт до 5 строк: (1) `warrant status` сверен с цепочкой `focus`; (2) условия `switch`; (3) просрочки
`review_by` — первыми, по каждой: продлить с причиной в журнал, закрыть со ссылкой или передать upstream; (4) шаги
`actor: human` — очередь maintainer'а; (5) правила цепочки: конфликты, >7, без `source`.

**Инварианты:** цепочка `focus` без разрыва; следующий шаг один — шаг в `focus`; каждый id в `waits` существует; у
проблемы есть `close_when`; dev/ обновляется в момент события, в коммите самой работы — после `warrant run finish`
(внутри Run guard запрещает dev/**; сбой внутри Run восстанавливается по записи Run).

**Журнал** узла — одна строка на событие со ссылкой: почему свернули, решение без отдельной записи, смена фокуса.
«Сделал X» не пишется — это `done` и коммит.

**`review_by` по умолчанию:** ловушка +14 дней · blocker +3 · major +14 · minor +30 · шаг человека +1 ·
`candidate` — до ближайшего PR.

**Промах агента** — строка журнала; повтор или заметная цена (лишний PR, неверный акт, откат) → `A-NNN`.

**Номера** — последовательно по префиксу; перед созданием — `main` и открытые ветки; дубль при слиянии — переименовать.

## Куда записывать

| Что | Куда |
|---|---|
| решение по Change | UNK (`PROPOSED`/`SPECIFIED`) или `I-N` в design.md Change |
| решение по продукту | `design/` (заморожен) → spec Change |
| норма процесса для всего проекта | WARRANT rule |
| где мы, что дальше, почему свернули | dev/, узел в фокусе |
| дефект, ловушка, пробел | `dev/issues/` |
| личная память агента | нет: автопамять выключена (`.claude/settings.local.json`) |

## Решения

Приняты grilling'ом 2026-09-28 (Q1–Q29 и поправки); подтверждение maintainer'а — комментарий в PR `chore/dev-state`.
Автоматики нет: скрипты, хуки и проверка формы — после реального цикла и только для повторяющегося; форму dev/ после T1
проверяет `lint` LATTICE.
