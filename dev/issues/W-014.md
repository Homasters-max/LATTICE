# Waiver в impl-PR делает Change factory-change

**Симптом.** Правило `process` велит заводить waiver `spec-approved` в impl-PR (`warrant waive` в ветке, активация
коммитом maintainer'а). Путь `.warrant/waivers/WAV-….json` — policy-путь (`match` профиля `factory-change`: `.warrant/**`):
`warrant ci` impl-PR даёт `RECORD_MISMATCH` (classify по diff требует `factory-change`) и `scope-valid` `FAIL`
(`SCOPE_VIOLATION`: для Change без `factory-change` policy-путь вне own state; `ci/paths.js` разрешает waiver'ы Change
только в spec- и archive-PR, N48). Так же `package.json`/`package-lock.json` в diff требуют профиль `chore`.
**Обход.** `warrant classify <change> --base origin/main` в ветке после активации waiver — профили `chore`,
`factory-change`, `feature`; затем `verify` последним коммитом. Цена: gate `factory-golden-passed` на
`VERIFYING->MERGED` (проходит в CI). **Закрытие.** Передать в WARRANT: waiver'ы Change — own state для
`scope-valid` impl-PR и не повод для `factory-change`; до того — правило `process` дополнить шагом classify.
