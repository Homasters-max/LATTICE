# План: вычистить переносы строк по ширине

Убрать из всех Markdown-источников переносы строк по ширине и не дать им вернуться: сначала очистить то, с чего агенты копируют форму, затем документы; возврат ловит проверка `md-wrap` перед коммитом; в конце доказать опытом, что цепочка заражения разорвана.

Правило — [RULE.md](RULE.md). Его текст получают в промпте только исполнители и кураторы этой работы (им решать случаи B, C, R); в общие инструкции агентов (`CLAUDE.md`, `AGENTS.md`) правило не добавляется — опыт раздела 1 показал, что оно не нужно.

## 1. Причина (установлена 2026-09-28)

Модель переносит строки не по своей привычке, а копирует форму текста, который видит в контексте. Опыт: один и тот же запрос «напиши документ Markdown» трём свежим субагентам Sonnet.

| Контекст субагента | Строк-продолжений абзаца | Самая длинная строка |
|---|---|---|
| пустой | 0 | 565 |
| прочитан один документ `design/domains/12-ledger.md` | 12 | 171 |
| файлов нет, но сам промпт перенесён на ~115 символов | 27 | 276 |

Переносы стоят на 97–120 символах, по счёту знаков, посреди фразы («решены / пользователем»). Цепочка заражения: перенесённые навыки и брифы → субагент пишет с переносами → следующий агент читает его документ → переносит сам. Ссылки `файл.md:N` закрепляют форму: склеить абзац нельзя, не сдвинув номера строк.

Второй опыт — сложный документ (frontmatter, вложенные списки, таблица, код, цитата, метки `**Опора:**`) тремя свежими Sonnet:

| Контекст субагента | Переносов по ширине (A) | Другое |
|---|---|---|
| пустой | 0 | метки подряд без пустой строки (L) — 2 места |
| прочитан документ после `md-wrap --fix` | 0 | L — 1 место |
| прочитан код с комментариями, перенесёнными на 120 (`check-refs.mjs`) | 0 | — |

Следствия для плана:

- В чистом контексте агент по ширине не переносит, код его не заражает — правило в общих инструкциях и хук на каждую запись не нужны.
- Агент изредка ошибается иначе — ставит метки подряд без пустой строки (L); это исправляет `md-wrap --fix` при проверке, без участия агента.
- Первыми чистятся источники образца (навыки, брифы, шаблоны), потом документы.
- Промпты этой работы пишутся без переносов: перенесённый промпт заражает исполнителя (первый опыт, строка 3).

## 2. Инструмент `md-wrap` (готов)

`C:/Users/Xiaomi/.claude/tools/md-wrap/md-wrap.mjs` — глобальный, для всех проектов. Структуру документа определяет парсер Markdown из Prettier 3.9.9 (закреплён в `package.json`), меняются только переводы строк внутри абзацев; всё остальное — байт в байт. Тест: `npm test` в папке инструмента (фикстура `test/cases.md` → `test/expected.md`, повторный запуск ничего не меняет).

Команды:

- `node md-wrap.mjs --check <файлы|папки>` — находки по классам с номерами строк; код выхода 1, если есть.
- `node md-wrap.mjs --fix <файлы|папки>` — исправляет классы A и L; файл пишется, только если разбор до и после эквивалентен (дерево и текст совпадают с точностью до пробелов; для L — если снова слить разделённые абзацы). Не прошёл — файл не тронут, в выводе «ОШИБКА».
- `--map <карта.json>` — с `--fix`: записать карту строк «старый номер → новый» изменённых файлов (пути от текущей папки; существующая карта дополняется).
- `node md-wrap.mjs --remap <карта.json> <файлы|папки>` — переписать по карте адреса `файл.md:N`, `:N-M`, `` `файл.md:N, M` ``; сопоставление по концу пути, поэтому работает и между проектами. Отчёт: переписано, неоднозначных, вне файла, «перештамповать» (отпечатки `#abc123` у задетых склейкой строк).
- `--ext .json,.jsonl` — с `--remap`: дополнительно эти типы файлов (индексы с адресами строк, например kb-search в SRA).
- `--json` — вывод для скриптов; `--exclude <подстрока пути>` — пропустить (можно несколько раз).
- `node md-wrap.mjs --hook` — режим хука `PostToolUse` (есть, но не подключается: см. раздел 1).

Фильтр файлов — только `.md` и `.txt`, другие типы инструмент не трогает (кроме явного `--ext` для `--remap`):

- `.md` — склейка, проверка, переписывание адресов.
- `.txt` — только переписывание адресов. В `.txt` перевод строки — часть содержания (таблицы, логи, выводы инструментов): по правилам Markdown такие строки — один абзац, и склейка их уничтожила бы.

Исключения — раздел 3.

Тест `npm test` проверяет и карту: на каждую строку фикстуры — адрес; после `--fix --map` и `--remap` каждый указывает на тот же текст (41 одиночный, 40 диапазонов). Проверено на LATTICE до склейки (`4baf44c`): 31 адрес переписан, все на тот же текст.

Классы находок:

| Класс | Что | Кто исправляет |
|---|---|---|
| A | перевод строки внутри абзаца, пункта списка, абзаца цитаты | `--fix`: склеивает через пробел |
| L | следующая строка — метка `**X:** …` в абзаце вне списка: автор хотел отдельную строку, а при отображении она сливается | `--fix`: делает отдельным абзацем (пустая строка перед меткой) |
| B | метка внутри пункта списка или короткая строка с концом фразы, следующая с заглавной | исполнитель: отдельный абзац, пункт списка или склеить |
| C | жёсткий разрыв (два пробела, `\`) | исполнитель |
| R | адрес строки `файл.md:N`, `файл.md:N-M`, `файл.md:N#отпечаток` | исполнитель: заменить на `файл.md#раздел` или id |

Проверено на копиях (реальные файлы не менялись):

| Область | Исправлено `--fix` | Осталось | Ошибок разбора |
|---|---|---|---|
| LATTICE `design/` | 1709 | R 50, B 1 | 0 |
| LATTICE `dev/`, `.claude/`, `README.md` | 334 | R 1 | 0 |
| свои навыки `~/.claude/skills/` | 471 | R 6, B 1 | 0 |
| `D:\kb` без `raw` | ≈ 24 000 | R 7, B 16 | 0 |

Попутно `--fix` чинит в `D:\kb` вики-ссылки `[[…|текст]]`, разорванные переносом: Obsidian такую ссылку ссылкой не считает.

Сгенерированные файлы не чистить руками — чинить генератор: LATTICE `AGENTS.md` собирает `warrant` из `.warrant/local/rules/`, `D:\kb\_meta\catalog.md` пишет `_meta/kb-lint.mjs` (сейчас оба чистые).

### Этап 6. Шаблоны там, где агенты создают файлы

Форма текста в контексте задаёт форму того, что агент пишет (раздел 1), поэтому каждый вид файла, который создают агенты, получает шаблон — скелет итогового файла без лишнего.

Принципы, одни для всех шаблонов:

- Шаблон — сам итоговый файл в минимальном виде: frontmatter (ключи с заглушками), `# <id> — <title>`, абзац-суть одной фразой, обязательные разделы по порядку. Необязательных разделов в шаблоне нет.

- Язык шаблона — язык документов проекта; заголовки разделов — те же, что в описании типа.
- Как заполнять — один раз в описании типа (`dev/README.md` «Файл», `_meta/schema.md`), не в каждом шаблоне.
- Шаблон проходит `md-wrap --check` без находок.
