Что написать (разделы брифа):
1. **Область** — таблица строк реестра (ID · вид · суть · откат).
2. **Принято выше** — ADR и решения прошлых сессий, которые касаются области (одна строка на решение, с файлом);
   интерфейсы выше по течению, которые использует файл (имя · владелец · адрес).
3. **Триаж** (режим D) — `| ID | Кат. A–F | Суть | Опора | Рекомендация | Вопрос? |`: A следует из принятого; B местное
   решение с вариантами; C дешёвое текстовое; D конфликт с внесённым / ADR; E открытый вопрос v0.3; F устарело.
   Режим R — по каждому решению: вопрос · варианты · критерии и опора · рекомендация итогов · что блокирует · какие
   пункты И от него зависят (● — решение определяет пункт полностью, D внесёт без вопроса; ◐ — частично, остаток в
   скобках) · какие файлы затронет · «Откат» (цена изменения после первых записей). Первой строкой — граф
   зависимостей между решениями области (что решается в первом раунде, что — после). Пункты И области без своей
   темы / ADR, но необратимые — отдельным списком «решить здесь».
4. **Черновик раундов** — фронтир: вопросы, которые можно задать сразу, и зависимые (в следующий раунд); формат
   навыка `grilling` (❓ Qn, ➡️ рекомендация, «Опора:», «Откат:»).
5. **Места правки** — `design/…:NN` из `grep -n` для каждого пункта A–D.
6. **Риски согласованности** — имена, определённые в другом файле; расхождения с принятыми ADR; противоречия
   П / Ф, которые затрагивает область; пункты, которые потянут правку уже пройденных файлов.
Режим ownership — вместо 3–4: таблица карты владения (`reference/formats.md`) по `design-lint.mjs --index`,
глоссарию и разделам «Модель»; понятия без владельца и с двумя определениями — отдельным списком.

Правила: адрес — только из `grep -n`, полным путём; без нового поиска по базе знаний; команды без фона; ≤ 20 КБ.
Ответ — одно слово `ok` (или `СТОП: <причина>`), без отчёта о работе.
