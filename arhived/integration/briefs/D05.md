## 4. Черновик раундов

N-20, N-23) — кроме … ? Отдельно подтвердить: Q-12-2 закрыть по ADR-4 (хранилище на проект, копия без общего
чтения) — единственный вариант, ADR уже решён.
➡️ Рекомендация: принять всё как в §3; Q-12-2 — да.
Опора: T-9 (R1 Q5), T-6 (R1 Q4.1), T-11 (R1 Q2), ADR-2,-3,-4,-8,-19,-23,-24,-27 (все `решён:принять`); D01 N-20;
D02 N-23; D03 (Ф-1, И-10 остаток).
Откат: низкий/средний для большинства; высокий там, где отмечено в §1 (И-2, И-3, И-12) — альтернативы нет, это
перенос решённого T-9/T-6 в текст.

**Раунд 1 — B/D:**
❓ **Q1** (И-10 + Q-12-3). `IndexBlob = {projection, seq, data}`; `saveIndex` — фоново после **каждого** коммита (не
«пока журнал < 50 МБ»); `loadIndex()` сверяет `seq` с хвостом, дочитывает `scan(fromSeq)`?
➡️ Рекомендация: да — старая рекомендация Q-12-3 держалась на пороге «< 50 МБ», который И-1/ADR-23 уже сняли
(триггер пересмотра — p95 пересборки, не объём); фоновый кэш безопаснее и без порога.
Опора: фрагмент И-10; ADR-23 (снимает «< 50 МБ»). «Фоново всегда» — **довод брифа**, не итог.
Откат: сверка — высокий (нужна для корректности); формат `IndexBlob` — средний (вычисляемый, удалить = пересобрать).

❓ **Q2** (10-kernel/И-19, таблица сроков сегментов). ADR-3: «срок по типу = горизонт replay», без числа. Таблица:
`std/execution`/`std/measurement` — один сегмент, срок = большее из (N последних успешных прогонов `setup@n` |
календарное окно конфигурации); число — замером при первом запуске, как ADR-23. Отдельно: значения по ссылке
(composer/judge, И-17=22-run/И-22) — интернированные, не сегмент, срок не ограничен; копия кампании стенда
(`.lattice/bench/<run>`, T138) — вне журнала, ADR-3 не касается.
➡️ Рекомендация: принять таблицу и оба примечания.
Опора: ADR-3 («где срок — решает D01/D05»); ADR-23 (метод замера); фрагмент И-17. Числа и связка «ссылка — не
сегмент» — **довод брифа**, в итогах конкретики нет.
Откат: высокий — заниженный срок тихо ломает replay старых прогонов (виден только явным отказом при обращении).
