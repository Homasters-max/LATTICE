## 6. Риски согласованности

1. **«Импорт» в двух смыслах:** `imports` (T65, `design/02-glossary.md:112`; T-7) и `Source.import()` — загрузка знаний
   (14-trust/И-4, И-5). Развести в глоссарии (с T126).
2. **N-14 тянет R5, R6:** при (б) PF-04 пишет `setup@n`, PF-05 и 23-bench/И-1 закрепляют ту же пару;
   `design/domains/22-run.md:39-40` — барьер перед закреплением (R6, N-4). Записать в «Заметку» PF-04, PF-05.
3. **`origin` у `core`/`std`:** ULID при `init` (R1) даст каждому проекту своё `std` — копия не будет неизменной
   (ADR-4). Довод брифа: `origin` пространств `core`/`std` — константа пакета; уточнить в D01/D06.
4. **ADR-26 против И-4** (§3.7): при (б) — новая ADR `supersedes` (номер с 28).
5. **Подпись сессии `std/release-<версия>`** (отложено R3 в D03/D06) нужна и для копии `std` (ADR-4).
6. **Владельцы (новые строки `ownership.md`):** `core/namespace`, объект пары (Q1), форма `summary` (Q6), тип
   находки-факта (Q4); порт `source` — `?`.
7. **Глоссарий (с T126):** проводка / `bindings`, `$env`, объект пары, `core/holds`, «копия неизменна»; правка T65.
   На ещё не созданные ADR — ссылка по сессии, не по номеру (lint).
8. **Адреса S0-pf сдвинуты:** 21-compose/И-10, И-14 — `:259`, `:263` (в `integration/briefs/S0-pf.md` — `:260`, `:264`).
9. Пройденных файлов D нет — обратных правок нет; больше всего ● получает D06 (15-catalog).
