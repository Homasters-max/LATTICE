## Q-04. Как разделять сущности, события и значения по природе идентичности и когда автоматически склеивать равные значения?

- **Место в дизайне:** KR-04 `design/domains/10-kernel.md:163#50cdbe` — два флага типа (`identity`, `mutable`) дают три
  вида; таблица видов `design/domains/10-kernel.md:38-44#478caf` (сущность — ULID или внешнее имя, версии 1…n; событие — ULID,
  только v1; значение — `#<hash>`, только v1; `content` + `mutable` запрещено). Значения без пространства имён —
  «дедупликация между проектами» KR-12 `design/domains/10-kernel.md:171#1ac95d`. GR-01 «значения интернируются автоматически —
  равны по определению» `design/domains/11-identity-grain.md:129#b4e036`; п. 2: запись существующего значения — no-op,
  ссылки обеих сторон на один `#hash` `design/domains/11-identity-grain.md:40-44#d61738`. Интернирование T29
  `design/02-glossary.md:43#58fb03`.
- **Уже исследовали:** Q-09 C-3 (значения по хэшу, общие для проектов, несовместимы с «забываемой нагрузкой»);
  Q-01 C-4 (ветвление ядра по виду — согласуется); Q-03 C-3 (хэш без версии типа). Здесь не повторяются.
- **Цена отката:** необратимо (`id` значений = хэш; правило интернирования в журнале) → L3 (включает L2).
- **Глубина:** L0 (5 выдач) → L1 (5 разделов 3 карточек; TERM-395, TERM-397 — целиком) → L2 (`related` PAT-146,
  TERM-395 просмотрены; `maps/map-architecture.md:202-203#54dc59` — блок тактических паттернов DDD, новых карточек нет) → L3
  (глава KDDD24-CH06, §Объект-значение, §Сущность).
- **Бюджет:** запросы 1 + 2 узких (+ 2 повтора F3 вне лимита) · разделы 5 + 2 термина целиком (L3: + 2) · главы 1 —
  в лимите.
- **Статус:** отвечен (C-1, C-2); C-3 — рассуждение на опоре одной emerging-карточки; C-4 — база молчит.
