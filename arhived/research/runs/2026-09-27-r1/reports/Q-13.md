## Q-13. Один универсальный механизм фактов-событий для членства, алиасов и утверждений — не слишком ли он общий?

- **Место в дизайне:** KR-13 `design/domains/10-kernel.md:172#f25c53`; §7 — тело `{of, value}`, роли объявляет тип, `key` —
  «тот же факт», пустой `key` — накопление (утверждения, подсказки), `false`/`null` — «закончился»,
  «один механизм» `design/domains/10-kernel.md:109-123#c5faf4`; поля типа `roles`, `key` `design/domains/10-kernel.md:101#649a36`;
  у ядра нет операции для фактов — общий `revision` `design/domains/10-kernel.md:136-146#c84cf5`; grilling 5 — факты
  полноценные события `design/domains/10-kernel.md:184-185#2234d3`. Применения: `core/alias` с ключом `[alias]`
  `design/domains/11-identity-grain.md:82#103225`, разделение — утверждение −1 **или** факт `value: false`
  `design/domains/11-identity-grain.md:87#dfab38`, кандидат в алиас от машины `design/domains/11-identity-grain.md:103#e6da58`;
  подсказка, различие, членство, связь `design/domains/21-compose.md:15-19#286403`; утверждение `core/assert`
  `design/domains/14-trust.md:23#2062fe`, «последнее от сессии по цели» `design/domains/14-trust.md:30#62a6d8`; «в силу при
  основании, требуемом типом» только для алиаса и подсказки `design/domains/14-trust.md:86#3940ae`; факты пишет любой
  участник `design/domains/15-catalog.md:33#efe9fe`; допуск `core/grant` `design/domains/15-catalog.md:36#5ac64a`; устаревание и
  вывод из обращения `design/domains/15-catalog.md:69-70#9fc75b`. Глоссарий T30, T47–T49, T83 `design/02-glossary.md:44#3fe789`,
  `design/02-glossary.md:76-78#d27017`, `design/02-glossary.md:122#d07ebf`.

  `value`) — не повторяются.

- **Глубина:** L0 (5 выдач) → L1 (7 разделов 6 карточек) → L2 (`related`: DEC-056, ANT-102, ANT-105, TERM-407 —
  прочитаны сборщиком, в выводы не вошли; карта `maps/map-architecture.md:131-136#5666e2` — блок Ousterhout «общее и
  частное», новых карточек нет). Главы oust21-ch06, oust21-ch09 не открывались (не L3).

- **Статус:** отвечен (C-1, C-2); C-3 — на опоре дизайна; C-4 — рассуждение.

C-1. Форма факта не слишком общая: один простой интерфейс, много применений, специфика — в типе.
  Опора: E-1 (три проверки интерфейса) · E-3 (механизм / специфика / политика) · E-4 (граница смешения)
  Отношение к дизайну: СОГЛАСУЕТСЯ — KR-13. Проверки DEC-055 проходят: интерфейс — две части (of, value), им
    выражены не меньше девяти видов (member, alias, retire, deprecate, grant, assert, cue, distinct, link);
    вызывающему не нужен код вокруг — «текущий факт по ключу» считает индекс; специфика (какие роли, что значит
    «тот же факт») объявлена данными типа, код ядра о видах не знает (10-kernel:133-134).
  Где в дизайне: design/domains/10-kernel.md:109-123, :172
  Действие: не требуется.
  Неверен, если: появится вид факта, которому нужен код вокруг вызова (например, факт с собственной логикой
    вычисления текущего значения) — сигнал, что интерфейс перестал покрывать нужды.
  Уверенность: высокая · Цена отката: высокая

C-2. Общий механизм не несёт политику записи и вступления в силу — управляющие факты открыты любому.
  Опора: E-5, E-6 (против: чувствительное состояние — один авторизованный писатель; журнал этого не даёт) ·
    E-3 (политика — отдельная часть, не механизм) · E-2 (деталь, нужная вызывающему)
  Отношение к дизайну: ПРОТИВОРЕЧИТ 15-catalog:33 («факты и утверждения — любой участник») для управляющих фактов;
    ПРОПУСК — «в силу при основании» задано только для алиаса и подсказки (14-trust:86); для core/grant,
    core/retire, core/deprecate, core/member в чужом решении ничего не сказано. Допуск, который может записать
    кто угодно, — это право, выданное самому себе.
  Где в дизайне: design/domains/15-catalog.md:33, :36; design/domains/14-trust.md:86; design/domains/21-compose.md:18
  Действие: 10-kernel §6/§7 — два поля типа факта: writers (любой / владелец пространства объекта в роли R /
    допущенный через grant) и inForce (минимальное основание: inferred / observed / declared). Правило owner
    (15-catalog) проверяет writers при коммите; строку 14-trust:86 заменить ссылкой на inForce. Для core/grant,
    core/retire, core/deprecate — writers = владелец пространства цели.
  Неверен, если: управляющие факты уже фильтруются через inForce = declared (владелец) для всех видов — тогда нужна
    только явная запись этого в типах core.
  Уверенность: высокая (дыра) · средняя (механизм) · Цена отката: высокая

C-3. Ключ факта выражается только ролями — «последнее утверждение от сессии» им не выражается.
  Опора: E-2 (новая функция верхнего слоя требует правки нижнего — признак слишком узкого интерфейса) · E-4
    (частный код trust может жить в trust)
  Отношение к дизайну: ПРОПУСК. §7: пустой key — утверждения накапливаются; 14-trust:30 и TR-02: учитывается
    последнее от одной сессии по цели, то есть ключ [target, by]; by — поле заголовка, не роль, и key его не
    видит. Сейчас это держится особым кодом trust.
  Где в дизайне: design/domains/10-kernel.md:119-120; design/domains/14-trust.md:30
  Действие: выбрать одно из двух и записать: (а) key может включать by (сессия) или участника — тогда «текущее
    утверждение» считает общий механизм; (б) утверждения накапливаются, свёртку «последнее от сессии» делает
    trust — записать это в §7 как исключение.
  Неверен, если: других видов с ключом «по автору» не появится — тогда (б) дешевле и достаточно.
  Уверенность: средняя · Цена отката: высокая

    путь.
  Неверен, если: двойной путь намеренный (владелец заканчивает, прочие оспаривают) — тогда записать порядок.
  Уверенность: низкая (рассуждение) · Цена отката: высокая
