C-1. Без фреймворков — оправдано для CLI и библиотеки с шестью портами.
  LATTICE — один процесс, один писатель, CLI поверх библиотеки (design/domains/30-adapters.md:77-88). Портов шесть,
  связывание — одна функция корня сборки (Q-75 C-1): DI-контейнер не окупится (E-1, E-2). Валидатор нужен только для
  подмножества JSON Schema (design/domains/13-rules.md:33); тесты — node:test; HTTP, хэши — встроены в Node 22. Одна
  группа характеристик на всю систему — монолитный, простой вариант (E-6, E-7, по аналогии). Агентные фреймворки
  не подходят по критериям DEC-010: LATTICE не агент-продукт, а привязка к провайдеру моделей и к движку хранения
  противоречит AD-02 и LG-05 (E-3).
  Опора: E-1 · E-2 · E-3 · E-6 (по аналогии)

  Неверен, если: появится сервер с несколькими клиентами, веб-интерфейс или внешние способности через exec —
    тогда фреймворк транспорта оправдан в адаптере, не в ядре.
  Уверенность: средняя (база о стеке молчит, G-1) · Цена отката: высокая

C-2. «Как WARRANT» — слабое обоснование; есть сильнее.
  WARRANT — первый проект (design/domains/30-adapters.md:63), а LATTICE — система для многих проектов; адаптер

  дороже по коду, но не по данным; (2) канонизация JSON по JCS (Q-06 C-2) определена через сериализацию чисел

  Опора: E-1 · рассуждение
  Отношение к дизайну: ПРОТИВОРЕЧИТ (обоснование AR-03)

  Действие: AR-03 «Почему» → «данные — канонический JSON (код заменим без миграции); JCS родной в JS; просто».
  Неверен, если: LATTICE будет делить код с WARRANT (общие модули) — тогда довод становится настоящим.
  Уверенность: средняя · Цена отката: высокая

C-3. Цена — в самодельном хранилище, а не в отсутствии фреймворка.
  Готовые движки дают строгие гарантии записи, воспроизведение и восстановление — в своей лёгкой схеме это
  труднее всего (E-5). В LATTICE именно это делается вручную в store-jsonl: дописывание с fsync, файловый замок,

  журнал мал и писатель один; колонка «позже» (design/domains/30-adapters.md:10) уже предусматривает замену, но без
  условия перехода.

  Отношение к дизайну: ПРОПУСК (условие перехода)

  Действие: 12-ledger LG-05 / AR-03: «store-jsonl — пока журнал меньше порога (вопрос grilling 12 №3: 50 МБ) и один

  Неверен, если: —
  Уверенность: средняя · Цена отката: высокая

C-4. «Без фреймворков» и «без тяжёлых фреймворков» — два правила; фреймворк не определён.
  AR-03 запрещает фреймворки (design/04-architecture.md:111), package.json — только тяжёлые
  (design/04-architecture.md:58). Без определения первый же SDK поставщика модели станет спором. Граница, совместимая
  с KISS/YAGNI (E-1, E-2) и портами: фреймворк — код, забирающий управление (контейнер внедрения, веб- или агентный

  Опора: E-1 · E-2 · рассуждение

    (инверсия управления) — нет»; тест структуры проверяет, что пакеты из dependencies импортируются только в adapters/
    (Q-81 C-3). Отдельно решить сборку TypeScript (tsc в dist/ или запуск без сборки) — в дизайне не указана.
  Неверен, если: —
  Уверенность: средняя · Цена отката: низкая
