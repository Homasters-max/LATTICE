# Пакет Q-52 · LN-05 · Гибридный поиск (оценка модели + BM25) — линейное слияние или слияние по рангам?

## Контекст в дизайне
- `design/domains/20-lens.md:92#4bf647` — LN-05: гибрид judge + BM25, слияние `linear` по умолчанию; BM25 бесплатен и помогает на терминах, linear даёт понятный балл.
- `design/domains/20-lens.md:50#230598` — стадия `fuse`: `linear` (judge + 0,3 · bm25/max, по умолчанию) или `rrf` → результат `scores.fused`.
- `design/domains/20-lens.md:52#a6d12e` — стадия `threshold`: `max(fused) < no_match` (предварительно 0,6) → `need.outcome = no-match`; порог читает числовое значение `fused`.
- `design/domains/20-lens.md:33#ffe6eb` — пул > `pool_max` (200) → предварительный отбор top-N по BM25 (второе, более раннее использование BM25 — до стадий `score.bm25`/`fuse`).
- `design/domains/22-run.md:28#d9f9bd` — конфигурация конвейера: стадия `fuse` с `params: {mode: "linear", bm25_weight: 0.3}` — единственный явно закреплённый режим в примере.
- `design/domains/22-run.md:53#ace5db` — тип `Ctx.needs[].scores`: `Record<Id, {bm25?: number; judge?: number; fused?: number}>` — по карточке хранятся числовые баллы, не только ранги.
- `design/01-first-run.md:23#318313` — критерий E1: `MRR` конвейера должен быть выше «BM25 по документам целиком» на ≥ 0,3 (нижняя граница 95 % CI > 0).
- `design/01-first-run.md:55#bd57ec` — протокол R4 (проход A): базовые линии для сравнения — (a) BM25 по документам целиком, (b) BM25 в домене, (c) LENS без `recall`.
