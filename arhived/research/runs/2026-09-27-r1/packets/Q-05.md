# Пакет Q-05 · KR-05 · Что включать в хэш содержимого, чтобы узнавать одинаковые данные при смене версии схемы?

## Контекст в дизайне
- `design/domains/10-kernel.md:48#7fa2d3` — `hash = sha256(canonical({"type": <id типа без версии>, "body": body}))`.
- `design/domains/10-kernel.md:50-52#de188c` — каноническая форма (T13): ключи отсортированы, без пробелов, NFC, числа как ES `toString`, без `undefined`; тип без версии → одинаковое содержимое под новой версией того же типа — то же значение.
- `design/domains/10-kernel.md:164,179#4aecde` — KR-05 и grilling-вопрос 2: альтернатива — хэш с версией типа — «смена версии типа меняет identity всех значений»; рекомендация — без версии.
- `design/domains/10-kernel.md:44#cae716` — четвёртая комбинация (`content` + `mutable`) запрещена: меняющееся содержимое не может быть своей identity (рамка для того, что вообще хэшируется).
- `design/domains/11-identity-grain.md:36,42-44#b846ca` — соседний, но другой механизм: ключ зерна `hash(id типа, [значения измерений по grain])` — для сущностей (`assigned`), а не для значений; используется для поиска дублей, а не как identity; посчитан по текущей версии определения зерна (в отличие от KR-05, где версия типа исключена).
- `design/02-glossary.md:21-23,27#7e72b3` — T12 хэш содержимого, T13 каноническая форма, T14 режим идентичности (`assigned`/`content`), T18 значение = `content` + неизменяемое.
- `design/03-python-lessons.md:45-46#203098` — реализация: `node:crypto` sha256 над канонической строкой; числа по ES `Number.prototype.toString`.
