# Пакет Q-11 · KR-10 · «Можно ли менять тип (классификацию) сущности, сохраняя её идентичность?»

## Контекст в дизайне
- `design/domains/10-kernel.md:169#68f38c` — KR-10: смена типа сущности — новая версия с другим `type`; `id` не меняется.
- `design/domains/10-kernel.md:23-30#6b224e` — заголовок ревизии: `type` — закреплённая ссылка на ревизию типа; `version` — целое ≥1, только следующее за текущим.
- `design/domains/10-kernel.md:36-44#36ed29` — три вида объектов по двум флагам `identity`/`mutable`; у сущности `id` не меняется, версий 1…n.
- `design/domains/10-kernel.md:148-154#53de4c` — инварианты: `id` ревизии не меняется никогда (инв. 1); `type` в заголовке — закреплённая ссылка на существующую ревизию типа (инв. 4).
- `design/domains/10-kernel.md:136-146#c84cf5` — операция `revision(input)`: заполняет ревизию «без проверки правил»; проверка правил — отдельная операция (13-rules).
- `design/domains/13-rules.md:24-27#e42320` — тип закрепляет свои правила через `rules`; ревизия проверена ровно теми правилами, что закреплены в её `type@n`; `hard`-нарушение отклоняет коммит.
- `design/domains/15-catalog.md:52-68#86eda7` — политика `refs` типа (`pin`/`follow`); при новой версии объекта закреплённые потребители не меняются, следующие — видят новую версию (в т.ч. новый `type`).
- `design/03-python-lessons.md:21,37#6ea4b7` — python-урок: `__class__ = Other` сохраняет identity → KR-10; но, в отличие от Python («тип можно менять свободно»), в LATTICE смена типа — только новой версией, проверяемой правилами нового типа.
- `design/domains/11-identity-grain.md:10-20#6b0f5b` — identity и «одинаковость» (зерно) — разные вещи; смена определения зерна тоже никогда не меняет identity (тот же принцип на соседнем механизме).
