# Пакет Q-56 · CP-01 · Как распознавать одну и ту же потребность при разных формулировках, не плодя сущностей?

## Контекст в дизайне
- `design/domains/21-compose.md:99#a79788` — сама строка решения CP-01: потребность — сущность, формулировки — подсказки, ключ — индекс, не identity.
- `design/domains/21-compose.md:14#0c3c7b` — объект «потребность» (`std/need`): тело `{scope, label, terms}`, зерно — «— (ключ потребности — индекс)», т.е. без зерна в обычном смысле.
- `design/domains/21-compose.md:25#27139d` — ключ потребности (T80) = `hash(область, отсортированные id терминов)` — быстрый поиск похожих; identity потребности — отдельный ULID.
- `design/domains/21-compose.md:52#5edf45` — стадия `recall`: код ищет по ключу (без факта `distinct`); точный повтор нормализованного текста = та же потребность; иначе `judge.verify` с порогами `same_hi`/`same_lo`.
- `design/domains/21-compose.md:100#77da40` — CP-05 (соседнее решение): «та же потребность?» сначала решает judge, в серой зоне между порогами — подтверждает Composer.
- `design/domains/22-run.md:23#67d088` — параметры стадии `recall` в конвейере: `same_hi: 0.85`, `same_lo: 0.5` (числа зерна-конвейера, не решения CP-01).
- `design/domains/11-identity-grain.md:98-105#cf29b0` — другой модуль (identity/grain) решает близкую задачу иначе: «семантические дубли» сущностей (разные ключи, один смысл) ищет LENS через `judge.verify`, и результат идёт не в объединение, а в факт `core/alias` с основанием `inferred` — слияния без подтверждения владельца нет.
