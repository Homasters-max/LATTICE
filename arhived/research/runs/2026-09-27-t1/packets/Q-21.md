# Пакет Q-21 · LG-01 · Один append-only журнал в JSONL как единственный источник истины — когда его хватает и где предел?

## Контекст в дизайне
- `design/domains/12-ledger.md:93#c31293` — сама строка решения: один append-only журнал JSONL на хранилище, пространства имён внутри; «просто, переносимо, история бесплатно».
- `design/domains/12-ledger.md:10-16#9db355` — модель: журнал — единственный источник истины; одна строка = одна ревизия, только дописывание, ничего не мутирует; в журнал пишется всё (объекты, типы, правила, факты, вызовы конвейера).
- `design/domains/12-ledger.md:104-110#af7a2e` — вопросы для grilling от самих авторов дизайна: рост журнала (события конвейера растут быстро — один логический журнал, сегменты по префиксу типа на уровне адаптера); несколько проектов в одном хранилище (рекомендация: хранилище на проект + общее `std` только для чтения, один писатель); кэш индекса (пересборка, пока журнал < 50 МБ, кэш — когда станет медленно).
- `design/domains/30-adapters.md:40-44#b55304` — физика адаптера `store-jsonl`: каталог `.lattice/` (`ledger.jsonl`, `index.json`, кэши), замок — файл `.lattice/lock`, запись — дописывание с `fsync`.
- `design/04-architecture.md:51#356d04` — `store-jsonl` — единственный адаптер хранилища в текущем обзоре архитектуры.
