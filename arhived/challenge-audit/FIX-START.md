# Исправление находок challenge-аудита — старт сессии

Внесение в `design/` решений по 59 находкам `REPORT.md` (F01–F59). Одна сессия — одна волна (волну 3 можно делить
на две). Реестр и ход — `FIX-STATE.md`.

## Запуск новой сессии

Промпт для пользователя:

```text
Продолжи исправление замечаний challenge-аудита: прочитай challenge-audit/FIX-START.md и FIX-STATE.md,
возьми следующую волну и веди её по регламенту.
```

## Что читать

1. Этот файл → `FIX-STATE.md` (какая волна следующая, что уже решено).
2. `REPORT.md`: §2 (топ рисков), §10 (рекомендации по лестнице), находки своей волны в §6 (якоря `#f01` …),
   §11 (что уже отклонено — не поднимать заново). Находки F60+ в отчёте нет — их текст в `FIX-STATE.md`,
   «Находки вне отчёта».
3. Для каждой находки — **цитируемые строки `design/` заново** (`Read` по адресам): прошлые волны могли их изменить.
   Сырые `findings/<роль>.md` — только если в итоговой находке не хватает контрсценария или паспорта.
4. `design/README.md` «Конвенции», `02-glossary.md` и `04-architecture.md` §8 — по мере надобности.

`design/` целиком не читать: работать адресно.

## Границы

- Правки — только в `design/` и `challenge-audit/FIX-STATE.md`. `REPORT.md` и `findings/` не править (история).
- `research/`, `integration/`, `batch/`, черновики в корне, `D:\kb` — только по запросу пользователя.
- Навык `arch-integrate` не применять: у него свой реестр в `integration/`. Веб — нет.
- Субагенты — не нужны; допустим один `Explore` на сверку согласованности в конце волны.

## Регламент волны

**Шаг 0.** Записать в `FIX-STATE.md` начало волны. В первой волне сначала спросить пользователя:
- **версия правок** — `v0.5` (новый `CHANGELOG-v0.5.md`, тег `design-v0.5` в конце всех волн) или правки v0.4 с
  тегом `design-v0.4.1`; от ответа зависит опора в «Почему» (`v0.5 · CA-F04` или `v0.4.1 · CA-F04`);
- **справки к F01 и F23** (`REPORT.md` §12): как агенты WARRANT получают `LATTICE_ACTOR`; где лежит `.lattice/` и
  синхронизируется ли каталог. От ответа зависит тяжесть F01 (S1 или S2) и нужная ступень разрешения.

**Шаг 1. Перепроверка.** Для каждой находки волны прочитать цитируемые строки. Уже закрыто прошлой волной —
статус `внесено ранее` с адресом, дальше не обсуждать.

**Шаг 2. Группы.** Свести находки, которые закрывает одно решение (связи — ниже). Одна группа — один вопрос.

**Шаг 3. Решения с пользователем.** По группе — вопрос с рекомендацией: минимальное разрешение из отчёта
(ступень лестницы `AUDITOR.md` §6) и 1–2 альтернативы, включая «отложить с наблюдаемым триггером». Пометить, если
решение требует ADR (затронуто больше одного домена или принцип P1–P12). S3–S4 одной волны можно предложить принять
пакетом по рекомендациям отчёта. Каждое решение — строка в «Решения пользователя» `FIX-STATE.md` сразу.

**Шаг 4. Внесение** — по конвенциям `design/README.md`:
- решение — строка с ID в «Решения» домена-владельца (карта `04-architecture.md` §8); в «Почему» — опора
  `<версия> · CA-Fnn`;
- новый термин — `T177+` в `02-glossary.md`; синонимов не вводить;
- решение шире домена или смена принципа — новый ADR в `adr/` и строка в `adr/README.md`;
- отложенное — в «Вне объёма» домена с **наблюдаемым** триггером и тем, что пишется в v1 уже сейчас;
- затронут инвариант или срез — поправить «Инварианты» домена и `05-slices.md`.

**Шаг 5. Сверка волны.** `Grep` новых ID и терминов по `design/`: ссылки живы, в глоссарии есть, у понятия один
владелец, старые формулировки, противоречившие решению, исправлены везде (особенно парные места из находок класса B).

**Шаг 6. Закрытие.** `FIX-STATE.md`: статусы и «Где» по каждой находке, статус волны, промахи. `CHANGELOG` выбранной
версии. Коммит: `design: challenge-аудит, волна N — внесено a, отклонено b, отложено c` (только `design/` и
`challenge-audit/FIX-STATE.md`). В чат — 5–10 строк: что внесено, что отклонено и почему, что следующее.
**Остановиться.**

## Правила

- **Не усложнять:** минимальное разрешение по лестнице; новый механизм — только если ступеней 1–5 не хватает, с
  объяснением почему.
- Решение принимает пользователь; без ответа — не вносить.
- Каждый промах — строкой в «Промахи» `FIX-STATE.md` (лишнее чтение, правка не того, неверный адрес, откат).
