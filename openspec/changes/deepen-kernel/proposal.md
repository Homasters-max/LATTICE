# Proposal

## Why

Тест структуры зашивает «периметр ядра = каталог»: интерфейс `checkKernel(dir)` проверяет один каталог, граница ядра —
его корень (`insideRoot`). А design требует другого: 04-architecture §3 — правила над графом импортов `src/` (направление
по матрице, нет циклов, изоляция адаптеров, периметр), ADR-43 и 04 §3 п. 6 — периметр «всё достижимое из точки входа
лежит в явном перечне», который каталогом не выражается (`src/ledger/projections.ts`, `src/rules/kernel-checks/**`,
интерфейсы `src/*/types.ts`). Каждое такое правило в нынешней форме легло бы отдельным обходом со своим разбором и
разрешением импортов.

В самом ядре три правила размазаны по файлам (разбор архитектуры 2026-09-30, кандидаты 2–4):
- таблица «какая форма идентификатора в какой позиции и какой код отказа» (`REQ-KR-005`) — у каждого вызывающего
  (`revision.ts`, `formatRef`, `hash.ts`, `ids.ts`), `revision.ts` повторяет `isVersion` руками; правило объекта
  `{"$ref"}` написано дважды с разным подсчётом ключей (`input.ts`, `refs.ts`);
- обход канонической формы — `walk(root, emit, prefix, hooks)` с флагом и префиксом пути, а `hash.ts` собирает
  канонический текст конверта `{body, type}` вручную, зная порядок ключей JCS;
- допуск строки (одиночный суррогат, неназначенная точка Unicode 16.0, NFC) решают три файла: `input.ts` берёт
  предикат у `canonical.ts` и ветвится одинаково для ключа и значения.

Срок — до среза S1. Точки входа `kernel-v1` ещё нет; после неё любая правка кода, достижимого из неё, — новая версия
ядра (ADR-32, ADR-43). Сейчас правка `src/kernel` без смены поведения — не новая версия: публичный интерфейс
`src/kernel/index.ts` и векторы формата v1 не меняются.

## What Changes

- Тест структуры — один модуль над графом импортов: файлы дерева разбираются один раз, правила — функции над графом,
  политика — данные (источники графа, точка входа, перечень периметра глобами). Политика проекта: источники `src/**`,
  точка входа `src/kernel/index.ts`, перечень `src/kernel/**`.
- `REQ-AR-001` (изменено): правила чистоты ядра — ко всем файлам перечня периметра; «импорт вне ядра» — импорт файла вне
  перечня; `no-kernel` — ещё и при отсутствии файла точки входа. Коды правил, фикстуры `test/fixtures/structure/kernel/**`
  и их метки `// expect:` — прежние.
- `REQ-AR-003` (новое): всё достижимое по импортам (включая `import type`) из точки входа лежит в перечне периметра,
  иначе — `outside-perimeter` с файлом и строкой импорта, который вывел за перечень.
- `REQ-AR-004` (новое): нет циклов импортов между файлами источников графа, отказ `import-cycle` — детерминированно.
- Ядро без смены поведения: `ref.ts` владеет таблицей позиций идентификатора и правилом объекта `{"$ref"}`;
  каноническая форма — две операции вместо флага, хэш канонизирует конверт целиком; допуск строки — одна функция рядом с
  таблицей Unicode 16.0.

Опора в design: 04-architecture §3 (п. 3, 6), §6; ADR-43; ADR-32; глоссарий T169, T196; разбор архитектуры 2026-09-30,
кандидаты 1–4.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `architecture`: периметр ядра — политикой (точка входа, перечень глобами) вместо каталога (`REQ-AR-001`); периметр —
  всё достижимое из точки входа (`REQ-AR-003`); нет циклов импортов (`REQ-AR-004`).

## Impact

- Код: `test/architecture/structure.ts`, `test/architecture/structure.test.ts`, новые фикстуры
  `test/fixtures/structure/perimeter/`, `test/fixtures/structure/cycles/`; `src/kernel/ref.ts`, `revision.ts`,
  `hash.ts`, `ids.ts`, `refs.ts`, `canonical.ts`, `input.ts`, `unicode16.ts`.
- Возможность `kernel` не меняется: `src/kernel/index.ts` (девять функций `REQ-KR-001`), `test/kernel/**` и
  `test/fixtures/jcs-vectors.json` — без правки; доказательство — те же тесты `SCN-KR-…`.
- Зависимостей не прибавляется; внешние системы и данные не затрагиваются.

## Non-goals

- Матрица доменов (04 §3 п. 1), изоляция адаптеров (п. 4), пакеты `dependencies` (п. 5), ввод-вывод вне ядра (п. 2 для
  `src/` целиком) — со срезом S1, строкой политики без нового обхода.
- Точка входа `kernel-v1`: `src/ledger/kernel-v1.ts` не создаётся, перечень периметра S1 не вводится.
- Никакого изменения поведения функций ядра: коды отказов, пути, порядок отказов, байты канонической формы и хэша —
  прежние.
- Правило «тесты внутри `describe`» (`REQ-AR-002`) не меняется.
