# Spec Delta

## Purpose

Правила структуры кода LATTICE, которые проверяет тест, а не ревью: направление импортов между частями системы,
границы ввода-вывода и форма тестов проекта (design/04-architecture.md §2, §3).

## ADDED Requirements

### Requirement: Ядро изолировано
<!-- id: REQ-AR-001 -->

Тест структуры SHALL разбирать исходные файлы TypeScript каталога `src/kernel/` и отклонять файл ядра, который:
- импортирует модуль вне `src/kernel/`, кроме встроенного модуля `node:crypto` (статический `import`, `export … from`
  и `import type` — одинаково);
- использует динамический импорт `import(…)`, `require(…)`, глобальные `process`, `fetch` или `Deno`/`Bun`.

Отказ теста SHALL называть файл, строку и нарушенное правило. Проверка SHALL работать по разбору исходного текста, без
исполнения проверяемых файлов.

#### Scenario: Ядро проекта проходит тест структуры
<!-- id: SCN-AR-001 -->
- **WHEN** тест структуры запускается на каталоге `src/kernel/` проекта
- **THEN** нарушений нет

#### Scenario: Нарушения ядра найдены
<!-- id: SCN-AR-002 -->
- **WHEN** тест структуры запускается на фикстуре-каталоге ядра с файлами: импорт `node:fs`; импорт
  `../ledger/commit.ts`; импорт пакета `canonicalize`; `export { x } from "node:path"`; `import type { T } from
  "../run/types.ts"`; вызов `import("./x.ts")`; чтение `process.env.HOME`; вызов `fetch("…")`; и файлом, который
  импортирует только `node:crypto` и `./hash.ts`
- **THEN** каждый файл с нарушением назван с номером строки и правилом; файл с `node:crypto` и `./hash.ts` нарушений не
  имеет

### Requirement: Тесты проекта объявлены внутри describe
<!-- id: REQ-AR-002 -->

Тест структуры SHALL разбирать файлы `test/**/*.test.ts` и отклонять вызов `test(…)` или `it(…)` из `node:test`, который
не находится лексически внутри функции, переданной в `describe(…)`: отчёт junit `node:test` помещает такой тест вне
`<testsuite>`, и проверка `tests-passed` его не учитывает. Отказ SHALL называть файл и строку вызова.

#### Scenario: Тест вне describe найден
<!-- id: SCN-AR-003 -->
- **WHEN** тест структуры запускается на фикстуре с файлом, где один `test(…)` стоит на верхнем уровне модуля, один
  `it(…)` — внутри обычной функции вне `describe`, а один `test(…)` — внутри `describe(…)`, затем на каталоге `test/`
  проекта
- **THEN** на фикстуре найдены ровно два нарушения — верхнеуровневый `test` и `it` вне `describe` — с номерами строк; в
  каталоге `test/` проекта нарушений нет
