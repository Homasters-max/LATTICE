# Proposal

## Why

The launch grilling of 2026-10-01 (record `design-next/reviews/2026-10-01-launch-readiness-grilled.md`, docs PR
`docs/sw-milestone`) fixed the order of work: `infra-baseline` → `s0-skeleton` → parallel Changes of slice S0 →
`s0-roundtrip` → switch SW → S1. Three things block the start of S0, and all three are policy paths — the maintainer's
acts — so they go together in one Change instead of three:

- **No test run outside a Change.** The job `warrant` judges only Changes. On a PR without a Change (documents, the
  coming normalization of `design-next`) and on a push to `main`, `npm test` and `npm run typecheck` never run; `main`
  was already red unnoticed once (issue #21, #28). S0 runs several Changes and docs PRs in parallel; every one of them
  needs the tests.
- **Artifacts are Russian, the design is English.** `openspec/config.yaml` says "All artifacts must be written in
  Russian" (source: `.warrant/local/openspec/rules.json`). `design-next` is English by its README: its texts become
  LATTICE blocks, and the judge reads block text. Specs of S0 reference design IDs (`Implements: …`, grilling Q6); a
  Russian spec is a second copy of the norm in another language. Decision of the maintainer: everything in the
  repository and on GitHub is English, Russian only in the chat (grilling Q19). The project rules that `warrant sync`
  renders into `AGENTS.md` are Russian too.
- **AREAs of the old architecture.** `.warrant/local/areas.json` maps 12 AREAs from design v0.6, three of them for
  ideas design-next does not take (GR grain — NX-06, RL rules — NX-05, CP compose — NX-13) and none for codec, store,
  projections, acts, cli, measure. WARRANT allocates REQ/SCN ids as "maximum + 1" per AREA without reservation:
  two parallel Changes in one AREA collide (`ID_DUPLICATE`, WARRANT WS-23), two Changes modifying one requirement
  overwrite each other at archive. The rule "one AREA = at most one active Change" (grilling Q20, design-next
  SL-T08) needs one AREA per spec of S0.

## What Changes

- **New workflow `.github/workflows/test.yml`**: job `test` on every pull request and on push to `main` — `npm ci`,
  `npm run typecheck`, `npm test`; Node 22; permission `contents: read`. `warrant.yml` is not touched.
- **Language**: `.warrant/local/openspec/rules.json` context — English; `warrant sync` regenerates
  `openspec/config.yaml`.
- **Project rules in English**: `.warrant/local/rules/env.json`, `maintainer-acts.json`, `process.json`,
  `tracking.json` — translated; meaning unchanged except four additions from the grilling (design D-4): the language
  rule, a freeze tag of `design-next` as a maintainer's act, parallel work by AREA and worktree, issue area `sw` with
  milestone and "Depends on:". `warrant sync` regenerates `AGENTS.md`.
- **AREAs**: `.warrant/local/areas.json` rewritten to the capabilities of the module matrix ST-M01 (design D-5).
- **Process test** `test/process/baseline.test.ts`: the form of `test.yml`, the language context, the AREA map.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None: the product LATTICE does not change; the CI and the process of the project do (`skip_specs: true`).

## Impact

- Policy paths: `.github/workflows/test.yml` (new), `.warrant/local/openspec/rules.json`,
  `.warrant/local/rules/{env,maintainer-acts,process,tracking}.json`, `.warrant/local/areas.json`; generated by
  `warrant sync`: `openspec/config.yaml`, `AGENTS.md`, `.warrant/warrant.lock.json`. Test
  `test/process/baseline.test.ts`. No `src/`.
- GitHub gets a second check, `test / test`, next to `warrant / warrant`. It is not a required check: protection of
  `main` is issue #20.
- From the merge on, every new artifact, commit, PR and issue is English. Existing Russian specs `architecture` and
  `kernel` stay until `s0-skeleton` and `s0-kernel` replace them (grilling Q16); archived Changes are history and stay.
- Closes #28. Issue #27 is closed as not taken (grilling Q8).

## Non-goals

- Translating existing specs, archived Changes, `design/` or old issues by this Change.
- Edits of `design-next` (docs PR `docs/sw-milestone`) and its normalization (separate docs PR).
- Protection of `main`, required checks, `.github/CODEOWNERS` (issue #20, the maintainer's act on the forge).
- A WARRANT check of the project (`dev-check`, issue #27): the type check runs in the job `test`.
- CI on a second operating system (LG-J02 needs it for projections; it comes with `s0-projections`).
- Changes of `.warrant/warrant.json`, the pin of WARRANT, the profile `human-acceptance`.
