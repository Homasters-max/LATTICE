# session-audit

Разбор сессий по транскрипту свежими субагентами: рабочий агент контекст не тратит, аналитик видит свои промахи со стороны. Норма — dev/README.md «Цикл разработки», dev/rules/reports.md.

## Вход

- Запускает только человек (`/session-audit`); агент на старте лишь показывает число неразобранных сессий (RUL-046).

- `python scripts/dev/dev-check.py --sessions` — транскрипты не в реестре и `SES` без разбора; либо id из аргумента.
- Текущую сессию не разбирать, пока она идёт (только по явной просьбе — как срез на момент разбора).
- Scratchpad сессии — для сжатий и черновиков; в репозиторий — только итог.

## Шаги

1. Для каждой сессии: `python scripts/dev/session-digest.py <id> --out <scratchpad>/digest-<id8>.md`.
2. Зарезервировать номера `RPT-NNN` подряд (следующий свободный в `dev/reports/`, `main` и открытых ветках).
3. Запустить аналитиков в фоне — до 5 одновременно, модель sonnet: промпт — [analyst.md](analyst.md) с подставленными `{root}`, `{session}`, `{session8}`, `{digest}`, `{transcript}`, `{rpt}`, `{out}`, `{traps}` (`python scripts/dev/dev-check.py --brief audit`). Ждать уведомлений, не опрашивать.
4. По каждому ответу: прочитать черновик `rpt`, `new-issues`, `session` в `{out}`; сверить `NEW-k` с `dev/issues/` (дубль → ссылка на существующую, повтор — в `refs` отчёта); новым — следующие номера `ISS-NNN`, файлы по README.
5. Записать `dev/sessions/SES-<id8>.md` (`links`, `audit: RPT-NNN`) и `dev/reports/RPT-NNN.md` (NEW-k → ISS-…); в проблемах, которые повторились, — ничего не править: повтор считается по `refs` отчётов.
6. Ловушка для новой проблемы с обходом — правило в узле или стандарте (README «Правила»); улучшение без проблемы — `IDEA-NNN`; пункт для WARRANT — в открытый `PRP` (или новый).
7. Сводный: с `--synthesis` (человек просит; агент может предложить при 5 разборах после последнего сводного) — аналитик по [synthesis.md](synthesis.md) со всеми `RPT` с последнего сводного; итог — `RPT-NNN` с `kind: synthesis`.
8. `python scripts/dev/dev-check.py` — 0 ошибок; коммит `session-audit: RPT-… (SES-…)` в ветку `chore/…`, PR вида `none`.

## Стоп

- Черновик аналитика дважды не по форме `rules/reports.md` — остановиться, показать maintainer'у.
- Больше 5 новых проблем одного класса в одной сессии или сводный нашёл blocker — остановиться, вопрос maintainer'у до продолжения работы по `focus`.
- Транскрипт не найден или обрезан — `SES` с `audit: null` и строкой «Разбор» о причине.

## Отчёт

Блок «✅ Готово» ([dev/rules/output.md](../../../dev/rules/output.md)): сессии → `RPT`, новые `ISS`, сработавшие повторно, сводный — да/нет, что передаётся в WARRANT.
