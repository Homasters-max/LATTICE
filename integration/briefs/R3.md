## 6. Риски согласованности

1. **Закрытая схема против `extends`:** И-1 «расширение — через `extends`» (`:100`) и Р-4 «схема не слабее» (`:352`) —
   наследник не добавит поле без правила закрытости по цепочке (Q2).
2. **no-op в нескольких местах** (`design/domains/10-kernel.md:34`, `:162`; `design/domains/12-ledger.md:22`;
   `design/05-slices.md:8`) — после Q3 сравнение по `(type@n, hash)`; 10-kernel/И-4 (no-op факта) — сверить в D01.
3. **Лестница против совместимости:** soft → hard у общего типа отклоняет прежде допустимые тела — нарушает И-2 без
   плана (Q6 п.4); «импортируемые» в v1 = `core`/`std` (15-catalog/И-3, R4).
4. **Алиасы LLM при импорте** (`design/domains/30-adapters.md:68`, `design/01-first-run.md:39`) и «в силу при
   `declared`» (`design/domains/14-trust.md:86`, GR-06 `design/domains/11-identity-grain.md:134`) — после Q4 это
   `std/alias-candidate`; правка D07, D10, D11.
5. **`split` = «−1»** (`design/domains/11-identity-grain.md:87`, `:115`; T32 `design/02-glossary.md:46`) против
   10-kernel/И-30 — Q8; разбиение потребности — не `split` (21-compose/И-6, R6).
6. **`std/domain` — два тела** (N-11: `design/domains/10-kernel.md:19` против
   `design/domains/11-identity-grain.md:32-33`): измерение `project` при Q5 дублирует пространство автора — D03.
7. **Генезис:** `grain_scope`, уровень `schema`, наследование `writers`/`inForce` — поля и правила `core/type`
   (`design/domains/10-kernel.md:129`) — до S1 (T-10); `type-shape` — только поля ядра (10-kernel/И-17).
8. **Глоссарий (с T123):** `std/alias-candidate` (не путать с T87 «кандидат»), область зерна, `examples`, лестница
   схемы; правка T20, T26, T32, T46, T66. **Владельцы** (новые строки `integration/ownership.md`): `grain_scope` —
   11-identity-grain, уровень `schema` — 13-rules; `std/block` (`integration/ownership.md:83`) — 20-lens.
9. **ADR-2:** ADR-15 по номеру не ссылаться до R5 (lint, урок R2).
