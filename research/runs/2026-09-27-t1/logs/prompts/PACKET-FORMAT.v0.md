# Пакет улик — формат для сборщика (этап 1)

Сборщик **собирает**, куратор **судит**. Пакет — это улики с адресами, а не выводы. Никаких «СОГЛАСУЕТСЯ /
ПРОТИВОРЕЧИТ», рекомендаций и оценки дизайна. Всё, что сборщик думает о смысле, — одна строка «зачем это куратору».

Инструменты (только они): поиск `KBS=~/.claude/skills/kb-search/scripts/kb-search.mjs` с `--kb`; чтение карточек —
`node $KBS --kb --section ID ["Раздел|Раздел"]` (строки уже с `путь:строка`); дизайн проекта — чтение `design/…` по
строкам; `grep` по `D:/kb/{patterns,decisions,antipatterns,glossary}` для точных терминов.

## Порядок сбора

1. **Контекст в дизайне:** открыть строку решения из задания и 10–40 строк вокруг; найти в `design/` другие места,
   где решение используется (`grep` по ID и ключевым словам). Записать адреса и по одной строке сути.
2. **Поиск L1:** широкий `node $KBS --kb "вопрос своими словами"` (без фильтра) + по граням из задания
   `node $KBS --kb "грань" --profile design --k 5 --brief` (грань «как называется» — `--profile define`). Строка `# !` →
   тот же запрос без фильтра. Формулировки — о потребности, своими словами. Всего: 1 широкий + ≤ 4 узких (+ повторы).
3. **Чтение L1:** до 6 карточек — те, что отвечают на вопрос. Для каждой `--section ID` (карта), затем разделы:
   pattern — Решение, Когда не применять, Trade-offs; decision — Критерии выбора, Варианты, Оговорки; antipattern —
   Симптом, Почему вредно, Чем заменить; term — всё тело. Выписать **только нужные строки**, диапазонами.
4. **L2:** ссылки `[[…]]` **из прочитанных разделов** L1 и поле `related` (`grep -E '^related:' <файл>`). Отобрать по
   описанию (первая строка `--section ID`) не больше 8 полезных; из них прочитать раздел у не больше 4. Остальные —
   списком ID без чтения.
5. **L3 (кандидаты):** для 2–3 главных карточек — поле `source` (`grep -E '^source:' <файл>`): путь главы. Главы не
   читать — это делает куратор.
6. **Пробелы:** что искали и не нашли (запрос + что пришло вместо).
7. `node ~/.claude/skills/kb-research/check-refs.mjs <пакет> --stamp` — отпечатки на все адреса.

## Формат файла `packets/Q-NN.md`

```text
# Пакет Q-NN · <ID решения> · <вопрос>

## Контекст в дизайне
- `design/…:NN-MM` — <суть в 1 строку>
(все места использования)

## Поиск
| S | Запрос и флаги | Режим · пул · $ | Топ (ID) | `# !` / повтор |

## L1 — улики
| E | ID | [тип · домены · зрелость] | Раздел | Адрес `путь:строки` | Суть своими словами (1–2 строки) | Зачем куратору (1 строка) |

## L2 — соседи
| ID | Откуда ссылка (E-n, раздел или related) | Описание (1 строка) | Прочитано: раздел · `путь:строки` или «—» |
Не прочитаны: ID, ID, …

## L3 — кандидаты глав
| Для | Глава (путь) |

## Пробелы
| Искали (S-n / grep) | Что пришло вместо |

## Статистика
запросов Jev: n (повторов: n) · BM25/grep: n · $: сумма · разделов прочитано: n · размер пакета: n КБ
```

Ограничения: пакет ≤ 20 КБ; не копировать карточки — только адреса и суть своими словами; не читать отчёты
`research/2026-*.md`, `research/kb-findings.md` — они вне задачи сборщика.
