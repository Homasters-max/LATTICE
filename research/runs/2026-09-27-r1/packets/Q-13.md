# Пакет Q-13 · KR-13 · Один универсальный механизм фактов-событий для членства, алиасов и утверждений — не слишком ли он общий?

## Контекст в дизайне
- `design/domains/10-kernel.md:172#f25c53` — строка решения KR-13 в таблице «Решения»: факт — событие `{of:{роль:ref}, value}`, ключ факта — в типе; «один механизм для членства, алиасов, утверждений, подсказок».
- `design/domains/10-kernel.md:109-123#c5faf4` (§7 «Факт — событие особой формы») — тело факта, роль `of`→ссылка, `key` типа определяет «тот же факт», пустой `key` — факты накапливаются; текст: «так выражаются членство, алиас, вывод из обращения, утверждение, подсказка, допуск — один механизм».
- `design/domains/10-kernel.md:96-101#9c65e1` (§6, таблица полей типа) — `roles`, `key` для типов фактов задаёт **тип**, не ядро; у ядра нет отдельного порта/операции для факта (см. «Операции» :136-146 — только `canonical`, `hash`, `parseRef`, `refsOf`, `newId`, `valueId`, `revision`, общие для всех видов объектов).
- Использование механизма в других модулях: `design/domains/11-identity-grain.md:82#103225` — слияние идентичности = факт `core/alias {of:{alias,canonical}, value:true}`, ключ `[alias]`; `design/domains/21-compose.md:15-19#286403` — таблица: подсказка `std/cue`, различие `std/distinct`, членство `core/member`, связь `std/link` — все как факты с разными ролями/ключами; `design/domains/14-trust.md:24#6bfc44` — факт доверия той же формы `{of:{target}, value, reason}`; `design/domains/15-catalog.md:36#5ac64a` — допуск `core/grant` тоже факт; `design/02-glossary.md:44,77,78,122#b3e259` — термины T30 алиас, T48 роль, T49 ключ факта, T83 членство.
