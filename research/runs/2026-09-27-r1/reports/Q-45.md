**Выводы**

```text
C-1. Свидетельство хранить у автора со ссылкой на цель — верно; его сила = сила идентичности автора.
  Опора: E-1 (за: провенанс — связь с ответственной идентичностью) · E-3 (за: метка владельца при записи) · E-4 (за:
    кто что сказал) · E-5 (вариант: атрибуция по издателю, не по месту) · E-8 (вариант: одно место для evidence) ·
    E-2 (граница: запись — утверждение, не доказательство)
  Отношение к дизайну: СОГЛАСУЕТСЯ — CT-04, P4, core/assert в пространстве сессии-автора с target на любую
    ревизию (design/domains/14-trust.md:21-27). Журнал хранилища — «одно место» (E-8), пространство автора лишь
    делит авторство. Оговорка (E-2, E-4): подпись — вне объёма (design/domains/14-trust.md:119), идентичность — by
    сессии, которую сейчас может завести кто угодно; это trust-independence C-3, здесь не повторяется.
  Где в дизайне: design/domains/15-catalog.md:33, :91; design/domains/14-trust.md:21-30
  Действие: не требуется (сила идентичности — по trust-independence C-3).
  Неверен, если: свидетельства будут переноситься между хранилищами без сессий-источников — тогда нужна подпись (E-4).
  Уверенность: высокая · Цена отката: высокая

C-2. Для историзуемых фактов «текущий — последний по ключу» от любого автора: третья сторона переписывает чужое.
  Опора: E-6 (против: запись одного — побочный эффект для всех) · E-7 (за: журнал только-дописывание не даёт права
    на изменение)
  Отношение к дизайну: ПРОТИВОРЕЧИТ. Ключ факта — роли; «текущий факт — последний по ключу (по at, затем seq)»
    (design/domains/10-kernel.md:118-119); автор и его пространство в ключ не входят. Членство, алиас, вывод из
    обращения, допуск — факты по ключу (design/domains/10-kernel.md:123). Факт живёт в пространстве автора
    (design/domains/15-catalog.md:33), но индекс сводит факты всех пространств по ключу — и факт агента
    {group: warrant/SOL-…, member: X} с value false закрывает членство, записанное владельцем. Строка в журнале
    чужая не тронута, но «текущее» — переписано: CT-04 «никто не переписывает чужое» держится только для
    накопительных фактов (пустой key — assert, cue).
  Где в дизайне: design/domains/10-kernel.md:118-123; design/domains/15-catalog.md:33, :91
  Действие: 10-kernel §7 — «текущий факт — последний по ключу в пространстве автора»: мнения разных авторов не
    перекрывают друг друга, их сводит доверие (14-trust). Управляющие факты (grant, retire, deprecate, alias)
    — только от владельца пространства цели (Q-44 C-2), и тогда «последний по ключу» среди них однозначен.
    Решать вместе с Q-44 C-2.
  Неверен, если: намеренно нужно, чтобы любой участник мог закрыть членство (совместная правка решения) — тогда это
    не факт третьей стороны, а допуск на тип факта, и его надо записать явно.
  Уверенность: высокая (дыра) · средняя (форма ключа) · Цена отката: высокая (смысл «текущего» в индексе; журнал
    не меняется, индекс пересобирается — LG-02)

C-3. «Любой может свидетельствовать» ограничено хранилищем.
  Опора: — (дизайн; рассуждение) · E-8 (граница «одного места»)
  Отношение к дизайну: ПРОПУСК. Рекомендация 12-ledger — хранилище на проект (design/domains/12-ledger.md:107-108);
    утверждение живёт в пространстве автора, то есть в хранилище автора. Проект B, утверждающий «блок std/X
    не сработал», пишет это в своё хранилище; проект A и владелец std его не видят. Доверие к общему блоку у
    каждого проекта своё — «общее доверие к std» не складывается.
  Где в дизайне: design/domains/15-catalog.md:91; design/domains/12-ledger.md:107-108; design/domains/14-trust.md:69-70
  Действие: записать в CT-04 «свидетельства видны в пределах хранилища»; обмен свидетельствами между проектами
    (например, выгрузка утверждений о std-блоках поставщику как proposal или отдельный журнал отзывов) — вопрос
    следующей версии, в grilling.
  Неверен, если: все проекты живут в одном хранилище (12-ledger:15 это допускает).
  Уверенность: средняя · Цена отката: низкая (граница записывается, механизм — позже)
```
