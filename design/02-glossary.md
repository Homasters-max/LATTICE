# 02. Глоссарий — единственный список терминов

Термины закреплены. Остальные файлы ссылаются сюда (`T07`) и синонимов не вводят. Код — имя в JSON и коде.
Колонка «Python» — ближайший аналог ([03-python-lessons](03-python-lessons.md)); прочерк — аналога нет.

## Объект и запись (kernel)

| # | Термин | Код | Определение | Python |
|---|---|---|---|---|
| T01 | **объект** | `object` | запись из заголовка и тела; всё в системе — объект (P1) | `PyObject` |
| T02 | **заголовок** | `header` | единственная фиксированная часть объекта: `id`, `type`, `version`, `at`, `by` | `ob_type` + `id()` |
| T03 | **тело** | `body` | открытый JSON; ядро его не ограничивает, ограничивают правила (T41) | `__dict__` |
| T04 | **идентификатор** | `id` | identity объекта: `<namespace>/<local>` или `#`+hex32 у значений (схема 1; метка следующей схемы зарезервирована — 10-kernel §4); не меняется никогда | `id()` |
| T05 | **пространство имён** | `namespace` | граница владения: ядро, библиотека, проект; первая часть `id` | модуль / пакет |
| T06 | **локальное имя** | `local` | часть `id` после `/`: ULID, внешнее стабильное имя (`REQ-KRN-011`) или имя (`type`) | имя в модуле |
| T07 | **версия** | `version` | номер ревизии объекта, целое ≥ 1, в заголовке, **не в теле** | — |
| T08 | **ревизия** | `revision` | неизменное состояние объекта в версии; адрес — `id@version` | — |
| T09 | **ссылка** | `ref` | `id` (следующая) или `id@n` (закреплённая); в теле — `{"$ref": "…"}` | ссылка на объект |
| T10 | **закреплённая ссылка** | `pinned` | `id@n`: всегда указывает на одну ревизию | сильная ссылка |
| T11 | **следующая ссылка** | `following` | `id`: указывает на последнюю живую ревизию | `weakref` + поиск по имени |
| T12 | **хэш содержимого** | `hash` | sha256 канонической формы `{type: <id типа без версии>, body}`: то же содержимое под новой версией типа — то же значение | `__hash__` |
| T13 | **каноническая форма** | `canonical` | JCS (RFC 8785); строки приводятся к NFC на входе коммита — одинаковые данные дают одинаковые байты (ADR-1) | `pickle` / `__reduce__` |
| T14 | **режим идентичности** | `identity` | как получается `id`: `assigned` (выдаётся) или `content` (= хэш) | `is` против `==` |
| T15 | **изменяемость** | `mutable` | может ли объект иметь версию > 1 | `list` против `tuple` |
| T16 | **сущность** | entity | `assigned` + `mutable`: identity стабильна, версии меняются (норма, домен, решение) | экземпляр класса |
| T17 | **событие** | event | `assigned` + неизменяемое: произошло один раз (факт, вызов, вердикт) | — |
| T18 | **значение** | value | `content` + неизменяемое: identity = содержимое (snapshot, карточка) | `tuple`, `frozenset` |
| T19 | **тип** | `type` | объект типа `core/type`: режим идентичности, `extends`, зерно и `grain_scope`, правила и `schema`, роли, ключ, `writers`/`inForce`, политика ссылок, карточка | `type` |
| T20 | **расширение** | `extends` | тип наследует контракт одного родителя — правила, роли, `writers`/`inForce` — только с сужением; карточку — нет (ADR-12) | базовый класс |
| T21 | **ядро** | `core` | замороженное пространство имён и код, который его знает (перечень — [04](04-architecture.md) §1, там же — что ядро читает вне `core`, ADR-35); меняется только версией ядра. Не весь код системы: журнал, доверие, каталог, интерпретатор — обычные релизы (10-kernel/И-32) | `builtins` |
| T22 | **стандартная библиотека** | `std` | общие типы механизма и способности (потребность, решение, конвейер …) — данные, версии как у всех; предметные типы — в проектах через `extends` (10-kernel/И-34) | stdlib |
| T23 | **генезис** | genesis | начальный набор объектов `core`; порождается кодом ядра, хэш генезиса — константа версии ядра, сверяется при открытии хранилища как звено цепочки генезиса (T177) (T-10) | инициализация интерпретатора |
| T177 | **переход ядра** | kernel transition | смена версии ядра на хранилище с данными: ядро vN знает цепочку хэшей генезиса v1…vN, дельту `core/*` пишет сессия `core/genesis-vN` отдельным коммитом `key = kernel:vN`, принимает владелец проекта; строка судится ядром своего коммита (10-kernel KR-19, ADR-34) | — |
| T144 | **происхождение пространства** | `origin` | неизменное поле `core/namespace`: ULID при `init` у проекта, константа у `core` (генезис) и `std` (пакет LATTICE); импорт отклоняет пространство с тем же именем и другим `origin` (10-kernel/И-27) | — |
| T145 | **шифруемое поле** | `$enc` | резерв формата v1: объект тела ровно с одним ключом `$enc`; ядро v1 его отклоняет; позже — шифротекст с ключом вне журнала, удаление ключа «забывает» данные (10-kernel KR-14, T-12) | — |

## Идентичность и зерно

| # | Термин | Код | Определение |
|---|---|---|---|
| T24 | **измерение** | dimension | поле тела, участвующее в зерне |
| T25 | **зерно** | `grain` | список измерений типа, которые определяют «это та же сущность» |
| T26 | **ключ зерна** | grain key | `hash(id типа, значения измерений)`; уникален среди живых сущностей типа в области зерна (T124: пространство автора или `store`, ADR-27) |
| T124 | **область зерна** | `grain_scope` | поле `core/type`: где ключ зерна уникален — пространство автора (по умолчанию) или `store` — всё хранилище (справочники `std`) (ADR-27) |
| T27 | **дубль** | duplicate | две живые сущности одного типа с одним ключом зерна — запрещено правилом `hard` |
| T28 | **семантический дубль** | near-duplicate | разные ключи зерна, один смысл; найденный — кандидат в алиас (T123), не слияние |
| T29 | **интернирование** | intern | запись уже существующего значения даёт тот же объект; для сущностей — `ensure` («найди или создай») |
| T30 | **алиас** | `core/alias` | факт «сущность A — это сущность B»; пишет владелец — подтверждение кандидата (ADR-8); ссылки на A разрешаются в B |
| T123 | **кандидат в алиас** | `std/alias-candidate` | факт «A — возможно, B», ключ `[alias, canonical]`, `value: {p, judge}` — балл `judge.verify` и тройка judge `{adapter, model, prompt_hash}`; `writers: any` (кандидат следующего писателя той же пары — текущий); открыт, пока для пары нет `core/alias` в силе и `std/distinct {value: true}`; в силу не входит; индексы и `resolve` его не видят (ADR-8) |
| T31 | **слияние** | merge | установка алиасов по плану; обратимо, история не переписывается |
| T32 | **разделение** | split | отмена алиаса: владелец пишет `core/alias {value: false}`; «−1» влияет на доверие, но не отменяет (10-kernel/И-30, ADR-6) |
| T33 | **перезерновка** | regrain | пересчёт ключей зерна при смене зерна, области зерна (T124) или тела; отчёт о коллизиях; план разрешения — владелец пространства (ADR-7) |
| T34 | **коллизия** | collision | набор живых сущностей, получивших один ключ зерна |
| T35 | **живая сущность** | live | не выведена из обращения (T58) и не является алиасом |

## Журнал

| # | Термин | Код | Определение |
|---|---|---|---|
| T36 | **журнал** | `ledger` | append-only последовательность ревизий; единственный источник истины; строка не меняется, сегмент со сроком истекает только целиком (ADR-3) |
| T37 | **коммит** | commit | пакет записей, проверяемый правилами `hard` целиком: всё или ничего |
| T38 | **индекс** | index | вычисляемое состояние (последние версии, текущие факты, ключи, алиасы, доверие, ссылающиеся); пересобирается из журнала |
| T39 | **пересборка** | rebuild | построение индекса из журнала; дважды — побайтно одинаково |
| T40 | **порядковый номер** | `seq` | целое, позиция записи в журнале; единственный порядок: текущий — последний по `seq`, старейший — меньший `seq`; `at` — только для людей (T-6) |
| T113 | **заголовок строки** | row header | служебные поля строки журнала вне объекта: `seq`, `commit` — у каждой строки; `kernel` (версия ядра), `key?` (ключ идемпотентности) — у маркера `core/commit`; заголовок объекта (T02) не меняется (T-11, LG-12) |
| T114 | **маркер коммита** | `core/commit` | последняя строка коммита, тело `{hash, rows}`; хвост журнала без маркера — не записанный коммит, при открытии → `.lattice/recovered/` (T-9, T-11, LG-12) |
| T115 | **сегмент журнала** | segment | часть журнала для событий исполнения со сроком хранения по маркеру (T184); проекции его не читают, истекает целиком (ADR-3) |
| T184 | **маркер сегмента** | `std/segment-event` | тип с пустой закрытой схемой, объектов своего типа не имеет: строка типа-наследника (`extends`), в том числе проектного, идёт в сегмент маркера со сроком маркера; `std/execution`, `std/measurement` — наследники (12 §1, ADR-3) |
| T170 | **проекция индекса** | `Projection` | раздел индекса: `{name, version, apply(row, ix)}` — чистая функция строки коммита и индекса; разделы журнала — у 12, `trust` подключает 14 через корень сборки (12-ledger §3, N-32) |

## Правила и контракты

| # | Термин | Код | Определение |
|---|---|---|---|

| T125 | **схема тела** | `schema` | поле `core/type`: форма тела (подмножество JSON Schema без `$ref`); компилируется в правило с уровнем; у общих типов (T172) — обязательна, закрыта и `hard`, уровень выбирает только проектный тип (ADR-9) |
| T42 | **уровень правила** | `level` | `hard` — при коммите, нарушение отклоняет запись; `soft` — lint, даёт находку |

| T134 | **проверки ядра** | kernel checks | безусловные проверки на каждой строке коммита любого писателя: `owner`, `immutable`, `grain-unique`, `ref-policy`, `roles`, `content-pin`, `kind`; `type-latest`; при публикации типа — `extends-chain` и совместимость; не параметризуются правилом (T-16); вместе с примитивами — замороженное ядро, версия — `kernel` (ADR-32) |
| T44 | **находка** | finding | результат проверки, который коммит не отклоняет: `soft` в `lint`, нарушение проверки выбора `check` в прогоне; оболочка нарушения + уровень (13-rules §1) |
| T45 | **контракт** | contract | вход и выход способности — ссылки на типы |
| T132 | **чтения и записи стадии** | `reads` / `writes` | пути `ctx`, которые стадия читает и дополняет; правило `contract` при публикации конвейера: каждое чтение записано раньше, в `emits` нет типов блоков (RL-19); `compatible` — по id без версии (T-3) |
| T46 | **совместимость** | compatible | выход A подходит ко входу B: тот же тип или его наследник, совместимый по контракту (ADR-12) |

## Факты и доверие

| # | Термин | Код | Определение |
|---|---|---|---|
| T47 | **факт** | fact | событие, связывающее объекты в ролях, со значением: `{of: {роль: ref}, value}` |
| T48 | **роль** | role | место объекта в факте (`group`, `member`, `alias`, `canonical` …); объявлена типом факта |
| T49 | **ключ факта** | fact key | роли, определяющие «тот же факт»; текущий факт — последний по `seq` с этим ключом среди записей допущенных `writers`; допуск проверен при коммите, отзыв прежних записей не меняет (T-6, ADR-6) |
| T173 | **роль цели** | `target` | поле `core/type` типа факта: роль, пространство чьего объекта — «пространство цели»; его владелец и допуски решают право записи (10-kernel §7) |
| T116 | **писатели типа факта** | `writers` | поле `core/type`: `owner` ⊂ `grant` (владелец или допущенный `core/grant`) ⊂ `any` (любой — «открытый всем»); `{purpose}` — сессии с этим назначением; наследник сужает; проверяет `owner` при коммите (ADR-6) |
| T117 | **действие факта** | `inForce` | поле `core/type`: когда факт действует — `write` (по праву записи) или `{basis: X}`; порядок `write` < `inferred` < `observed` < `derived` < `declared` (ADR-6) |
| T50 | **утверждение** | `core/assert` | факт о факте или ревизии (роль `target`): кто и с какой надёжностью за или против |
| T51 | **надёжность** | `reliability` | число −1…1 в утверждении: «+» — за, «−» — против |
| T52 | **участник** | `core/actor` | тот, кто пишет: `human`, `agent`, `machine`; вид задаёт реестр участников (T118), не сам участник |
| T53 | **сессия** | `core/session` | один сеанс работы участника; открывает и пишет хост, не участник (ADR-25), `by` ревизии — она сама; вне реестра — `actor: null` и `claimed`; `actor` — закреплённая `actor@n` (реестр — на `seq` голоса, TR-13); хост пишет наблюдённое — `claimed_via` (T178) и `os_user` (хэш пользователя ОС); единица «последнего утверждения» (ADR-5); независимость считается по группам (T121) |
| T148 | **программа сессии** | `core/session.software` | `имя@версия` программы участника `machine` (парсер); ставит хост; смена версии — новая сессия, не новый участник (TR-07) |
| T178 | **способ заявления** | `claimed_via` | поле `core/session`: как вызывающий назвал участника — `flag` (`--as` без терминала), `env` (`LATTICE_ACTOR`), `tty` (`--as` в интерактивном терминале с подтверждением); участника `human` называет только `tty`. Личность — заявление вызывающего, хост её не проверяет; поле делает подмену видимой постфактум (14-trust §1, ADR-25) |
| T118 | **реестр участников** | participant registry | сущности `core/actor` в пространстве проекта; пишет владелец или допущенный; участник вне реестра — уровня `agent` (ADR-25) |
| T119 | **декларант** | declarant | участник `human` с допуском `core/grant {declare: true}`: вправе дать основание `declared` и решающее «−», не будучи владельцем; допуск не-человеку не действует (находка lint) (ADR-25) |
| T54 | **доверие** | trust | вычисляется из утверждений по двум осям: основание и состояние спора |
| T55 | **основание** | `basis` | `inferred` (только LLM) · `observed` (≥ N групп независимости, T121) · `derived` (детерминированный разбор источника; запись, выведенная из вердиктов, — не `derived`) · `declared` (явное `core/assert` «+» человека-владельца или декларанта, TR-17) |
| T56 | **состояние спора** | `epistemic` | `settled` (итог «+») · `contested` (есть «+» и «−» / раскачка) · `rejected` («−» независимых групп без заметного «+», TR-14) · `unresolved` (утверждений мало) |
| T179 | **правило выдачи** | — | блок выдаётся, только если жив и его доверие не в `policy.lens.exclude`, с пометками `mark` и `deprecated`; одно для LENS, `recall`, `add[]` и `materialize` (14-trust §7, TR-15) |
| T120 | **исходная сессия** | `via` | необязательное поле `core/assert`: сессия, чей голос несёт утверждение посредника (`learn`); учёт — по `via ?? by` (ADR-5) |
| T121 | **группа независимости** | independence group | единица независимых подтверждений: участник (`human`, `machine`) или `(kind, model)` (`agent`) (ADR-26); `(agent, unknown)` — вне реестра — никому не «другая» (TR-16); поле `trust().groups` — число групп с «+» без группы автора |
| T147 | **голос группы** | group vote | значение группы независимости по цели: `human`/`machine` — последнее утверждение участника, `agent` — среднее последних утверждений её сессий (TR-03) |
| T122 | **перекрыт владельцем** | `overruled` | поле `trust()`: `{by, at}` — решающее «−» явным `core/assert` человека-владельца пространства цели или декларанта; «−» из его вердикта (утверждение обучения) — обычный голос (TR-17); LENS исключает (14-trust/И-13) |
| T57 | **политика доверия** | `std/policy` | объект типа `std/policy` с порогами вычисления доверия, параметрами LENS, кандидатов и обучения; по умолчанию — `std/trust-policy`; своя у пространства имён; правила обучения (`calibration`) — только `std` (TR-05); ядро её не читает (ADR-35) |
| T130 | **держание** | `core/holds` | событие: участник записал значение, которое уже есть в хранилище (своё или скопированное, ADR-4); хранит `by`, в доверие не входит — провенанс, не голос (10-kernel/И-6, Ф-12) |
| T137 | **назначение сессии** | `purpose` | обязательное поле `core/session` (строка из закрытого перечня хоста, 30-adapters §3, AD-15; `bench` резервирует 14-trust, TR-12; `simulate` — 23-bench, T163), ставит хост (ADR-25); доверие и гейт читают его перечнем разрешённых — значение вне перечня не питает и не учит; сессии стенда не питают доверие и обучение — кроме `simulate-consumer` (T-5); от `recall` рабочего пространства их отделяет копия кампании (T138) |
| T142 | **политика кандидатов** | `std/policy.candidates` | порог (ADR-13, T136), бюджет — размер очереди владельца, не предел записи (11 GR-17), кластер — одно решение, память отказов (`std/distinct`, T81); доля принятых — метрика стенда (T-8) |

| T176 | **часть набора** | `subset` | `dev \| test` — поле элемента (T161) и плана (T111): на `dev` калибруют, на `test` меряет регрессионный план (T143); не `split` (T32) (23-bench §1) |
| T105 | **эталон** | gold | ожидаемые блоки для вопроса |
| T106 | **ловушка** | trap | вопрос без слов эталона (доля общих слов ≤ 0,15) |
| T107 | **пустышка** | blank | вопрос, на который в области ответа нет |
| T108 | **перефраз** | paraphrase | другой текст той же потребности |
| T109 | **прогон** | `std/bench-run` | событие `{plan, tuple, results, metrics, verdict: pass \| fail \| invalid, copy}` (`tuple` — кортеж исполнения T131 вызовов кампании): итог кампании в основном журнале; `results` — по вопросу с id вызова в копии |
| T110 | **критерий** | criterion | условие успеха, записанное до прогона |
| T111 | **план стенда** | `std/bench-plan` | событие `{kind: regression \| candidate \| explore, set: ref@n, subset, setup: ref@n, base?, baselines, mode, budget, state, criteria[], n, seed, supersedes?, recheck_every?}` — пишется до прогона; правка — новый план с `supersedes` (ADR-21); режим — в плане; `Meta` расходится с `setup` — прогон `invalid`; `candidate` несёт только `base`, `setup`, `state`; `seed` — из `base` (23-bench BN-07) |
| T112 | **режим simulate-consumer** | `simulate-consumer` | вердикты выводятся из эталона сессиями `purpose: simulate` (T163); единственный режим, где стенд обучает систему, — только в копии кампании |
| T162 | **кампания** | campaign | прогоны планов на одной копии журнала (T138): текущая и новая настройка, базовые линии, проходы первого запуска |
| T163 | **сессия симулятора** | `purpose: simulate` | сессия потребителя-симулятора режима `simulate-consumer`; резервирует 23-bench, открывает хост `lattice bench` только в копии кампании; симулятор — свой участник `machine` (своя группа) |
| T138 | **копия кампании** | `.lattice/bench/<run>` | эфемерная копия журнала, на которой идёт кампания стенда до `plan.state`; её хэш — в `bench-run`; в основной журнал — только `std/bench-run` (T-5, 23-bench BN-08); `replay` вызова кампании — на копии, копии нет — `expired` |
| T180 | **метка копии** | `std/bench-copy` | событие `{plan}` — первый коммит копии кампании (T138), пишет хост `lattice bench` (`writers: {purpose: bench}`); гейт принимает вердикты `purpose: simulate` только в хранилище с меткой, основное хранилище с меткой `open()` не открывает (23-bench BN-14, 30-adapters AD-15, ADR-29) |
| T139 | **гейт обучения** | `learning-gate` | hard-правило коммита: строка обучения `from: verdict` — только если сессия вердикта `purpose: verdict` и `bench` строки — **засчитанный прогон** кортежа вызова (T131): последний по `seq` прогон этого кортежа по плану `candidate` с `base` на регрессионный план (T143), действующий на `seq` плана, и он `pass` (более поздний `fail` закрывает); или `purpose: simulate` при метке копии (T163, T180); ADR-29, 13-rules RL-18 |
| T143 | **регрессионный план** | `base` | план `kind: regression` владельца (действующий — последний по `seq` среди записей того, кто был владельцем на `seq` их записи): регрессионный набор и δ (вектор с направлением, не меньше шума); план кандидата `setup` — новое событие с `base` на него; ротация `test` — новая версия набора (23-bench/И-14, И-15) |

## Слова, которые больше не используются

| Было (черновики) | Стало | Почему |
|---|---|---|
| context (LATTICE) | пространство имён (T05) / область (T76) | универсальная система: граница владения и область поиска — разные вещи |
| posit | факт (T47) | факт — тоже объект (событие), одна форма записи |
| unit | единица знания (T67) и карточка (T71) | блок и его представление для поиска — разные объекты |
| группа-ответ, answer | решение (T82) | покрывает и знания, и способности |
| answer-set | разбор (T78) | междоменный вопрос — несколько потребностей, не особый тип |
| вопрос (объект) | потребность (T79) + подсказка (T72) | текст — подсказка; identity — у потребности |
| алиас unit'а, обучаемый алиас | подсказка (T72) | один механизм для блоков и потребностей |
| Jev, JEV | порт `judge` (T88), адаптер `judge-jev` | технология, а не компонент |
| `content_hash` как версия | версия (T07) + хэш (T12) | номер ревизии и содержимое — разные вещи |
| root kind (concept / thing / event) | режим идентичности + изменяемость (T14–T18) | событие — это режим объекта, остальное — тип |
