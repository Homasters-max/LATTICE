# 02. Глоссарий — единственный список терминов

Термины закреплены. Остальные файлы ссылаются сюда (`T07`) и синонимов не вводят. Код — имя в JSON и коде.
Колонка «Python» — ближайший аналог ([03-python-lessons](03-python-lessons.md)); прочерк — аналога нет.

## Объект и запись (kernel)

| # | Термин | Код | Определение | Python |
|---|---|---|---|---|
| T01 | **объект** | `object` | запись из заголовка и тела; всё в системе — объект (P1) | `PyObject` |
| T02 | **заголовок** | `header` | единственная фиксированная часть объекта: `id`, `type`, `version`, `at`, `by` | `ob_type` + `id()` |
| T03 | **тело** | `body` | открытый JSON; ядро его не ограничивает, ограничивают правила (T41) | `__dict__` |
| T04 | **идентификатор** | `id` | identity объекта: `<namespace>/<local>` или `#`+hex32 у значений (схема 1; метка следующей схемы зарезервирована — 10-kernel §4); не меняется никогда | `id()` |
| T05 | **пространство имён** | `namespace` | граница владения: ядро, библиотека, проект; первая часть `id` | модуль / пакет |
| T06 | **локальное имя** | `local` | часть `id` после `/`: ULID, внешнее стабильное имя (`REQ-KRN-011`) или имя (`type`) | имя в модуле |
| T07 | **версия** | `version` | номер ревизии объекта, целое ≥ 1, в заголовке, **не в теле** | — |
| T08 | **ревизия** | `revision` | неизменное состояние объекта в версии; адрес — `id@version` | — |
| T09 | **ссылка** | `ref` | `id` (следующая) или `id@n` (закреплённая); в теле — `{"$ref": "…"}` | ссылка на объект |
| T10 | **закреплённая ссылка** | `pinned` | `id@n`: всегда указывает на одну ревизию | сильная ссылка |
| T11 | **следующая ссылка** | `following` | `id`: указывает на последнюю живую ревизию | `weakref` + поиск по имени |
| T12 | **хэш содержимого** | `hash` | sha256 канонической формы `{type: <id типа без версии>, body}`: то же содержимое под новой версией типа — то же значение | `__hash__` |
| T13 | **каноническая форма** | `canonical` | JCS (RFC 8785); строки приводятся к NFC на входе коммита — одинаковые данные дают одинаковые байты (ADR-1) | `pickle` / `__reduce__` |
| T14 | **режим идентичности** | `identity` | как получается `id`: `assigned` (выдаётся) или `content` (= хэш) | `is` против `==` |
| T15 | **изменяемость** | `mutable` | может ли объект иметь версию > 1 | `list` против `tuple` |
| T16 | **сущность** | entity | `assigned` + `mutable`: identity стабильна, версии меняются (норма, домен, решение) | экземпляр класса |
| T17 | **событие** | event | `assigned` + неизменяемое: произошло один раз (факт, вызов, вердикт) | — |
| T18 | **значение** | value | `content` + неизменяемое: identity = содержимое (snapshot, карточка) | `tuple`, `frozenset` |
| T19 | **тип** | `type` | объект типа `core/type`: режим идентичности, `extends`, зерно и `grain_scope`, правила и `schema`, роли, ключ, `writers`/`inForce`, политика ссылок, карточка | `type` |
| T20 | **расширение** | `extends` | тип наследует контракт одного родителя — правила, роли, `writers`/`inForce` — только с сужением; карточку — нет (ADR-12) | базовый класс |
| T21 | **ядро** | `core` | замороженное пространство имён: форма записи, типы-основы, примитивы проверок; меняется только версией кода. Не весь код системы: журнал, доверие, каталог, интерпретатор — обычные релизы (10-kernel/И-32) | `builtins` |
| T22 | **стандартная библиотека** | `std` | общие типы механизма и способности (потребность, решение, конвейер …) — данные, версии как у всех; предметные типы — в проектах через `extends` (10-kernel/И-34) | stdlib |
| T23 | **генезис** | genesis | начальный набор объектов `core`; порождается кодом ядра, хэш генезиса — константа версии ядра, сверяется при открытии хранилища (T-10) | инициализация интерпретатора |
| T144 | **происхождение пространства** | `origin` | неизменное поле `core/namespace`: ULID при `init` у проекта, константа у `core` (генезис) и `std` (пакет LATTICE); импорт отклоняет пространство с тем же именем и другим `origin` (10-kernel/И-27) | — |
| T145 | **шифруемое поле** | `$enc` | резерв формата v1: объект тела ровно с одним ключом `$enc`; ядро v1 его отклоняет; позже — шифротекст с ключом вне журнала, удаление ключа «забывает» данные (10-kernel KR-14, T-12) | — |

## Идентичность и зерно

| # | Термин | Код | Определение |
|---|---|---|---|
| T24 | **измерение** | dimension | поле тела, участвующее в зерне |
| T25 | **зерно** | `grain` | список измерений типа, которые определяют «это та же сущность» |
| T26 | **ключ зерна** | grain key | `hash(id типа, значения измерений)`; уникален среди живых сущностей типа в пространстве автора (T124, ADR-27) |
| T124 | **область зерна** | `grain_scope` | поле `core/type`: где ключ зерна уникален — пространство автора (по умолчанию) или `store` — всё хранилище (справочники `std`) (ADR-27) |
| T27 | **дубль** | duplicate | две живые сущности одного типа с одним ключом зерна — запрещено правилом `hard` |
| T28 | **семантический дубль** | near-duplicate | разные ключи зерна, один смысл; найденный — кандидат в алиас (T123), не слияние |
| T29 | **интернирование** | intern | запись уже существующего значения даёт тот же объект; для сущностей — `ensure` («найди или создай») |
| T30 | **алиас** | `core/alias` | факт «сущность A — это сущность B»; пишет владелец — подтверждение кандидата (ADR-8); ссылки на A разрешаются в B |
| T123 | **кандидат в алиас** | `std/alias-candidate` | накопительный факт «A — возможно, B», ключ `[alias, canonical]`; пишет любой, в силу не входит; индексы и `resolve` его не видят (ADR-8) |
| T31 | **слияние** | merge | установка алиасов по плану; обратимо, история не переписывается |
| T32 | **разделение** | split | отмена алиаса: владелец пишет `core/alias {value: false}`; «−1» влияет на доверие, но не отменяет (10-kernel/И-30, ADR-6) |
| T33 | **перезерновка** | regrain | пересчёт ключей зерна при смене зерна или тела; отчёт о коллизиях; план разрешения — владелец пространства (ADR-7) |
| T34 | **коллизия** | collision | набор живых сущностей, получивших один ключ зерна |
| T35 | **живая сущность** | live | не выведена из обращения (T58) и не является алиасом |

## Журнал

| # | Термин | Код | Определение |
|---|---|---|---|
| T36 | **журнал** | `ledger` | append-only последовательность ревизий; единственный источник истины; строка не меняется, сегмент со сроком истекает только целиком (ADR-3) |
| T37 | **коммит** | commit | пакет записей, проверяемый правилами `hard` целиком: всё или ничего |
| T38 | **индекс** | index | вычисляемое состояние (последние версии, текущие факты, ключи, алиасы, доверие, потребители); пересобирается из журнала |
| T39 | **пересборка** | rebuild | построение индекса из журнала; дважды — побайтно одинаково |
| T40 | **порядковый номер** | `seq` | целое, позиция записи в журнале; единственный порядок: текущий — последний по `seq`, старейший — меньший `seq`; `at` — только для людей (T-6) |
| T113 | **заголовок строки** | row header | служебные поля строки журнала вне объекта: `seq`, `commit` — у каждой строки; `kernel` (версия ядра), `key?` (ключ идемпотентности) — у маркера `core/commit`; заголовок объекта (T02) не меняется (T-11, LG-12) |
| T114 | **маркер коммита** | `core/commit` | последняя строка коммита, тело `{hash, rows}`; хвост журнала без маркера — не записанный коммит, при открытии → `.lattice/recovered/` (T-9, T-11, LG-12) |
| T115 | **сегмент журнала** | segment | часть журнала для событий исполнения со сроком хранения по типу; проекции его не читают, истекает целиком (ADR-3) |

## Правила и контракты

| # | Термин | Код | Определение |
|---|---|---|---|
| T41 | **правило** | `core/rule` | объект: уровень, примитив проверки, параметры, к каким типам применяется |
| T125 | **схема тела** | `schema` | поле `core/type`: форма тела (подмножество JSON Schema без `$ref`); компилируется в правило с уровнем, `hard` по умолчанию для `core`/`std` (ADR-9) |
| T42 | **уровень правила** | `level` | `hard` — при коммите, нарушение отклоняет запись; `soft` — lint, даёт находку |

| T134 | **проверки ядра** | kernel checks | безусловные проверки на каждой строке коммита любого писателя: `owner`, `immutable`, `grain-unique`, `ref-policy`, `roles`; не параметризуются правилом (T-16) |
| T44 | **находка** | finding | результат `soft`-проверки: объект, правило, сообщение |

| T132 | **чтения и записи стадии** | `reads` / `writes` | пути `ctx`, которые стадия читает и дополняет; правило `contract` при публикации конвейера: каждое чтение записано раньше; `compatible` — по id без версии (T-3) |
| T46 | **совместимость** | compatible | выход A подходит ко входу B: тот же тип или его наследник, совместимый по контракту (ADR-12) |

## Факты и доверие

| # | Термин | Код | Определение |
|---|---|---|---|
| T47 | **факт** | fact | событие, связывающее объекты в ролях, со значением: `{of: {роль: ref}, value}` |
| T48 | **роль** | role | место объекта в факте (`group`, `member`, `alias`, `canonical` …); объявлена типом факта |
| T49 | **ключ факта** | fact key | роли, определяющие «тот же факт»; текущий факт — последний по `seq` с этим ключом среди записей допущенных `writers` (T-6, ADR-6) |
| T116 | **писатели типа факта** | `writers` | поле `core/type`: кто вправе писать факт — владелец пространства цели, допущенные (`core/grant`) или любой (накопительные факты); проверяет `owner` при коммите (ADR-6) |
| T117 | **действие факта** | `inForce` | поле `core/type`: когда факт этого типа действует (ADR-6) |
| T50 | **утверждение** | `core/assert` | факт о факте или ревизии (роль `target`): кто и с какой надёжностью за или против |
| T51 | **надёжность** | `reliability` | число −1…1 в утверждении: «+» — за, «−» — против |
| T52 | **участник** | `core/actor` | тот, кто пишет: `human`, `agent`, `machine`; вид задаёт реестр участников (T118), не сам участник |
| T53 | **сессия** | `core/session` | один сеанс работы участника; открывает хост, не участник (ADR-25); единица «последнего утверждения» (ADR-5); независимость считается по группам (T121) |
| T148 | **программа сессии** | `core/session.software` | `имя@версия` программы участника `machine` (парсер); ставит хост; смена версии — новая сессия, не новый участник (TR-07) |
| T118 | **реестр участников** | participant registry | сущности `core/actor` в пространстве проекта; пишет владелец; участник вне реестра — уровня `agent` (ADR-25) |
| T119 | **декларант** | declarant | участник с допуском `core/grant {declare: true}`: вправе дать основание `declared`, не будучи владельцем (ADR-25) |
| T54 | **доверие** | trust | вычисляется из утверждений по двум осям: основание и состояние спора |
| T55 | **основание** | `basis` | `inferred` (только LLM) · `observed` (≥ N групп независимости, T121) · `derived` (детерминированный разбор источника; вывод — не выше входов) · `declared` (владелец) |
| T56 | **состояние спора** | `epistemic` | `settled` · `contested` (есть «+» и «−» / раскачка) · `unresolved` (утверждений мало) |
| T120 | **исходная сессия** | `via` | необязательное поле `core/assert`: сессия, чей голос несёт утверждение посредника (`learn`); учёт — по `via ?? by` (ADR-5) |
| T121 | **группа независимости** | independence group | единица независимых подтверждений: участник (`human`, `machine`) или `(kind, model)` (`agent`) (ADR-26); поле `trust().groups` — число групп с «+» без группы автора |
| T147 | **голос группы** | group vote | значение группы независимости по цели: `human`/`machine` — последнее утверждение участника, `agent` — среднее последних утверждений её сессий (TR-03) |
| T122 | **перекрыт владельцем** | `overruled` | поле `trust()`: `{by, at}` — решающее «−» владельца пространства цели; LENS исключает (14-trust/И-13) |
| T57 | **политика доверия** | `core/trust-policy` | объект с порогами вычисления доверия; своя у пространства имён; правила обучения (`calibration`) — только `std` (TR-05) |
| T130 | **держание** | `core/holds` | событие: участник записал значение, которое уже есть в хранилище (своё или скопированное, ADR-4); хранит `by`, в доверие не входит — провенанс, не голос (10-kernel/И-6, Ф-12) |
| T137 | **назначение сессии** | `purpose` | обязательное поле `core/session` (строка; `bench` резервирует 14-trust, TR-12; `simulate` — 23-bench, T163), ставит хост (ADR-25); сессии стенда не питают доверие, обучение и `recall` — кроме `simulate-consumer` (T-5) |
| T142 | **политика кандидатов** | `core/trust-policy.candidates` | порог (ADR-13, T136), бюджет на владельца, кластер — одно решение, память отказов (`std/distinct`, T81); доля принятых — метрика стенда (T-8) |

| T74 | **словарь** | lexicon | термины области; подаётся в judge как `state` один раз на запрос |
| T75 | **домен** | `std/domain` | сущность-группа блоков проекта (проекция, не граница владения); область поиска |
| T76 | **область** | scope | где решается потребность: пространство имён + домен |
| T77 | **пул** | `std/pool` | значение `{scope, cards}`: карточки живых блоков области без исключённых `policy.lens`, поданные на оценку |
| T78 | **разбор** | frame | задача → список атомарных потребностей |
| T79 | **потребность** | `std/need` | атомарная потребность в одной области; то, под что сохраняется решение |

## Слова, которые больше не используются

| Было (черновики) | Стало | Почему |
|---|---|---|
| context (LATTICE) | пространство имён (T05) / область (T76) | универсальная система: граница владения и область поиска — разные вещи |
| posit | факт (T47) | факт — тоже объект (событие), одна форма записи |
| unit | единица знания (T67) и карточка (T71) | блок и его представление для поиска — разные объекты |
| группа-ответ, answer | решение (T82) | покрывает и знания, и способности |
| answer-set | разбор (T78) | междоменный вопрос — несколько потребностей, не особый тип |
| вопрос (объект) | потребность (T79) + подсказка (T72) | текст — подсказка; identity — у потребности |
| алиас unit'а, обучаемый алиас | подсказка (T72) | один механизм для блоков и потребностей |
| Jev, JEV | порт `judge` (T88), адаптер `judge-jev` | технология, а не компонент |
| `content_hash` как версия | версия (T07) + хэш (T12) | номер ревизии и содержимое — разные вещи |
| root kind (concept / thing / event) | режим идентичности + изменяемость (T14–T18) | событие — это режим объекта, остальное — тип |
