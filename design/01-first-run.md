# 01. Первый запуск — цель, эффект, протокол

## Цель

Показать на реальных данных WARRANT (подбор норм для агентов), что система:

1. **находит** нужные нормы лучше простого поиска;
2. **помнит**: повтор потребности обслуживается без поиска — дешевле и не хуже;
3. **учится**: вердикты чинят неполные и ошибочные решения;
4. **честно отказывает**: «нужного нет» отличает от промаха поиска;
5. **не дублирует и не схлопывает** объекты при смене гранулярности;
6. **описывает и воспроизводит себя**: конвейер берётся из LATTICE, прогон воспроизводится побайтно.

Один прогон проверяет обе половины концепции: блоки знаний — нормы WARRANT; блоки способностей — стадии конвейера,
который их ищет.

## Что мы увидим (эффекты и критерии)

Критерии предварительные: окончательные числа фиксируются в `std/bench-plan` **до** прогона (BN-02).

| # | Эффект | Как видно | Критерий (предварительно) |
|---|---|---|---|
| **E1** | Находит | `hit@3`, `MRR` на контроле против базовых линий | `hit@3` ≥ 0,95; `MRR` выше «BM25 по документам целиком» на ≥ 0,3, нижняя граница 95 % CI > 0 |
| **E2** | Помнит | проход B: перефразы и точные повторы | `recall-rate` ≥ 0,6 на перефразах и 1,0 на повторах; `select-F1` не ниже прохода A (Δ ≥ −0,02); цена на вопрос ниже ≥ 50 % |
| **E3** | Учится | проход C: намеренно испорченные решения после вердиктов | `calibration-Δ` (`select-F1`) ≥ +0,1; ≥ 80 % испорченных починено; ни один верный член не удалён |
| **E4** | Честно отказывает | пустышки и промахи | пустышки → `no-match` / `gap`: точность и полнота ≥ 0,8; каждый промах B → кандидат в ловушку |
| **E5** | Не дублирует | сценарий смены зерна домена | 0 тихих слияний, 0 дублей; публикация без плана отклонена; слияние и разделение обратимы; `rebuild --check` совпадает |
| **E6** | Самоописание и воспроизводимость | конвейер из LATTICE; `replay`; версия 2 конвейера | конвейер читается из журнала; `replay` и `rebuild` побайтно совпадают; версия 2 закрепляется или отклоняется регрессионным барьером по данным |
| E7 *(необязательно)* | Универсальность | второе пространство (малый справочник) на том же `std` | ноль правок ядра и `std`; только адаптер `source` и конфигурация |

Главная картинка для человека — **три реальные задачи WARRANT** (группы задач Change): пакет норм, который получил
бы агент, с причинами и доверием, рядом с тем, что агент читал без LATTICE.

## Протокол прогона

```text
R0  init                 .lattice/, core + std, пространство warrant, политика доверия
R1  import               нормы, домены, словарь, набор стенда                          → S4
R2  lint + rebuild       ноль находок hard; rebuild --check побайтно                    → E6 (часть)
R3  план                 std/bench-plan: набор@n, конвейер@1, базовые линии, критерии  → записан до прогона
─── проход A (холодный) ────────────────────────────────────────────────────────────────
R4  solve × контроль     все вопросы test через конвейер; базовые линии:
                         (a) BM25 по документам целиком, (b) BM25 в домене, (c) LENS без recall  → E1, E4
R5  вердикты             режим simulate-consumer: вердикт по эталону
                         (выбор = эталон → complete; не хватает → incomplete + add; лишнее → unused;
                          мимо → wrong); сессии — разные для групп перефразов                   → S8
─── проход B (повтор) ──────────────────────────────────────────────────────────────────
R6  solve × перефразы    перефразы и точные повторы вопросов прохода A                        → E2
─── проход C (обучение) ────────────────────────────────────────────────────────────────
R7  порча                отдельная сессия убирает по одному эталонному члену у N решений
                         и добавляет по одному лишнему (факты членства)
R8  solve + вердикты     те же потребности; вердикты simulate-consumer, 3 сессии              → E3
─── сценарии ───────────────────────────────────────────────────────────────────────────
R9  зерно                фикстура: домены lifecycle/ru и lifecycle/en; новая версия std/domain
                         без language в grain → отчёт → без плана отклонено → merge → split   → E5
R10 конвейер v2          fuse: rrf → регрессия на наборе → закрепить или отклонить           → E6
R11 replay               повтор прогона R4 из кэшей → побайтное сравнение пакетов             → E6
R12 демонстрация         3 задачи Change → пакеты                                            → картинка
R13 отчёт                .lattice/runs/first-run.md + std/bench-run в журнале
```

**Режим `simulate-consumer`** — единственное место, где стенд обучает систему (BN-04): вердикты выводятся из эталона,
чтобы измерить механику обучения без живых агентов. Это явно помечено в отчёте. Живые вердикты агентов —
следующий этап.

## Отчёт (что будет в `first-run.md`)

1. Таблица E1–E6: метрика, критерий, результат, CI, PASS/FAIL.
2. E1: `hit@3` / `MRR` по доменам и видам вопросов (обычные, ловушки) против трёх базовых линий.
3. E2: доля повторов без поиска, цена и задержка до/после, `select-F1` A против B.
4. E3: испорченные решения — было / стало, какие члены вернулись, какие ушли.
5. E4: пустышки — отказ; промахи B — список ловушек-кандидатов.
6. E5: отчёт о коллизиях, план, журнал фактов алиасов, результат `rebuild --check`.
7. E6: версия конвейера, решение барьера, результат `replay`.
8. Три пакета норм для реальных задач.
9. Что не сработало и какие решения доменов пересмотреть.

## Вне первого запуска

- Исполнение способностей проектов (`exec`) — только builtin-стадии.
- Живые вердикты агентов, UI, несколько хранилищ.

## Вопросы для grilling

1. **Критерии E1–E3** — такие числа или ориентироваться на результаты черновиков (MRR 0,90 / 1,00 в доменах)?
   Рекомендация: E1 — не ниже черновиков на том же контроле; E2–E3 — как в таблице, это новые эффекты без истории.
2. **Порча в проходе C** — синтетическая (R7) или найти реально неполные решения прохода A? Рекомендация: обе —
   реальные дают честный эффект, синтетические гарантируют объём выборки.
3. **E7** включать? Рекомендация: да, если есть 30 минут на адаптер малого справочника — это единственное прямое
   доказательство универсальности.
