# 03. Уроки объектной модели Python (и что это значит для TS/Node)

Python — язык, где «всё есть объект» доведено до конца, включая типы и сам тип `type`. Его низкий уровень
(CPython) решает те же задачи, что и LATTICE: identity, равенство, неизменяемость, типы как объекты, реестр
модулей. Ниже — что берём, что меняем и почему. Реализация — TypeScript/Node, как WARRANT.

## Что берём

| Python (CPython) | Как устроено | LATTICE | Решение |
|---|---|---|---|
| `PyObject` = `ob_refcnt` + `ob_type` + данные | у каждого объекта маленький фиксированный заголовок и произвольное тело | заголовок `{id, type, version, at, by}` + открытое `body` | KR-01, KR-02 |
| `id(x)` против `x == y` | identity и равенство — разные вопросы; `is` сравнивает identity | `id` — identity; `hash` — равенство содержимого | KR-04, KR-05 |
| `type(x)`, `type(type) is type`, `object` — база всех | тип — тоже объект; цепочка замыкается на `type` | `core/type` имеет тип `core/type`; генезис замыкает цепочку | KR-08 |
| изменяемые (`list`, `dict`) против неизменяемых (`tuple`, `frozenset`, `str`) | хэшировать можно только неизменяемое | `mutable: false` у событий и значений; идентичность по содержимому — только у неизменяемых | KR-04 |
| интернирование (малые `int`, `sys.intern`) | одинаковое значение — один объект в памяти | значение с тем же содержимым — тот же `id` (`#hash`); повторная запись — no-op по `(type@n, hash)` или `core/holds`, если пространство значение ещё не держит | KR-04, GR-01, ADR-2 |
| контракт `__eq__` / `__hash__`; изменение ключа в `dict` ломает словарь | равные объекты обязаны иметь равный хэш; ключ нельзя менять на месте | ключ зерна (T26) меняется только через перезерновку с планом, не на месте | GR-03, GR-04 |
| `__dict__` против `__slots__` | по умолчанию атрибуты открыты; `__slots__` — добровольное ограничение | тело открыто; схема — правило типа; у общих типов (`core`, `std`, импортируемых) обязательна, закрыта и `hard` | KR-02, RL-02 |
| дескрипторы, `@property` | атрибут может быть вычисляемым, а не хранимым | доверие, статус snapshot'а, «последняя версия» — вычисляются в индексе, не пишутся | LG-02 |
| `typing.Protocol` (структурно) и `abc.ABC` (номинально) | совместимость по форме или по объявленному родству | контракт — номинально (`extends`); структурная совместимость — не в первой версии, когда появятся способности из разных проектов | RL-05 |
| MRO, наследование | линеаризация множественного наследования | `extends` — один родитель; композиция вместо иерархий | KR-09 |
| `__class__ = Other` (смена класса экземпляра) | identity сохраняется при смене типа | смена типа сущности — новая версия с другим `type`; `id` не меняется | KR-10 |
| `sys.modules`, `import`, пакеты | реестр загруженных модулей; пространства имён | пространства имён, `imports` проекта, индекс | CT-01, CT-02 |
| `builtins` против stdlib против site-packages | неизменное ядро, стандартная библиотека, пакеты пользователя | `core` (заморожено) → `std` (данные) → пространство проекта | KR-11 |
| подсчёт ссылок, GC | объект живёт, пока на него ссылаются | удаления ревизий нет; индекс ссылающихся (`referrers`) показывает, кто держит ревизию; вывод из обращения — факт; события исполнения — сегментами со сроком, истекают только целиком | CT-05, ADR-3 |
| `weakref` | ссылка, которая не удерживает объект | следующая ссылка (`id` без версии) не закрепляет ревизию | KR-07 |
| `pickle`, `__reduce__` | каноническое представление объекта для сериализации | каноническая форма JCS (RFC 8785), строки — NFC на входе → хэш | KR-06, ADR-1 |
| `@dataclass(frozen=True)` | неизменяемая запись с равенством по полям | тип значения (`identity: content`) | KR-04 |
| `__init_subclass__`, метаклассы | хук при создании класса | правила типа проверяются при публикации его версии (перезерновка, совместимость) | GR-03 |

## Что меняем по сравнению с Python

| Python | LATTICE | Почему |
|---|---|---|
| объект мутирует на месте | ревизия неизменна, новая версия — новая запись | история, воспроизводимость, «кто на какой версии» |
| `id()` — адрес в памяти, живёт с процессом | `id` — постоянное имя в пространстве имён | объекты живут годами и между проектами |
| удаление при нуле ссылок | удаления ревизий нет, только вывод из обращения; события исполнения истекают сегментом целиком ([12](domains/12-ledger.md) §1) | закреплённые ссылки обязаны разрешаться всегда; значения, на которые ссылается трасса, лежат в основном журнале и не истекают |
| тип объекта можно менять свободно | смена типа — новая версия, проверяется правилами нового типа | правила зависят от типа |
| один процесс — один мир | много проектов, много хранилищ | пространства имён и импорты |

## Что это значит для TS/Node

- **Структурная типизация TS** совпадает с идеей открытого тела: форма проверяется схемой, а не классом.
- **Номинальные ID** — branded types (`type Id = string & {__brand: 'Id'}`), чтобы `Ref` и `Id` не путались.
- Запись журнала — одна структура `Revision`; различий «класс на тип» в коде нет: тип — данные.
- Неизменяемость — `readonly` и `Object.freeze` на ревизиях из журнала; меняется только индекс.
- Хэш — `node:crypto` sha256 над канонической строкой; каноническая форма — JCS (RFC 8785) готовой реализацией с её
  тестовыми векторами (ключи — по кодовым единицам UTF-16, числа — по ES `Number.prototype.toString`); строки
  приводятся к NFC на входе коммита (KR-06, ADR-1).
- ULID — для выдаваемых `id`: время + случайность, без координации между процессами и машинами.
