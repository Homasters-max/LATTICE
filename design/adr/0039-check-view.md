# ADR-39. Вид проверки `CheckView` — контракт у rules, три адаптера

Статус: принято 2026-09-29 · сессия R1–R4 (архитектурный разбор 2026-09-29, кандидат 2)

Проверкам ядра и примитивам нужен синхронный умозрительный вид «индекс + незакоммиченные строки» на префиксе или на итоге коммита (LG-03). `LedgerView` (12 §5) — порт чтения стадий: `history` асинхронна, чтений `grain`, `aliases`, `executions` и цепочки типа в нём нет. Copy-on-write проекций для каждого префикса не принадлежал никому, а `examples` правила (RL-10) прогонять было не на чем, кроме хранилища.

Решили:

1. **`CheckView` — контракт у потребителя, rules** (ADR-24): ровно чтения перечня [04](../04-architecture.md) §1 (ADR-35) — `revisions`, `latest`, `grain`, `aliases`, `facts`, `executions`, цепочка `extends` типа, поля `std` для гейта; синхронный, не шире перечня.
2. **Три адаптера с первого дня.** Индекс на `seq` (чтения вне коммита, `revalidate`); `overlay(ix, rows)` у ledger — `.at(i)` префикс до строки `i`, `.total()` итог коммита, copy-on-write проекций внутри; `fromRows(rows)` у rules — вид из строк без хранилища: `examples` правила и тесты проверок.
3. **`LedgerView` остаётся портом стадий** (`get`, `history`, `facts`, `find`, `referrers` на `seq`).
4. Исключение правила интерфейса (04 §2) «`rules/types` → `ledger/types`» снимается: rules читает свой `CheckView`, ledger реализует его адаптером `overlay`.

**Варианты:** (б) расширить `LedgerView` чтениями проверок — порт стадий раздувается чтениями ядра, `history` асинхронна, проверки на `examples` по-прежнему без вида; (в) проверки читают сырой индекс — владельца префикса и итога нет.

**Последствия:** 13-rules (§2 — `CheckView`, `fromRows`), 12-ledger (§3, §5 — адаптер `overlay`), 04-architecture (§2 — правило интерфейса, AR-06), 05-slices (S1: каждая проверка — тест на `fromRows()`; префикс против итога — один тест `overlay`). Шов кандидата 1 (ADR-38).

**Опора:** архитектурный разбор 2026-09-29, кандидат 2; ADR-24, ADR-35; решение maintainer'а (сессия R1–R4, Q2).
