# ADR-34. Переход ядра — цепочка генезиса и коммит перехода

Статус: принято 2026-09-27 · challenge-аудит, волна 1 (CA-F12) · принцип; протокол — до первой версии ядра после первых данных

Хэш генезиса — константа версии ядра, `open()` сверяет его при открытии (`design/domains/10-kernel.md` KR-16, `design/domains/12-ledger.md` §2); ревизии `core/*` пишет только код ядра. До первой записи реальных данных смена генезиса — новая константа и пересчёт фикстур (SL-04). После неё путь «журнал ядра v1 → ядро v2» не был описан: `open()` отказывает по хэшу, писать `core/<тип>@2` нечем — владельца `core` в хранилище проекта нет (CA-F12). Любая эволюция замороженного становилась пересозданием хранилища или внештатным обходом сверки — «валидатор меняется посреди работы» (P9).

Решили: **переход ядра** (T177) по образцу коммита обновления `std` (CT-10).

1. **Цепочка генезиса.** Ядро vN знает хэши генезиса v1…vN и для каждого шага vK → vK+1 — дельту генезиса: новые ревизии `core/*`, которые порождает код ядра, как сам генезис. `open()` принимает хранилище, чей генезис и уже записанные переходы — префикс цепочки; хэш вне цепочки — отказ. Ядро v1 знает цепочку из одного звена; отключать сверку нельзя ни «временно», ни флагом.
2. **Коммит перехода.** Дельту vK → vK+1 пишет сессия `core/genesis-vK+1` — объект `core/session` в самой дельте, `by` — она сама (как `core/genesis`); коммит отдельный, `key = kernel:vK+1`, маркер несёт `kernel = vK+1`. Принять переход — акт владельца проекта: хост открывает коммит от его имени, как обновление `std`. До перехода хранилище на новом ядре открывается только на чтение.
3. **Строка судится ядром своего коммита.** Проверки ядра строки — версии `kernel` её маркера; новое ядро прежние строки не перепроверяет. Что изменилось бы, показывает `revalidate` (RL-12).

**Отложено до первой версии ядра после первых данных** (триггер — запрос на изменение, которое по 04 §1 требует новой версии ядра, когда в хранилище проекта уже есть реальные данные): исключение проверки `owner` для сессии `core/genesis-vN`, команда CLI перехода, порядок с обновлением `std`, чьи типы ссылаются на новые `core/*`. В v1 уже сейчас: `kernel` в каждом маркере (LG-12), сверка генезиса — как принадлежность цепочке, тест S1 «хэш вне цепочки — отказ `open()`».

**Варианты:** (б) новое хранилище и перенос строк с картой «старый → новый `seq`» — ядру проще, но меняются `seq` и хэши коммитов, а трассы, snapshot'ы и ключи идемпотентности ссылаются на старые. (в) Отложить целиком с триггером — первый же запрос на новое ядро встречает хранилище без пути, и соблазн обойти сверку хэша.
