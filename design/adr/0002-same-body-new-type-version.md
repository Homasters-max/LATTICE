# ADR-2. То же тело под новой версией типа — новая ревизия; no-op — по `(type@n, hash)`

Статус: принято 2026-09-27 · сессия R3

Запись сущности с тем же хэшем тела, но под новой версией типа (`type@n+1`), — новая ревизия, а не no-op. Совпадение «ничего не изменилось» проверяется по паре `(type@n, hash)`; формула хэша (T-11, ADR-1) не меняется. Так перевод сущностей на новую версию типа без изменения тела (`migrate`) выполним. Значения (`content`) не затрагиваются: при совместимой версии типа `#id` тот же. Кто запускает перевод и когда выводится старая версия — решения волн 2 и 3 (15-catalog/И-13 — сессия R4; вывод старых версий — сессия R5); вопрос Q-47 разнесён по ним.

**Варианты:** (б) явная миграция — отдельная операция, которая тот же результат пишет особым видом записи; (в) валидность по текущей версии типа без перевода — старые ревизии молча проверяются новой схемой, закреплённая версия типа теряет смысл.

**Последствия:** 10-kernel (no-op записи), 12-ledger (no-op коммита), 11-identity-grain (перевод при смене зерна), 15-catalog (`migrate`), 05-slices (S2). Откат низкий — лишние ревизии в журнале безвредны.

**Опора:** Q-03 C-3, D-13 (рассуждение); связь с Q-47 C-2…C-4 — довод брифа R3.

**Реестр:** ADR-2; частично — 10-kernel/И-2, 13-rules/И-3.
