# ADR-47. Происхождение голоса — `via ?? by` без знания типов run; «в силе ли факт» — операция trust

Статус: принято 2026-09-29 · сессия R1–R4 (архитектурный разбор 2026-09-29, кандидат 10); код — срез S3, S8

Чтобы вычислить `basis`, trust шёл по `from` к `std/verdict` за его `by` и узнавал `std/learned-assert` — тип 22-run — чтобы исключить его из `declared` и из решающего «−» (TR-17): trust ниже run по матрице, но кодировал правила происхождения run, и новый тип строки обучения молча менял смысл доверия. «В силе ли факт» (`inForce {basis}`, KR-13) не отвечал ни один модуль: проекция `facts` его не учитывает, в операциях trust его нет, lens выводил «подсказка ≥ `observed`» сам (LN-10); порядок `basis` описан дважды — 10 §7 и 14 §3. Отказ `trust()` на политике не `std/policy` (ADR-35) не имел места: непонятно, ломает ли он коммит, пересборку или каждое чтение. Проекция `trust` зависела от порядка списка проекций.

Решили:

1. **Автор голоса = `via ?? by`; решающий голос — явный `core/assert` без `via`.** `declared` и решающее «−» даёт только утверждение, чья сессия — сама автор голоса; утверждение с `via` (посредник, `learn`) — обычный голос группы автора. Trust не знает имён типов run.
2. **Контракт на стороне run:** строка, выведенная из вердикта (`from`), несёт `via` — сессию вердикта. Уточнено C2: держит гейт `learning-gate` (он уже в `rules` каждого такого типа), а не безусловная схема — строки тех же типов без `from` (член от Composer, подсказка `recall`) `via` не несут.
3. **Интерфейс trust += `inForce(fact)` и `standing(target)`:** «в силе ли факт» по `inForce` его типа и доверию; порядок `basis` — одно место (14 §3), 10 §7 ссылается. Lens читает `inForce`, не выводит порог сам.
4. **Проверка политики — при `open()`:** ссылка `namespace.policy` не на `std/policy` — отказ открытия с адресом, не каждого чтения.
5. **Голос хранит свои признаки на своём `seq`** (группа, вес по ключу — из `authority`, ADR-40): смена политики перевзвешивает сохранённые голоса, не прогоняет журнал; результат не зависит от порядка проекций (`rebuild --check`).

**Варианты:** (б) отложить до S3 — нарушение слоёв уже в тексте TR-17, цена на бумаге — только текст.

**Последствия:** 14-trust (§2, §3, «Операции», TR-07, TR-17, инварианты 3–4), 22-run (§6 — `via` у типов обучения, RN-14), 20-lens (LN-10), 10-kernel (§7 — `inForce` ссылается на trust, порядок `basis`), 12-ledger (§3 — `facts` и порядок проекций).

**Опора:** архитектурный разбор 2026-09-29, кандидат 10; ADR-5 (расширяется), ADR-6 (вычислитель `inForce`), ADR-35 п. 2 (место отказа) — не противоречит ни одному; решение maintainer'а (сессия R1–R4, Q10).
