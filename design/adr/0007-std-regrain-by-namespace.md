# ADR-7. Смена зерна `std`-типа — перезерновка по пространствам с планами их владельцев

Статус: принято 2026-09-27 · сессия R3

Смена зерна общего (`std`) типа — новая версия типа с новым зерном; сущности этого типа перезерновываются **по пространствам имён**: в каждом пространстве коллизии новых ключей (область зерна — пространство автора, ADR-27) разрешает план его владельца (ADR-6, ADR-25). Обновление `std` в хранилище проекта проходит вместе с планом владельца проекта: без плана для пространств с коллизиями новая версия типа не публикуется в этом хранилище. Протокол сбора планов и то, кто подписывает коммит обновления `std`, — доменные проходы 11-identity-grain и 15-catalog (D03, D06). Принято принципом до первой смены зерна `std`-типа: пока у `std` один потребитель, протокол минимален.

**Варианты:** (а) expand-and-contract — новый тип рядом со старым и перевод сущностей: сохраняет `id` старых только через алиасы, удваивает типы на время перехода, а решение о переводе чужих сущностей всё равно требует их владельцев. Отложить до первой смены: 11-identity-grain/И-5 и дыра «перезерновка без владельца» (15-catalog) остались бы без правила.

**Последствия:** 11-identity-grain (перезерновка, `regrain`; И-5), 15-catalog (обновление `std`, `migrate`), 02-glossary (T33). Откат низкий до первой смены зерна `std`; после `merge` по плану — необратимо.

**Опора:** Q-16 C-3, D-33; T-7, T-13; ADR-27.

**Реестр:** ADR-7; определяет 11-identity-grain/И-5.
