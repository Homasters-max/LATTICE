# ADR-43. Замороженное ядро — одна версионированная точка входа `kernel-v1`

Статус: принято 2026-09-29 · сессия R1–R4 (архитектурный разбор 2026-09-29, кандидат 6)

Обещание «меняется только с версией `kernel`» (ADR-32, ADR-35) охранялось в одном каталоге из трёх: у `src/kernel` есть тест чистоты (REQ-AR-001), у `src/rules/kernel-checks` (проверки, примитивы, гейт) и у `src/ledger/projections.ts` (`revisions`, `latest`, `grain`, `aliases`, `facts`, `executions`) — нет. Правка проекции молча меняла смысл ядра v1; проекции `grain` и `aliases` кодируют семантику identity (GR-02, GR-05), а лежат в ledger.

Решили:

1. **`kernel-v1 = {kernel, genesis, checks, primitives, projections, authority}`** — одна версионированная точка входа замороженного ядра; каталоги ADR-32 остаются на месте. Файл — `src/ledger/kernel-v1.ts` (уточнено D08): матрица не даёт `src/kernel` импортировать rules и ledger, а ledger — нижний домен, которому разрешены `kernel`, `identity`, `rules`.
2. **Тест структуры** распространяет правила чистоты ядра (без ввода-вывода, без зависимостей вне ядра и интерфейсов) на всё, что достижимо из точки входа.
3. Маркер коммита берёт `kernel` из точки входа; замороженные фикстуры по версии `kernel` гоняются против неё; смена версии ядра — новая точка входа, а не правка трёх каталогов.
4. Смысл проекций `grain` и `aliases` — у 11-identity-grain, код — в ledger, охрана — точкой входа.

Уточнено F (финальное чтение, F-dev Н21, Н22): форма `kernel-v1 = {version: "v1", genesis: {rows, hash}, checks, primitives, projections, authority, overlay, fromRows}` (04 §1) — вид `overlay` определяет вердикт проверок наравне с проекциями; тест структуры п. 6 — «достижимое из точки входа ⊆ явного перечня периметра» (04 §3): прежнее «импортирует только достижимое» было истинно всегда; фикстуры — `test/fixtures/kernel-v1/`.

**Варианты:** (б) как есть — периметр ядра охраняется в одном каталоге из трёх; (в) перенести проекции и проверки в `src/kernel` — ломает раскладку ADR-32 (проверкам нужен индекс).
