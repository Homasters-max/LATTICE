# ADR-35. Что ядро читает вне `core` — часть версии ядра; тип политики доверия — в `std`

Статус: принято 2026-09-27 · challenge-аудит, волна 1 (CA-F13, CA-F49)

Замороженное ядро — генезис, примитивы и проверки ядра (`design/04-architecture.md` §1). Но гейт обучения `learning-gate` читает поля `std/verdict`, `std/bench-run`, `std/bench-plan`, `std/execution` и значения `purpose`, которые меняются релизами `std`; проверки ядра судят по проекциям индекса, которые выходят релизами ledger; а в генезисе лежит тип `core/trust-policy` с закрытой схемой, где параметры LENS, кандидатов и обучения (CA-F13, CA-F49). Два канала релиза были связаны неявно: `std/bench-plan@2` с новым `kind` проходил совместимость схемы, но ядро v1 его не понимало; новый ключ `calibration` требовал новой версии ядра.

Решили:

1. **Перечень чтений ядра** — в [04](../04-architecture.md) §1: поля `std` и проекции индекса, которые читают проверки ядра и примитивы, — часть версии ядра. Новая версия `std`-типа из перечня не меняет смысла прочитанных полей; новое значение, которое ядро читает (вид плана, `purpose`), — новая версия ядра (ADR-34). Код проекций из перечня — слой замороженного ядра по версии, как проверки ядра (ADR-32): проекция меняется только с `kernel`.
2. **Тип политики доверия — `std/policy`**, не тип генезиса. Ядро политику не читает: её читают trust, lens, compose и run — код системы. Экземпляр по умолчанию остаётся `std/trust-policy`; `core/namespace.policy` — прежняя ссылка. Ядро проверяет только, что ссылка разрешается; тип цели (`std/policy` или наследник) проверяет 14-trust: иначе `trust()` отказывает, а не подменяет политику (как PF-03 — без запасного варианта). Новый ключ политики — новая версия `std/policy` по совместимости схемы общего типа, не версия ядра.

**Уточнено v0.6 (ADR-47, ADR-40):** место отказа — не `trust()`, а `open()` с адресом коммита (12-ledger LG-27); ревизию с такой ссылкой не собирает каталог (`setPolicy`, 15-catalog «Операции»). Перечень чтений ядра (п. 1) += проекция `authority` и `countedRun` (04 §1).

**Варианты:** (б) вынести из `core/trust-policy` только `lens`, `candidates`, `calibration` в отдельный `std`-тип — два объекта политики и две ссылки из пространства ради того, что ядро не читает ни в одном из них. (в) Только перечень, политика — в генезисе: новый ключ `calibration` по замеру R8 — новая версия ядра через ADR-34.

**Последствия:** 04-architecture (§1 — перечень, §8 — строки политики), 10-kernel (§8 — `trust-policy` из `core` в `std`), 14-trust (§4, TR-05), 11-identity-grain (политика кандидатов), 13-rules (`learning-gate` — ссылка на перечень), ADR-20 (числа окна — в `std/policy`), 02-glossary (T21, T57, T142). Генезис меняется до первых данных (SL-04) — откат дешёвый.

**Опора:** challenge-аудит F13 (E-02 = A-08), F49 (E-10); ADR-28 (довод «тип генезиса с закрытой схемой делает новый порт новой версией ядра»), ADR-32, RL-08, KR-11.
