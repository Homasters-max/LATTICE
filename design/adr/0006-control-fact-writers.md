# ADR-6. Права на факты — поле `writers` в типе факта; «текущий» — последний по `seq` среди допущенных

Статус: принято 2026-09-27 · сессия R2 · уточнено C2b

Тип факта (`core/type`) объявляет два поля. `writers` — кто вправе писать факт этого типа: владелец пространства цели, допущенные через `core/grant` или «любой» (по умолчанию — для накопительных фактов). `inForce` — когда факт действует. Примитив `owner` (13-rules) проверяет `writers` при коммите по цепочке `by` → сессия → участник (T-9: коммит без CAS, порядок — `seq`, T-6). Управляющие факты (`core/grant`, `core/retire`, `core/deprecate`, `core/alias`, отзыв версии) пишет владелец пространства цели или допущенный; накопительные (`core/assert`, `std/cue`, `used` …) — любой участник. **«Текущий» управляющий факт — последний по `seq` с этим ключом среди записей допущенных `writers`**; запись недопущенного отклоняется коммитом и «текущим» не становится; допуск проверяется на момент коммита — отзыв `core/grant` прежних записей не меняет (уточнено C2c). Поле одно — `writers` (не `authority`).

P4 («тело говорит владелец, факты — кто угодно», `00-vision`) после этого верен для накопительных фактов; текст принципа уточняется в D14 по этой ADR (принцип не меняется: управляющий факт по смыслу — решение владельца).

**Уточнено C2b (1·Q2, Q3):** значения — перечисления с порядком, чтобы наследование проверялось сравнением (ADR-12): `writers` — `owner` ⊂ `grant` ⊂ `any`, плюс `{purpose}` (⊂ `any`); `inForce` — `write` \| `{basis: X}`, `write` < `inferred` < `observed` < `derived` < `declared`. Тип факта называет роль цели полем `target` (генезис: `grant` → `namespace`, `alias` → `alias`, `member` → `group`, `retire`/`deprecate` → `object`, `holds` → `namespace`); у `core/member` — `grant`. «Накопительный» — только пустой `key`; `writers: any` — «открытый всем». Отзыв версии — `core/retire` на `id@n` (ADR-15). 10-kernel §7, KR-13.

**Варианты:** (б) «текущий» — последний в пространстве автора (15-catalog/И-9, факт живёт в пространстве автора): допускает два действующих алиаса одной сущности из разных пространств — против инварианта 3; права не проверяются при записи, а разбираются при чтении.

**Последствия:** 10-kernel (`core/type.writers`, `inForce`; §7 факты; И-29, И-30, И-12), 15-catalog (таблица «Кто что пишет», CT-04; И-7, И-9), 13-rules (`owner` проверяет `writers`), 14-trust (И-11, И-13), 11-identity-grain (И-6, И-12; кандидат в алиас — сессия R3), 23-bench (И-6), 00-vision (P4, текст), 05-slices (S3), 02-glossary (T49, T116, T117). `writers`/`inForce` — поля типа генезиса (T-10). Наследование `writers`/`inForce` по `extends` (только сужение) — вопрос сессии R3 (что наследует `extends`).
