# ADR-15. Вывод старых версий способностей в v1 — согласованный переход; строгий `pin` — со второго проекта

Статус: принято 2026-09-27 · сессия R5 · уточнено C2b

«Закреплённые ссылки работают» (CT-05, `design/domains/15-catalog.md:70`, `:92`) — для данных. Код исполняется только
при совпадении `impl.pins` и без отзыва версии (T-2, 10-kernel/И-12): рантайм отказывает, чтение `id@n` остаётся. Пока
у способности один проект-потребитель, старую версию выводит владелец согласованным переходом: сам переводит
потребителей на новую версию, затем `core/retire` на старую `id@n`. Триггер пересмотра — второй проект-потребитель: тогда строгий
`pin` и вывод по политике — `retire` с датой, после неё `broken` + `replaced_by`.

**Уточнено C2b (1·Q6):** отзыв версии — `core/retire {object: id@n}`: код ревизии не исполняется, чтение работает,
остальные версии живы; `core/retire {object: id}` — вывод объекта целиком. Отдельного типа нет (15-catalog §5, T174).

**Варианты:** (а) строгий `pin` + вывод по политике сразу — механизм дат и политики без второго потребителя, которому
он нужен; (б) выбран для v1.
**Последствия:** 15-catalog (CT-05 «вечны — для данных», §вывод из обращения), 10-kernel (отказ исполнения — T-2),
22-run (рантайм отказывает по `impl.pins`). Откат низкий, пока потребитель один.
**Опора:** Q-46 C-3, Q-47 C-3, C-4, D-42, D-43; ADR-2 (то же тело под `type@n+1` — новая ревизия).
**Реестр:** ADR-15, 15-catalog/И-12.
