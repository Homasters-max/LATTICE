# ADR-42. Кортеж исполнения — один модуль: зерно `code` — модуль, засчитанный прогон — `countedRun`

Статус: принято 2026-09-29 · сессия R1–R4 (архитектурный разбор 2026-09-29, кандидат 5)

Кортеж исполнения (T131) определён в одном месте, а сверяется в семи: отказы на старте, `Meta.model` на каждый вызов, гейт пакета «проверен стендом», выбор `bench` в `learn`, `learning-gate`, replay `code-changed`, `invalid` стенда. Запрос «засчитанный прогон кортежа» (T139) записан четырежды — runtime, `learn`, `learning-gate`, bench: разойдётся одна копия — пакет помечен «проверен стендом», а гейт отклонит обучение. Кто вычисляет `code`, не сказано: `Ident` хэша кода не несёт, модули адаптеров видит только корень сборки; пример исполнения ключует `code` по пакету (`lattice-lens`), RN-34 — по хэшу модуля. При зерне «пакет» любой релиз ломает совпадение гейта и replay.

Решили:

1. **Зерно `code` — модуль.** Сборка генерирует манифест кода — хэши модулей стадий и адаптеров; тесты его фиксируют; `code` кортежа и `impl.pins` — хэши модулей из манифеста, версия пакета — справочно (RN-34). Релиз, не тронувший модуль, не ломает `pass` и replay; правка кода не меняет `std`.
2. **`countedRun(view, tuple)` — одна чистая функция T139** в `rules/kernel-checks` (замороженное ядро, ADR-32; гейт и так там). Её читают `learning-gate`, `learn`, отметка пакета «проверен стендом» и bench. Свойство: `bench ≠ null` в пакете ⇔ гейт принимает строку обучения этого вердикта.
3. **`run/tuple`** — `capture` (кортеж вызова из `setup`, манифеста, промптов, политики), `startRefusals` (все отказы старта одной таблицей) и `matches` (сверка кортежей для replay и стенда).

**Варианты:** зерно — пакет: каждый релиз меняет кортеж; `countedRun` в run — гейт ядра не может звать run по матрице.

**Последствия:** 22-run (§1 T131, §3 — отказы старта, §6 — `learn`, §7 — `code-changed`, пример исполнения, RN-34), 13-rules (§2 — `learning-gate` через `countedRun`, §3 — `impl.pins`), 23-bench (§1 `invalid`, §5), 30-adapters (§2 — манифест кода), 04-architecture (§1 — `countedRun` в перечне), 02-glossary (T139, манифест кода). Зерно — до S0: от него `impl.pins` в `std`-JSON.

**Опора:** архитектурный разбор 2026-09-29, кандидат 5; ADR-29 (не пересматривается — одна функция его реализует), ADR-32, ADR-35; решение maintainer'а (сессия R1–R4, Q7).
