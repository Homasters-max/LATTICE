# ADR-12. `extends` наследует контракт — правила, роли, `writers`/`inForce` — только с сужением; карточка — нет

Статус: принято 2026-09-27 · сессия R3

`extends` — наследование контракта: наследник сохраняет вид предка (`identity`, `mutable`) и наследует правила и роли фактов (с ключом); всё наследуемое только сужается. Поля карточки (`card`) не наследуются — это слой LENS; заимствование карточки — ссылкой. **Совместимость (13-rules/Р-4):** правила наследника ⊇ правил родителя `@n`, схема не слабее; подстановка наследника в `ref-type` / `roles` допустима только при ролях, объявленных в контракте. Дополнения: `writers` наследника ⊆ `writers` родителя, `inForce` не слабее (иначе наследник управляющего факта обходит ADR-6); закрытость схемы (`additionalProperties`) считается по объединению свойств всей цепочки `extends`, «не слабее» — по полям родителя (иначе закрытая схема общего типа и расширение через `extends` несовместимы).

**Варианты:** (б) наследуются только правила, роли и карточка — ссылкой: роли фактов пришлось бы повторять в каждом наследнике, а подстановка в `ref-type` не опиралась бы на контракт.

**Последствия:** 10-kernel (KR-09, таблица `core/type` — строка `extends`; И-21, И-22, И-23), 13-rules (Р-4, `ref-type`, И-8 = 10-kernel/И-21), 20-lens (карточка — не по `extends`), 02-glossary (T20, T46). Откат средний: после первых наследников — перевыпуск каждого.

**Опора:** Q-10 C-1, Q-10 C-2, Q-33 C-1, Q-33 C-2, D-22, D-48; Ф-6; T-13; ADR-6. Дополнения про `writers`/`inForce` и закрытость по цепочке — довод брифа R3.

**Реестр:** ADR-12, Ф-6; определяет 10-kernel/И-21 = 13-rules/И-8.
