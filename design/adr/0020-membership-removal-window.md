# ADR-20. Удаление членства — окно: `unused` в N из последних M выдач

Статус: принято 2026-09-27 · сессия R6

Правило «`unused` в ≥ 3 разных сессиях и ни разу не `used`» (`design/domains/22-run.md:122-123`) делает удаление
почти невозможным: один давний `used` держит члена вечно. Решили: член удаляется (факт членства `value: false`), если
в N из последних M выдач он `unused`; по умолчанию 3 из 5. Выдачи считаются по группам независимости (ADR-26), сессии
стенда не считаются (T-5). N и M — числа политики `core/trust-policy` рядом с `verdict_weights` (под `policy@rev`,
T-15), M калибрует стенд. Асимметрия сохраняется: добавить — один вердикт с причиной.

**Варианты:** А «3 из 3» — требует ровно трёх выдач подряд без `used`; В доля за окно — отчёты дают только направление
(«окно вместо вечного вето»); Б сохраняет принятую асимметрию (порог не ниже 3) с запасом на редкую выдачу
(фрагмент 22-run Р-1).
**Последствия:** 22-run (калибровка членства), 14-trust (числа в политике), 05-slices (S8). Откат: числа — низкий
(ревизия политики); форма правила — высокий после первых удалений.
**Уточнено v0.5 (ADR-35):** тип политики — `std/policy` (экземпляр по умолчанию — `std/trust-policy`), не тип
генезиса.
**Уточнено v0.5 (challenge-аудит F07, F38):** удаление члена — только строкой обучения: правило типа `std/member`
требует `from` при `value: false` (22-run RN-25), поэтому строку без вердикта отклоняет коммит, а её гейт — ADR-29.
Само окно (N из M по группам) считает код `learn` — граница хоста, как `from` у писателя с допуском (T-16). `unused`
питает только окно: его вес в сумме спора — 0 по умолчанию (RN-26), иначе член, нужный в части задач потребности,
копил «−» и становился `contested` без ошибки.
**Опора:** Q-67 C-1, Q-67 C-4, D-75; T-15.
**Реестр:** ADR-20, 22-run/И-14, П-28.
