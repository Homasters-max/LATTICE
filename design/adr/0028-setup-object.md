# ADR-28. Настройка исполнения — объект `std/setup`, один на пространство; генезис не меняется

> v0.5: «один на пространство» и зерно без измерений заменены — действующая настройка — `<пространство>/setup`, прочие `std/setup` — базовые линии (уточнение ниже).

Статус: принято 2026-09-27 · сессия R4 · уточняет PF-02 (`design/proposals/PF-config.md` §3.1)

Пара «действующий конвейер + адаптеры портов с моделями» лежит в объекте типа `std/setup` — один на пространство имён (зерно без измерений, область — пространство автора, ADR-27), например `warrant/setup`. Ревизии пишет владелец пространства (правило `owner`, CT-03): смена модели или конвейера — новая ревизия, откат — ещё одна. Суть PF-02 сохраняется: конвейер и модели меняются атомарно одной ревизией, `model` — точный идентификатор версии (алиас провайдера отклоняется при запуске), вызов и план стенда закрепляют ревизию настройки (`setup@n`; поле вызова — сессия R5, план стенда — сессия R6). Тело `core/namespace` остаётся прежним: `name`, `owner`, `imports` (только здесь — D-38), `policy`, `doc`; поле `origin` — R1. Тип `core/namespace` — тип генезиса, его тело описывает 15-catalog; `std/setup` — 22-run.

```json
{ "id": "warrant/setup", "type": "std/setup@1",
  "body": { "pipeline": {"$ref": "std/pipeline.solve@1"},
            "ports": { "judge":    { "adapter": "judge-jev",       "model": "<точная версия>" },
                       "composer": { "adapter": "composer-claude", "model": "<точная версия с датой>" },
                       "source":   { "adapter": "source-warrant" } } } }
```

**Варианты:** (а) поля `pipeline`, `ports` в `core/namespace@1` (PF-02 буквально): при закрытой схеме `core` (T-13) меняют ревизию типа генезиса и хэш генезиса (T-10, 10-kernel/И-16); ядро узнаёт про `adapter`/`model` (против `design/domains/10-kernel.md:133-134`), тип `core` ссылается на `std/pipeline`, новый порт — новая версия ядра. (в) поля без схемы — против T-13. Выбран (б) — это «условие пересмотра» самого PF (C-2), выполненное заранее: частые смены модели не задевают `namespace@n`.

**Уточнено v0.5 (challenge-аудит F34):** «один на пространство» противоречил «базовая линия — ревизия настройки» (23-bench): ревизия `setup` меняла рабочий конвейер, отдельный объект нарушал «один». Действующая настройка — объект с локальным именем `setup` (`warrant/setup`), её читает вызов; прочие объекты `std/setup` пространства — базовые линии стенда. Зерно у `std/setup@1` снято (тип без зерна, identity — `id`): «один» держало оно, теперь — имя. Несколько рабочих конвейеров — «Вне объёма» 22-run с триггером (22-run RN-29, 23-bench BN-15).

**Последствия:** 15-catalog (тело `core/namespace`, PF-config:15-catalog — без `pipeline`/`ports`), 22-run (тип `std/setup`, интерпретатор берёт конвейер и порты из него), 30-adapters (модели — из `std/setup`, точной версией), 04- architecture (конфигурация проекта), 10-kernel (таблица слоёв: `setup` в `std`), 23-bench и вызов (закрепляют `setup@n` — сессии R5, R6), 02-glossary (T126). Откат низкий до S5.

**Опора:** T-10, T-13; 10-kernel/И-16, И-17; PF C-2; N-14.

**Реестр:** N-14, PF-02, PF-config:15-catalog (место полей), PF-config:30-adapters, PF-config:22-run (частично).
