# ADR-33. Первый коммит пространства — самоустановление в проверке `owner`

Статус: принято 2026-09-27 · сессия F

Проверка ядра `owner` пропускает ревизию, только если её пишет владелец пространства или допущенный (`design/domains/13-rules.md` §2), а владелец — поле `owner` тела `core/namespace` — ссылка на `core/actor`, которого тоже пишет владелец (`design/domains/14-trust.md` §1). При `init` в индексе нет ни пространства, ни владельца: первый коммит пространства по правилу не проходит (аудит F, F-5). Решили: **самоустановление**. Если проектного пространства в хранилище ещё нет, его создаёт коммит, в котором есть первая ревизия `core/namespace` и участники из её `owner`, а сессия коммита — сессия одного из этих участников; такой коммит `owner` пропускает целиком. Дальше — обычный `owner`. В хранилище v1 — одно проектное пространство: самоустановление возможно, только пока его нет.

**Варианты:** (б) особая сессия `init`, которую `owner` пропускает по имени, как `core/genesis`, — второе исключение в замороженном ядре, личность владельца первой записи не проверяется.

**Последствия:** 13-rules (строка `owner` §2), 15-catalog (§1 — первый коммит пространства), 30-adapters («Операции», `lattice init`), 05-slices (S2 — тест самоустановления и отказа второго). Проверка ядра меняется до первых данных (SL-04) — откат дешёвый, пока нет журнала проекта.

**Опора:** довод агента (аудит F); ADR-25 (реестр у владельца), ADR-32 (проверки ядра — замороженное ядро).

**Реестр:** N-132.
