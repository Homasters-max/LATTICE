# ADR-44. Replay — интерпретатор с записанными адаптерами; сквозное поведение порта — обёртка `Recording`

Статус: принято 2026-09-29 · сессия R1–R4 (архитектурный разбор 2026-09-29, кандидат 7); код — срез S5, S9

Один порт judge записывался двумя механизмами: стадия judge пишет `std/measurement` (lens), вызовы `verify` / `choose` — `calls` вызова (run). Ключ кэша `(adapter, model, prompt_hash, state_hash, norm, card)` задан в lens (§6), а живёт в каждом адаптере — фиктивному он тоже нужен, иначе «повтор из кэша» S5 не проверить. Replay был отдельной механикой рядом с интерпретатором.

Решили:

1. **Replay = тот же интерпретатор с `Deps` из записанных адаптеров** `recorded(execution)` — judge, composer, source, ids отдают записанное в трассе вызова; живой, фиктивный и записанный адаптер — три адаптера одного шва.
2. **Обёртка `Recording`** над портами LLM — сквозное поведение порта в одном месте: кэш по ключу потребителя, проверка ключей ответа (LN-18), сверка `Meta.model` с `setup` (RN-32), запись вызова в трассу. Адаптеры сжимаются до транспорта.
3. **Один механизм записи judge:** баллы стадии и вызовы `verify` / `choose` записывает обёртка; `std/measurement` остаётся событием стадии judge (что оценено), а не вторым каналом записи вызова.

Уточнено C2/F (F-gaps Н3): баллы `judge.score` записывает стадия `judge` строкой `std/measurement` в `rows` вызова (обёртка отдаёт их — живые или из кэша); вызовы `verify` / `choose` и прочие порты — обёртка в `calls`. Каналов записи два, но у каждого вида вызова — один; replay читает `score` из `std/measurement`, остальное — из `calls` (20 §6, 22 §3, §7). Над записанным адаптером `Meta.model` — модель порта из `setup@n` вызова (22 §3).

**Варианты:** (б) отложить до S5 — форма порта уже нужна фиктивным адаптерам S0 (кэш, LN-18); цена на бумаге — только текст.

**Последствия:** 22-run (§3 — `Recording`, §7 — replay), 20-lens (§5, §6 — ключ кэша у обёртки, LN-08, LN-18), 30-adapters (§1, §5 — адаптеры-транспорт). `Meta` остаётся у run (ADR-24) — переносится только поведение.

**Опора:** архитектурный разбор 2026-09-29, кандидат 7; ADR-3 (горизонт replay), ADR-19, ADR-24 — не пересматриваются; решение maintainer'а (сессия R1–R4, Q10).
