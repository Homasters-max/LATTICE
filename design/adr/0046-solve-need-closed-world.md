# ADR-46. Потребность → решение: явный автомат `solveNeed` и замкнутый мир `ClosedWorld` — отложено до S6

Статус: отложено 2026-09-29 · сессия R1–R4 (архитектурный разбор 2026-09-29, кандидат 9); триггер — подход к срезу S6

Переходы «повторной потребности» закодированы полями `done`, `outcome`, `selection.outcome`, `recall.status` в восьми стадиях; каждая следующая реализует протокол пропуска; `select` угадывает «замену сломанного члена» по `recall`; self-search выбирает сам, потому что конвейер не умеет вернуться. `check` глубокий, но типизирован на `Ctx`, а у `add[]` вердикта и CLI `materialize` `Ctx` нет. Три мира различаются: мир ссылок, источник цитаты, гранулярность отказа.

Предложение (не принято — отложено):

1. `solveNeed(need, {retrieve, judge, composer, source, view, ids}) → {rows, solution, outcome, notes}` у compose держит переходы fresh / stale / broken / empty явно; конвейер — `frame → solveNeed → deliver`.
2. `ClosedWorld` (`fromCandidates`, `live(view, scope, seq)`, `verifyQuote`, `checkSelection`) — одна проверка для вызова, вердикта и `materialize`.

**Почему отложено:** реализация — S6+; по YAGNI форма решается на коде среза, когда станет видно, сколько переходов реально нужно. ADR-18 (линейная цепочка стадий) не нарушается ни в одном варианте.

**Последствия:** 21-compose — «Вопросы для grilling» с рекомендацией принять при подходе к S6; 22-run — ссылка из §5 `verdict()`. Пересмотр — новой ADR.

**Опора:** архитектурный разбор 2026-09-29, кандидат 9; ADR-18, ADR-36; решение maintainer'а (сессия R1–R4, Q12).
