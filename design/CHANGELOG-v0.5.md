# CHANGELOG — design v0.4 → v0.5

v0.5 вносит решения по находкам challenge-аудита design v0.4 (`../challenge-audit/REPORT.md`, F01–F59). Решения
принимает пользователь по волнам; реестр — `../challenge-audit/FIX-STATE.md`. В «Почему» — опора
`v0.5 · CA-Fnn`. Базовая линия — тег `design-v0.4`; тег `design-v0.5` — после всех волн.

До волн: определение системы различает v1 и цель — VI-05 ([00-vision](00-vision.md); F26, F46, F52 — текст видения).

## Волна 1 — генезис и ядро, формат первых данных

Находки: F01, F03, F12, F13, F14, F23, F25, F26, F28, F44, F46, F49. Всё до первого запуска: граница SL-04, после
неё генезис и формат первых данных не пересчитать.

### Сквозное

- **Переход ядра** (ADR-34, T177, KR-19): ядро знает цепочку хэшей генезиса; дельту `core/*` пишет сессия
  `core/genesis-vN` отдельным коммитом, принимает владелец проекта; строка судится ядром своего коммита. Протокол —
  до первой версии ядра после первых данных (10 «Вне объёма»). F12.
- **Что ядро читает вне `core`** — перечень [04](04-architecture.md) §1, часть версии ядра (ADR-35, AR-14): поля
  `std` для `learning-gate`, значения `purpose`, проекции индекса. Тип политики доверия — `std/policy`, не тип
  генезиса; экземпляр `std/trust-policy` прежний. F13, F49.
- **Личность — заявление вызывающего** (ADR-25 уточнён, T178): хост её не проверяет, но пишет в `core/session`
  `claimed_via` (`flag` | `env` | `tty`) и `os_user`; участника `human` называет только `--as` в терминале с
  подтверждением. F01 (тяжесть — S2 по справке пользователя: `LATTICE_ACTOR` агенту задаёт оркестратор).

Находки: F02, F06, F09, F10, F15, F16, F17, F24, F33, F36, F37, F43. До S3 и S7.

### Сквозное

- **Повтор решения выдаёт текущее и проверенное.** Snapshot `stale` и при смене состава (CP-20); пустое решение —
  всегда через LENS; `by: exact` — только по подсказке в силе (CP-21); полная таблица `recall` по сводке решения
  (TR-14). F02, F17, F36.

  `materialize`. F15.
- **Время реестра** (TR-13): вид, модель, владелец, декларант — на `seq` голоса; `core/session.actor` — `actor@n`;
  следующая цель утверждения — ревизия на `seq` утверждения. F06, F33.

## Волна 3а — гейт стенда и обучение

Находки: F04, F05, F07, F08, F29, F31, F34, F35, F38, F47, F50, F52. До S8–S9. Волна 3 разделена: 3б —
исполнение, воспроизводимость, источник.

### Сквозное

- **Засчитанный прогон** (T139, ADR-29 уточнён, RL-18, BN-13): гейт засчитывает последний по `seq` прогон кортежа
  по плану `candidate` на регрессионный план, действующий на `seq` плана; более поздний `fail` закрывает; `seed` — из
  `base`; строка обучения несёт `bench` — засчитанный прогон, доказательство переживает истечение сегмента. F04, F31.
- **Политика в кортеже** (T131, CT-16, RN-24): `namespace.policy` = `id@n` (`refs: pin`); `policy@n` — в кортеже
  исполнения и в совпадении гейта; `learn` выводит строки по политике кортежа вызова. F05.
- **Метка копии и перечень `purpose`** (T180, BN-14, AD-15, TR-12): событие `std/bench-copy` первым коммитом копии;
  гейт принимает `simulate` только при нём, `open()` основного хранилища с ним — отказ; `purpose` — закрытый перечень
  хоста, гейт и доверие читают его перечнем разрешённых. F08, F50 (а).
- **Удаление члена — только строкой обучения** (RN-25, ADR-20 уточнён): `schema {required: [from]}` при
  `value: false` у `std/member`; окно — граница кода `learn`. F07.
- **`count` направлен** (RL-17): окончание факта не проверяется по `max`, установка — по `min`; ужесточённое
  правило не запирает данные. F29.
