# CHANGELOG — design v0.4 → v0.5

v0.5 вносит решения по находкам challenge-аудита design v0.4 (`../challenge-audit/REPORT.md`, F01–F59). Решения
принимает пользователь по волнам; реестр — `../challenge-audit/FIX-STATE.md`. В «Почему» — опора
`v0.5 · CA-Fnn`. Базовая линия — тег `design-v0.4`; тег `design-v0.5` — после всех волн.

До волн: определение системы различает v1 и цель — VI-05 ([00-vision](00-vision.md); F26, F46, F52 — текст видения).

## Волна 1 — генезис и ядро, формат первых данных

Находки: F01, F03, F12, F13, F14, F23, F25, F26, F28, F44, F46, F49. Всё до первого запуска: граница SL-04, после
неё генезис и формат первых данных не пересчитать.

### Сквозное

- **Переход ядра** (ADR-34, T177, KR-19): ядро знает цепочку хэшей генезиса; дельту `core/*` пишет сессия
  `core/genesis-vN` отдельным коммитом, принимает владелец проекта; строка судится ядром своего коммита. Протокол —
  до первой версии ядра после первых данных (10 «Вне объёма»). F12.
- **Что ядро читает вне `core`** — перечень [04](04-architecture.md) §1, часть версии ядра (ADR-35, AR-14): поля
  `std` для `learning-gate`, значения `purpose`, проекции индекса. Тип политики доверия — `std/policy`, не тип
  генезиса; экземпляр `std/trust-policy` прежний. F13, F49.
- **Личность — заявление вызывающего** (ADR-25 уточнён, T178): хост её не проверяет, но пишет в `core/session`
  `claimed_via` (`flag` | `env` | `tty`) и `os_user`; участника `human` называет только `--as` в терминале с
  подтверждением. F01 (тяжесть — S2 по справке пользователя: `LATTICE_ACTOR` агенту задаёт оркестратор).
