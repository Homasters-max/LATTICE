# 20. lens — поиск кандидатов

**Назначение.** По потребности вернуть 5–20 кандидатов из LATTICE с баллами, причинами и доверием — дёшево и
быстро. LENS **не выбирает** и **не разрешает действие** (P5): выбирает Composer.

**Зависит от:** [10-kernel](10-kernel.md) (виды объектов, поле типа `card`), [12-ledger](12-ledger.md) (журнал,
сегменты), [13-rules](13-rules.md) (способности, `reads`/`writes`, `impl.pins`), [14-trust](14-trust.md) (`trust()`,
`policy.lens`), [15-catalog](15-catalog.md) (живость, устаревание, индекс потребителей); контракт стадий и `Ctx` —
[22](22-run.md). Порт `judge` определяет этот домен (ADR-24); реализации — [30](30-adapters.md).
**Используют:** adapters (реализации `judge`), compose (кандидаты, `judge.verify`), хост (`aliasCandidates` после
`ensure` и импорта, [11](11-identity-grain.md) §6), run (стадии), bench (метрики поиска).

## Модель

### 1. Карточка — то, что оценивается

Поиск идёт не по блокам, а по **карточкам** (`std/card`, T71): карточка — стабильная проекция `блока@n`, значение,
адресуемое по содержимому; оценка кэшируется по её хэшу (LN-01). Сколько текста видит оценщик — параметр адаптера:
у `judge-jev` в замере черновиков — заголовок и первый абзац, 2,5 % текста документа.

```json
{ "id": "#9b1e02c4d7aa…", "type": "std/card@1",
  "body": { "of": {"$ref": "warrant/REQ-VER-007@4"},
            "title": "Waiver спасает только FAIL",
            "summary": "Waiver применяется к проверке со статусом FAIL; BLOCKED не снимает…",
            "cues": ["waiver", "исключение из проверки", "override check"] } }
```

- Тело: `of` — закреплённая ссылка на ревизию блока; `title`, `summary` — отрисовка шаблона типа; `cues` — тексты
  подсказок. Одинаковое содержимое — одна карточка; изменился блок или подсказки → новая карточка, старая оценка не
  переиспользуется.
- **Шаблон** — поле типа `card` ([10](10-kernel.md) п. 5): `{title: "<путь тела>", summary: ["<пути>"]}` или
  закреплённая ссылка на тип, чей шаблон взять (`{"$ref": "std/knowledge@1"}`). Отрисовка: строка — как есть,
  список — через запятую, ссылка — `id@n`, отсутствующий путь пропускается. Наследник по `extends` шаблон не
  наследует — заимствует ссылкой (ADR-12). Блок — объект, у типа которого есть `card` (T66).
- **Способности** — те же поля: стандартный шаблон `std/capability` —
  `{title: "title", summary: ["input", "output", "reads", "writes"]}`, строка контракта без особого случая (LN-09).
- **Подсказки в карточке** — `std/cue` ([21](21-compose.md)) на **эту ревизию** блока, в силе (основание ≥ `observed`,
  [14](14-trust.md) §7), не больше `cues_max` — по убыванию `support.plus`, при равенстве — по тексту. Подсказки
  прежней ревизии в карточку новой не переходят: они уходят в `recheck` ([22](22-run.md)) и входят снова после
  подтверждения (LN-10). Подтверждение считается по группам независимости (ADR-26): сессии одной группы — один голос.
- Текст карточки — из тела блока. Если `summary` написала LLM, это основание ревизии блока (`inferred`), а не
  свойство карточки. Достаточность карточки меряет стенд: базовая линия «по полному тексту блока» и `hit@3` по виду
  блока — [23](23-bench.md), [01](../01-first-run.md).

### 2. Типы знаний и словаря

| Тип | Вид | Тело | Зерно | Карточка |
|---|---|---|---|---|
| `std/knowledge` (T67) | сущность | `{title, summary, refs?}` — `refs`: документ, код, тесты | — | `{title: "title", summary: ["summary"]}` |
| `std/term` (T73) | сущность | `{scope: ref std/domain, label, doc?}` | `[scope, label]` | нет — термин не блок |

- Типы проектов расширяют `std/knowledge` (`warrant/norm`, [30](30-adapters.md)); шаблон — ссылкой.
- Синонимы термина — подсказки `std/cue` с целью `term` ([21](21-compose.md)). Термины области — словарь
  (lexicon, T74): один раз на запрос уходит в judge как `state`.

### 3. Пул — что оценивается

**Пул** (T77) — значение `std/pool@1` `{scope, cards: ["#…"]}`: карточки живых блоков области — членов домена
(`core/member`), не выведенных из обращения ([15](15-catalog.md)), минус исключённые политикой (`policy.lens.exclude`,
[14](14-trust.md) §4) — до judge, чтобы не платить за оценку того, что всё равно не выдаётся.

- Размер ≤ `pool_max` (по умолчанию 200) — оценивается весь; больше — предварительный отбор top-N по BM25. Блоки
  из буста (§4, `lexicon`) и кандидаты по `id` входят в пул в обход отбора. Полноту отбора меряет стенд
  (`pool-recall`, [23](23-bench.md)).
- Пул и карточки — значения в основном журнале: пишутся один раз, повторные оценки ссылаются на хэш
  ([12](12-ledger.md) §1 — то, на что ссылается трасса, не истекает).

### 4. Стадии LENS

Каждая стадия — способность `std/stage.<имя>` ([13](13-rules.md) §3): сигнатура `(ctx, params, deps) → Promise<ctx>`,
`reads`/`writes` — пути `Ctx` ([22](22-run.md) §2), код закреплён `impl.pins`. Порядок и параметры задаёт конвейер
(объект в LATTICE); конвейер v1 — линейный, без условий (Ф-5): стадия, которой нечего делать, пропускает
потребность. Пути ниже — внутри `needs[]`.

| Стадия | Что делает | `reads` | `writes` |
|---|---|---|---|
| `normalize` | регистр, ё/е, пробелы, концевая пунктуация — только обратимые для смысла правила | `text` | `norm` |
| `route` | область не задана вызывающим → сначала термины словаря, при неоднозначности `judge.choose` по описаниям доменов; два домена выше порога → находка «составная задача» (сигнал, не ветвление) | `norm`, `scope` | `scope`, `findings` |
| `id-lookup` | явные ID блоков в тексте (`REQ-…`, `ADR-…`) → прямые кандидаты с причиной `id` | `text` | `candidates` |
| `lexicon` | подсказки терминов → id терминов (ключ потребности, [21](21-compose.md)); **буст** — блоки, ссылающиеся на термин (индекс потребителей, [15](15-catalog.md) §4) | `norm`, `scope` | `terms`, `boosts` |
| `pool` | собрать пул (§3), отрисовать карточки; параметры `pool_max`, `cues_max` | `scope`, `norm`, `boosts`, `candidates` | `pool`, `rows` (значения `std/pool`, `std/card`) |
| `bm25` | лексический балл по карточкам | `norm`, `pool` | `scores.bm25` |
| `judge` | `judge.score(state = словарь + описание области, query = потребность, items = карточки)` → событие `std/measurement` (§6) | `norm`, `terms`, `pool` | `scores.judge`, `measurement` (ссылка), `rows` (`std/measurement`) |
| `fuse` | порядок: `linear` (judge + 0,3 · bm25/max, ADR-16) или `rrf`; кандидаты по `id` — впереди | `scores`, `candidates` | `scores.fused`, `candidates` |
| `trust` | `trust()` каждого кандидата; пометки `marks` по `policy.lens.mark` и устаревание `deprecated {replaced_by}`; балл не меняет | `candidates` | `candidates` |
| `threshold` | `max(scores.judge)` < `no_match` и нет кандидатов по `id` → кандидатов нет | `scores.judge`, `candidates` | `outcome` |
| `cut` | top-K (по умолчанию 20) с причинами `why` (какая стадия дала вклад) | `candidates` | `candidates` |

- **Буст балл не меняет** (LN-11): он гарантирует блоку место в пуле и даёт причину `lexicon:<термин>`; вес буста в
  `fuse` — кандидат сравнения на стенде, как `rrf`.
- **Порог «нет ответа»** (T91) читает балл judge, не `fused`: `fused` — только порядок, не [0,1] (ADR-13, ADR-16).
  Параметры стадии: `no_match` и `calibrated_for {adapter, model, prompt_hash}` (T136) — под какую версию judge
  подобран порог; подбор — сеткой на `dev` по обеим ошибкам (ложный отказ, ложный ответ), проверка — один раз на
  `test` ([23](23-bench.md)). Рантайм отказывает, если `calibrated_for` расходится с judge из `setup`
  ([22](22-run.md), ADR-28). Без `calibrated_for` стадия `no-match` не выносит: кандидаты идут дальше, в трассе —
  `threshold: uncalibrated`; отказать может `select` (LN-07).
- Стадии `recall` (повтор решения) и `select` (выбор) — в [21-compose](21-compose.md): они про потребности и решения.

### 5. Порт `judge` — три вопроса

```ts
interface Judge {
  score(r: { state: Json; query: string; items: { id: Id; text: string }[] }): Promise<Scored>
  verify(r: { state: Json; statements: string[] }): Promise<{ p: number[]; meta: Meta }>
  choose(r: { state: Json; query: string; options: { id: Id; text: string }[] }): Promise<Chosen>
  describe(): Ident                    // adapter, model, prompts: {score, verify, choose} — [22](22-run.md) §3
}
type Scored = { scores: Record<Id, number>; meta: Meta }
type Chosen = { p: Record<Id, number>; meta: Meta }
```

| Вызов | Где используется | Выход |
|---|---|---|
| `score` | релевантность карточек потребности | балл на карточку |
| `verify` | «потребность A — та же, что B?» ([21](21-compose.md)); «блок A и блок B — одно?» ([11](11-identity-grain.md) GR-06) | `p` на утверждение |
| `choose` | маршрутизация по доменам (`route`) | распределение по вариантам |

- `Meta` — сводка ответа порта, общая с `composer` ([22](22-run.md), T135): адаптер, модель, цена, время, токены.
- `state` — один раз на запрос (словарь области, описание): стабильный префикс для кэша и пакетной обработки у
  адаптера; токены не растут с числом вопросов (LN-04).
- Вопросы атомарные; композиция — в коде стадий.
- Балл и уверенность — вход для порогов и порядка, не доверие (TR-06); действие по баллу — только обратимое, ошибку
  которого ловит вердикт (ADR-13).
- Какой judge исполняет — адаптер и точная версия модели в `std/setup` ([22](22-run.md), ADR-28), не в теле
  конвейера; `prompt_hash` — от шаблона вопроса адаптера.

### 6. Оценка и кэш

Оценка — событие `std/measurement@1` (T90), сегмент исполнения ([12](12-ledger.md) §1):

```json
{ "type": "std/measurement@1",
  "body": { "need": {"$ref": "warrant/01J8…N"}, "pool": "#4c0e…",
            "judge": { "adapter": "judge-jev", "model": "<точная версия>", "prompt_hash": "sha256:…" },
            "scores": { "#9b1e…": 0.91, "#77a0…": 0.12 },
            "execution": {"$ref": "warrant/01J8…X"} } }
```

- Тело тонкое: ссылки и числа; пул — ссылкой на значение, не копией (LN-08).
- **Кэш** — ускорение, не истина (T-4): ключ `(адаптер, модель@версия, prompt_hash, state_hash, norm, card id)` →
  балл; живёт в адаптере. Попадание в кэш экономит оплату, но не запись: каждый вызов пишет
  `std/measurement` с баллами, которые использовал, в свои `rows` — и при попадании в кэш; `execution` — этот вызов.
  Ответы `verify` и `choose` — в `calls` стадии ([22](22-run.md) §3). Воспроизведение читает записи своего вызова, а не
  кэш. Смена пула
  дооценивает только новые карточки.

### 7. Выход LENS (контракт для compose)

```json
{ "need": "…", "scope": "warrant/domain.lifecycle",
  "candidates": [
    { "ref": "warrant/REQ-VER-007@4", "card": "#9b1e…", "scores": {"judge": 0.91, "bm25": 0.40, "fused": 1.03},
      "trust": { "basis": "derived", "epistemic": "settled", "support": {"plus": 0, "minus": 0}, "groups": 0,
                 "policy": "std/trust-policy@1" },
      "marks": [], "why": ["judge", "lexicon:waiver"] } ],
  "outcome": "candidates | no-match", "measurement": "warrant/MEA-01J8…" }
```

- **Кандидат** (T87): `ref`, `card`, `scores`, `trust` — выход `trust()` как есть ([14](14-trust.md), без
  `overruled`: перекрытое в пул не входит), `marks` — пометки `[{kind, replaced_by?}]` (T150), `why` — причины.
- **Значения `policy.lens`** в `std/trust-policy`: `{exclude: ["overruled"], mark: ["inferred", "contested"]}`; словарь
  состояний — значения `basis`, `epistemic` и `overruled`. Проект переопределяет ([14](14-trust.md) §4).
  `deprecated` — статус каталога, помечается всегда, вне политики; выведенное из обращения в пул не входит.

## Операции

| Операция | Вход → выход |
|---|---|
| `aliasCandidates(ids, by)` | → факты `std/alias-candidate` отдельным коммитом: `judge.verify` по карточкам кандидатов той же области ([11](11-identity-grain.md) §6, T142); вызывает хост после `ensure` и импорта |
| `lens(need, scope?)` | → выход §7; пишет `std/measurement` и значения пула и карточек в коммит прогона ([22](22-run.md)) |
| `card(block@n)` | → карточка (§1): шаблон типа + подсказки ревизии в силе; чистая функция журнала |
| `judge.score / verify / choose` | порт §5 |

## Инварианты

1. Карточка — функция `блока@n`, шаблона его типа и подсказок этой ревизии в силе: одинаковый вход — одна карточка.
2. Доверие не меняет балл: исключение — до judge по политике, остальное — пометки.
3. `threshold` читает только балл judge закреплённой версии; `calibrated_for` расходится с `setup` → рантайм отказывает.
4. Кандидаты с причиной `id` порогом не отбрасываются.
5. Каждая оценка, которую использовал вызов (оплаченная или из кэша), — событие `std/measurement` этого вызова со
   ссылкой на пул.
6. Сессии стенда (`purpose: bench`) подсказки не подтверждают (T-5, [14](14-trust.md) TR-12).

## Решения

| ID | Решение | Почему |
|---|---|---|
| LN-01 | Поиск по карточкам (значениям), а не по сырым блокам | карточка — стабильная проекция `блока@n`, кэшируется по хэшу; объём, который видит оценщик, — параметр адаптера. v0.4 · И-1 · Q-48 C-1 |
| LN-02 | Подсказки в силе (≥ `observed`, по группам независимости) входят в карточку; обучение поиска — через подсказки | один механизм алиасов, защищён доверием; сессии одной модели — один голос; эффект меряет стенд на отложенных перефразах. v0.4 · ADR-26 · T-15 · И-9, И-11 |
| LN-03 | Стадии — способности с `reads`/`writes` и `impl.pins`, конвейер — объект LATTICE, v1 линейный | самоописание (P9); `contract` проверяет порядок стадий при публикации; замена стадии — новая версия конвейера со стендом. v0.4 · T-3 · T-2 · Ф-5 |
| LN-04 | Judge — порт с тремя вызовами; `state` — один раз на запрос; контракт — здесь | заменяемая технология; `state` — стабильный префикс для кэша и пакета; экономия — свойство адаптера, цена меряется на стенде. v0.4 · ADR-24 · T-10 · И-8 |
| LN-05 | Гибрид judge + BM25, слияние `linear` по умолчанию; `fused` — только порядок | BM25 бесплатен и помогает на терминах; `rrf` — сравнение на стенде. v0.4 · ADR-16 |
| LN-06 | Доверие — пометка и фильтр по `policy.lens`, не множитель; исключение — в `pool` до judge | порядок решает стенд, политика явная; не платить за оценку невыдаваемого. v0.4 · T-14 · И-6 · П-21 |
| LN-07 | Порог «нет ответа» — по `max(scores.judge)`, привязан `calibrated_for` к версии judge, калибруется на `dev` по обеим ошибкам; без калибровки не отказывает; `id` не режет | балл разных версий несравним; отказ — действие по баллу (ADR-13): без калибровки лишнего кандидата поймает `select`, пропущенный ответ — никто. v0.4 · ADR-13 · T-14 · И-4, И-7, И-12 · Ф-10 |
| LN-08 | Каждая оценка, использованная вызовом, — событие с пулом-ссылкой в `rows` этого вызова, и при попадании в кэш; кэш — только ускорение | аудит: на каком составе получены баллы; replay читает запись своего вызова — журнал истина. v0.4 · T-4 · И-14 · C1 B5 |
| LN-09 | Карточка `{of, title, summary, cues}`; шаблон типа — пути тела или ссылка на тип; способности — тот же шаблон со строкой контракта | одна форма для знаний и способностей; шаблон — данные, не код. v0.4 · N-8 · ADR-12 · v0.3 вопрос 3 |
| LN-10 | Подсказка блока привязана к `блоку@n`; новая ревизия → `recheck`; в карточке ≤ `cues_max` (10 до замера) | подсказка не переживает смену смысла блока и не копится без предела. v0.4 · И-10 · Q-49 C-4 |
| LN-11 | Буст `lexicon` — место в пуле и причина, не слагаемое балла | закрывает висящее поле без правки ADR-16; термин не теряется при отборе BM25. v0.4 · И-5 · Q-52 C-4 |
| LN-12 | Область задаёт вызывающий; `route` — запасной путь: термины, затем `judge.choose`; составная задача — сигнал | ошибку маршрута ловят `self-search` и вердикт (ADR-13). v0.4 · v0.3 вопрос 1 |
| LN-13 | K = 20 до стенда; критерий — «эталон в выдаче» ≥ 0,95 | запас для Composer, пока нет замера. v0.4 · v0.3 вопрос 2 |
| LN-14 | `std/knowledge`, `std/term` и `std/pool` определяет этот домен | карточка, словарь и пул нужны только поиску. v0.4 · N-13 · И-14 |
| LN-15 | Семантические дубли сущностей ищет операция `aliasCandidates` — её вызывает хост после коммита `ensure` / импорта | identity lens не импортирует (AR-04); кандидат накопительный и в силу не входит — отдельный коммит безопасен. v0.4 · ADR-8 · C1 B8 |

## Вне объёма

- Эмбеддинги и векторные индексы — не сравнивались; добавляются как ещё одна стадия `std/stage.<имя>` с баллом в
  `scores`, если стенд покажет пользу.
- Вес буста и `rrf` в `fuse` — кандидаты регрессионного сравнения на стенде (S9), не значения по умолчанию.
- Ветвление конвейера по условиям — граф новой версией интерпретатора, когда путей станет > 2 ([22](22-run.md), Ф-5).
