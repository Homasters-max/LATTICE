# 30. adapters — реализации портов, корень сборки, хост и CLI

**Назначение.** Подключить внешнее — хранилище, технологию оценки, LLM, источник проекта — так, чтобы домены о нём не
знали. Контракт порта определяет домен-потребитель (ADR-24); этот домен — реализации портов, корень сборки, проводка,
хост, который открывает сессии, и CLI.

**Зависит от:** контракты портов — `store`, `clock`, `ids` ([12](12-ledger.md) §5), `judge` ([20](20-lens.md) §5),
`composer`, `source` ([21](21-compose.md) §8), `exec`, `Meta`, `describe()` ([22](22-run.md) §3); `std/setup` и операции
`solve`, `answer`, `verdict`, `learn`, `replay` ([22](22-run.md)); коммит и `open()` ([12](12-ledger.md) §2); реестр
участников, сессия, `purpose`, `software` ([14](14-trust.md) §1); обновление `std` ([15](15-catalog.md) §1); кампания
стенда ([23](23-bench.md) §3); типы `std/knowledge`, `std/term` ([20](20-lens.md) §2), `std/domain`,
`std/alias-candidate` ([11](11-identity-grain.md)), `std/bench-item`, `std/bench-set` ([23](23-bench.md) §1). Что кому
можно импортировать — матрица [04](../04-architecture.md). **Используют:** никто — корень сборки единственный
импортирует `adapters/*`.

## Модель

### 1. Порты и адаптеры

| Порт | Контракт | Адаптеры | Фиктивный (тесты, срез S0) | Позже |
|---|---|---|---|---|
| `store` | `Store` — [12](12-ledger.md) §5 | `store-jsonl` | `store-memory` | SQLite, PostgreSQL (LG-09) |
| `clock`, `ids` | `Clock`, `Ids` — [12](12-ledger.md) §5 | системные | фиксированные | — |
| `judge` | `Judge`, `Scored`, `Chosen` — [20](20-lens.md) §5 | `judge-jev` (TypeSafe) | `judge-fixture` | любая модель оценки, локальный классификатор |
| `composer` | `Composer` — [21](21-compose.md) §8 | `composer-claude` (API), `composer-caller` (агент) | `composer-fixture` | другие LLM |
| `source` | `Source`, `Place` — [21](21-compose.md) §8 | `source-warrant`, `source-files` | `source-fixture` | адаптеры других проектов |
| `exec` | `Exec` — [22](22-run.md) §3 | — (не в первом запуске, RN-10) | — | способности проектов |

- `Meta` и `describe(): Ident` портов LLM — [22](22-run.md) §3. Адаптер отдаёт в `Meta` цену, время, токены, своё —
  в `detail` (у `judge-jev` — `promptHash`, `stateHash`).
- **Контрактные тесты:** у каждого порта — общий набор; живой и фиктивный адаптер проходят один и тот же (контракт
  `Store` — [12](12-ledger.md) §5).
- **Ошибка адаптера** — `{adapter, code, status?, retryable}`, без тела и заголовков ответа поставщика: в них бывают
  ключи и данные запроса. Рантайм кладёт её в `error` стадии ([22](22-run.md) §3).
- **Код адаптера** (проверяет тест структуры; матрица — [04](../04-architecture.md)): адаптер импортирует контракт
  своего порта и ядро, но не другие адаптеры и не домены конвейера. Пакеты из `dependencies` (SDK поставщика) и
  встроенные модули ввода-вывода (`node:fs`, `fetch`, `process.env`) — только в `adapters/` и `cli/`.
- Версия контракта — в экспорте адаптера (`contract: "source@1"`); корень сборки сверяет её при сборке.

### 2. Корень сборки и проводка

**Корень сборки** (T166) `src/cli/wire.ts` — единственный модуль, который импортирует `adapters/*`: читает проводку,
открывает хранилище, берёт `std/setup` из журнала, создаёт адаптеры по `setup.ports` и собирает `Deps` (T133).

**Проводка** (`bindings`, T128) — файл `lattice.config.json`, «где лежит». «Что лежит» (конвейер, адаптеры портов,
модели) — `std/setup` в журнале (ADR-28, [22](22-run.md) §1):

```json
{ "$schema": "lattice://config/2",
  "namespace": "warrant",
  "data": ".lattice",
  "bindings": {
    "judge-jev":       { "endpoint": "https://…", "key": { "$env": "JEV_API_KEY" } },
    "composer-claude": { "key": { "$env": "ANTHROPIC_API_KEY" } },
    "source-warrant":  { "root": "D:/project/WARRANT" } } }
```

- Строгая схема. Запуск отменяется до первого вызова с путём поля, если: неизвестный ключ; значение секрета литералом, а
  не `{"$env": "NAME"}` (T127); переменной окружения нет; у адаптера из `setup.ports` нет привязки; `model` в `setup` —
  алиас провайдера (сверка `describe()` — [22](22-run.md) §3).
- **Запасного адаптера нет** (PF-03): нет ключа или привязки — отказ, а не тихая подмена (judge → только BM25).
  Запасной режим — отдельная ревизия `std/setup`; она проходит стенд как любая другая.
- Моделей в проводке нет: они только в `std/setup`, точной версией (ADR-28).
- Значения, разрешённые из `$env`, хост регистрирует в проверке «нет зарегистрированных значений». Её проходят коммит
  ([12](12-ledger.md) §2, шаг 3) и каждый писатель `.lattice/` (§4).

### 3. Хост — кто открывает сессии

**Хост** (T164) — процесс команды CLI. Он открывает сессии (ADR-25), ставит `purpose` и `software`
([14](14-trust.md) §1) и вызывает операции доменов; пишущий участник сессию сам не открывает.

- **Кто действует:** `--as <участник>`, по умолчанию — переменная `LATTICE_ACTOR`. Нет ни того ни другого — пишущая
  команда отказывает с подсказкой. Читающие команды (`explain`, `lint`, `replay`, `rebuild --check`) сессий не
  открывают. Вид и модель участника — из реестра владельца; вне реестра — `agent` с неизвестной моделью, все такие —
  одна группа `(agent, unknown)` (ADR-26). Личность хост передаёт честно — допущение модели угроз ([14](14-trust.md)
  «Вне объёма»).
- **Одна сессия на команду;** `purpose` — имя команды (`init`, `update`, `load`, `solve`, `answer`, `verdict`,
  `regrain`, `bench`). Эти значения, кроме `bench`, резервирует этот домен; `bench`, `simulate`, `learn` — их владельцы
  ([14](14-trust.md), [23](23-bench.md), [22](22-run.md)).
- **Участников `machine`** хост берёт из реестра сам: `init` регистрирует `<пространство>/learner` (сессии `learn`,
  [22](22-run.md) §6); первый `load` регистрирует участников адаптера `source` сессией владельца. `software` парсера —
  `имя@версия`; смена версии — новая сессия того же участника (T148).

| Команда | Сессии: участник · `purpose` |
|---|---|
| `init`, `update` | владелец проекта · `init` / `update`; копии `std` сохраняют сессию пакета `std/release-<версия>` ([15](15-catalog.md) §1) |
| `load` | владелец · `load` — реестр и допуски участников адаптера; парсер (`machine`, `software`) · `load`; автор обогащения (`agent`) · `load` |
| `solve`, `answer` | вызывающий (`--as`) · `solve` / `answer` |
| `verdict` | потребитель (`--as`) · `verdict`; затем `<пространство>/learner` · `learn` |
| `learn` | `<пространство>/learner` · `learn` |
| `bench` | `--as` · `bench`; симуляторы · `simulate` — только в копии кампании ([23](23-bench.md) §3) |
| `regrain` | владелец · `regrain` |

### 4. Каталог данных `.lattice/`

| Путь | Что | Писатель | Истина |
|---|---|---|---|
| `ledger.jsonl` | журнал ([12](12-ledger.md) §1) | `store-jsonl` (`append`) | да |
| `lock` | замок `{owner: процесс и сессия, expires}`; просроченный снимается | `store-jsonl` | — |
| `index.json` | кэш индекса — только после триггера LG-09 (`saveIndex`) | `store-jsonl` | нет: пересобирается |
| `recovered/` | хвост без маркера `core/commit`, отрезанный при `open()` ([12](12-ledger.md) §2) | `store-jsonl` | нет |
| `cache/judge/`, `cache/composer/` | кэши оценок и ответов (§5) | адаптеры | нет: ускорение (T-4) |
| `runs/<id>.log` | файл хода вызова (T155, [22](22-run.md) §3) | рантайм | нет; удаляется после коммита |
| `answers/<id вызова>.jsonl` | ответы агента в режиме `composer-caller` (§5) | хост `answer` | нет; удаляется после коммита вызова |
| `bench/<run>/` | копия кампании (T138, [23](23-bench.md) §3) | хост `bench` | копия; в основном журнале — `std/bench-run` с её хэшем |
| `reports/` | отчёты для человека (первый запуск — `first-run.md`) | хост | нет |

Каждый писатель проходит проверку «нет зарегистрированных значений» (AD-06, T-12). Хранилище — только локальный диск;
сетевые файловые системы не поддерживаются ([12](12-ledger.md) LG-06).

### 5. Адаптеры

#### `store-jsonl`

- Реализует `Store` ([12](12-ledger.md) §5): `append` — под замком `lock` проверка `expect`, дописывание строк и маркера
  `core/commit` с `fsync`; `scan` отдаёт только целые коммиты; `history` не реализует (есть `scan`); `saveIndex` /
  `loadIndex` — `index.json`.
- Один писатель: замок с владельцем и сроком; чужой непросроченный замок — отказ `locked`, просроченный снимается.
- Переход на SQLite (порт не меняется) — по триггеру LG-09: p95 пересборки индекса выше порога; порог — замером первого
  запуска, объём файла — справочно (ADR-23). `store-memory` — тот же контракт в памяти, для тестов.

#### `judge-jev` — технология оценки TypeSafe

- `score` → оценка релевантности каждой карточки по шкале; `verify` → вопрос «истинно ли»; `choose` → выбор из
  вариантов. Вопросы одного запроса независимы и идут параллельно; композиция — в стадиях ([20](20-lens.md) §5).
- `state` (словарь области и описание) — один раз на запрос; у `judge-jev` в замере черновиков это дало −42 % токенов.
  Это свойство адаптера, не порта: у обычной LLM тот же эффект — только кэшем префикса или пакетным вызовом; цену на
  принятый результат меряет стенд.
- `describe()` → `{adapter: "judge-jev", model, prompts: {score, verify, choose}}` — `prompt_hash` шаблонов вопросов;
  рантайм сверяет его с `std/setup` и `calibrated_for` ([22](22-run.md) §3).
- Кэш `cache/judge/` по ключу `(адаптер, модель@версия, prompt_hash, state_hash, norm, card id)` ([20](20-lens.md) §6).
  Ключ API — ссылкой `{"$env"}` из проводки.
- Исходные замеры (черновики): ~$0,002 и ~1 с на вопрос при пуле ~200 карточек; оценщик видит заголовок и первый
  абзац — 2,5 % текста документа ([20](20-lens.md) §1).

#### `composer-claude`

- Вызов модели Claude с JSON-схемой выхода; модель — из `std/setup`, точной версией (ADR-28); промпт стадии — из её
  `params`, `prompt_hash` считает рантайм ([21](21-compose.md) §8). `describe()` → `{adapter: "composer-claude", model}`.
- Кэш `cache/composer/` по ключу `(адаптер, модель@версия, prompt_hash, schema_hash, input_hash, params)`. Попадание —
  не новый ответ: трасса вызова ссылается на прежний ([22](22-run.md) §3, §7).
- Выход проверяется схемой задания; невалидный выход — ошибка стадии, не «лучшее, что получилось» (AD-05).

#### `composer-caller` — режим агента

- Модель не вызывает: задание уходит вызывающему агенту. Режим задаёт ревизия `std/setup` — `ports.composer =
  {adapter: "composer-caller", model: "<точная версия модели агента>"}`, а не флаг вызова (AD-03). `describe().model` —
  модель из `setup`: проверить её адаптер не может, это слово вызывающего, как личность у хоста.
- Протокол (ADR-19, [22](22-run.md) §3):

```text
lattice solve "<задача>"   → pending: stdout {status: "pending", execution, task: {kind, input, schema}},
                             отдельный код выхода; в журнал — ничего, файл хода — pending
lattice answer <execution> <json|@файл>
                           → ответ по схеме task (AD-05) → дописать в .lattice/answers/<execution>.jsonl
                             с ключом (kind, хэш input) → перезапуск вызова с тем же id
перезапуск                 → composer-caller отдаёт записанные ответы по ключу; первое новое задание — снова
                             pending; judge — из кэша; коммит вызова (ok или error) → файл ответов удаляется
```

- Истина — `calls` трассы `std/execution`, не файл ответов; кэша у адаптера нет (Ф-3).

#### `source-warrant` — первый проект

- `load()` (T129) отдаёт ревизии загрузки:
  - **Нормы** — парсер разбирает структуру документов WARRANT: `warrant/<внешний ID>` (`REQ-…`, `SCN-…`, `ADR-…#п`,
    `TERM-…`), тип `warrant/norm` (расширяет `std/knowledge@1`, карточка — ссылкой на его шаблон, [20](20-lens.md) §2).
    Тело — только извлечённые поля: `title`, `summary` — первый абзац нормы, `refs` (документ, код, тесты). Автор —
    сессия парсера (`machine`, `software: warrant-parser@<версия>`) → основание `derived`.
  - **Обогащение из units доменов** (370, написаны LLM) — автор `agent` `warrant/units` → `inferred`. `summary` units —
    факт `warrant/summary` (`of: {norm: ref@n}`, значение — текст; тип проекта, [14](14-trust.md) TR-09); в карточку
    не входит — служит `explain` и базовой линией стенда. Алиасы — `std/alias-candidate` (ADR-8): в силу входят только
    через `core/alias` владельца.
  - **Расхождения** парсера и units (нормы нет, другой заголовок, другой домен) — `std/load-finding` (§6).
  - **Домены:** `lifecycle` (`LCY`), `cli-core` (`CLI`) → `std/domain` + членство норм.
  - **Словарь:** `docs/02-vocabulary.md` → `std/term {scope, label, doc?}`; синонимы — подсказки `std/cue` с целью
    `term`.
  - **Набор стенда:** вопросы и эталоны → `std/bench-item` и `std/bench-set {scope, items: [ref@n]}`; данные — от
    владельца.
- Повторный `load` пишет только изменённое (no-op — [12](12-ledger.md) §2) и снимает исчезнувшие расхождения
  (`value: false`).
- `text(ref)` → `{text, revision}` — полный текст блока и ревизия содержимого источника (коммит WARRANT); ревизия
  уходит в `execution.source` (PF-04).
- `locate(ref)` → `{places: [{kind, path, lines?}]}`; `grep(q, scope)` → `Ref[]` по тексту блоков области
  (self-search); `find(q, scope?)` → `{places}` по сырому репозиторию — места для дыры покрытия ([21](21-compose.md)
  §8). Путь и строки вычисляются при чтении и не входят в identity.

#### `source-files` — простой проект

- Каталог `root` (+ `glob`): файл — блок `std/knowledge`; заголовок файла (front matter) — `id`, `title`, `domain?`,
  `refs?`; `summary` — первый абзац. Автор — участник `machine` адаптера → `derived`.
- Новый простой проект подключается проводкой, без нового адаптера; проверка — E7 первого запуска
  ([01](../01-first-run.md)).

### 6. Находка загрузки — `std/load-finding` (T165)

```json
{ "type": "std/load-finding@1", "by": "warrant/SES-…",
  "body": { "of": { "target": {"$ref": "warrant/REQ-VER-007"} },
            "value": { "kind": "title-mismatch", "note": "units: «…»; парсер: «…»" } } }
```

- Факт (`extends core/fact`, KR-13): ключ `(target, kind)`; `writers` — сессии `purpose: load`; `value: false` —
  расхождение снято следующей загрузкой.
- По журналу не пересчитывается (наблюдение внешнего источника), поэтому это факт, а не отчёт (ADR-10,
  [13](13-rules.md) RL-06). В доверие не входит; владелец видит действующие находки запросом по типу.

## Операции (CLI)

```text
lattice init                          .lattice/, генезис, core + std (update), пространство, реестр, <ns>/learner,
                                      <ns>/setup@1 ([22] §1)
lattice update                        коммит обновления std новой версии пакета ([15] §1)
lattice load                          source.load() → коммиты сессий загрузки (§5)
lattice solve "<задача>" [--scope <домен>] [--json]
                                      → пакет или pending (§5)
lattice answer <execution> <json|@файл>   ответ агента → перезапуск вызова
lattice verdict <файл|json>           коммит вердикта → попытка learn
lattice learn                         learn для вердиктов без коммита обучения ([22] §6)
lattice lint [<область>]              находки soft — отчёт ([13])
lattice regrain <тип> [--plan <файл>] перезерновка ([11])
lattice bench <план>                  кампания на копии → std/bench-run ([23])
lattice replay <execution> [--bench <run>]
                                      повтор вызова; вызов кампании — на её копии
lattice rebuild [--check]             пересборка индекса; --check — сравнить побайтно
lattice explain <ref>                 история, доверие, потребители
```

Общие флаги: `--as <участник>` (§3), `--json`. Режим стенда задаёт поле `mode` плана, не флаг ([23](23-bench.md) §1).

## Инварианты

1. `adapters/*` импортирует только корень сборки; адаптеры не импортируют друг друга; пакеты и ввод-вывод — только в
   `adapters/` и `cli/` (AD-01).
2. Живой и фиктивный адаптер порта проходят один контрактный набор (AD-07).
3. Ни один файл `.lattice/` не содержит значения секрета: в проводке — только `{"$env"}`, писатели проверяют
   зарегистрированные значения (AD-06).
4. Проводка невалидна или модель — алиас → отказ до первого вызова; адаптер не подменяется (AD-08).
5. Выход Composer — любого адаптера — проходит схему задания до стадии (AD-05).
6. Каждая пишущая команда — сессии, открытые хостом; сессию `simulate` хост открывает только в копии кампании (AD-10,
   BN-04).
7. Кэши и `answers/` — ускорение и транспорт, не истина: их потеря не теряет данных журнала (AD-09, T-4).

## Решения

| ID | Решение | Почему |
|---|---|---|
| AD-01 | Всё внешнее — через порты; `adapters/*` импортирует только корень сборки `src/cli/wire.ts` | P10, заменяемость; правило проверяемо тестом структуры. v0.4 · T-10 · И-1 · И-3 |

## Вне объёма

- Флаг вызова `--composer caller` — нет: подмена мимо `setup@n` ломает гейт обучения (D12 Q1 (б)).
- Запасной адаптер при отсутствии ключа — нет (PF-03).
- Сетевые файловые системы и несколько писателей — дальше SQLite (AD-13).
- Адаптеры вне пакета LATTICE (привязка — путь модуля и версия контракта) — когда второй проект принесёт свой адаптер.
- `summary` LLM в карточке — только по замеру стенда (D12 Q6, N-62).
- Общий `std`-тип для LLM-обогащения — со вторым адаптером ([14](14-trust.md) TR-09).
