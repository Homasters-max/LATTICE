# 14. trust — факты, утверждения, доверие

**Назначение.** Ответить «насколько этому верить» для любой ревизии и любого факта — вычислением из утверждений,
а не присвоенным статусом (P5).

**Зависит от:** [10-kernel](10-kernel.md), [12-ledger](12-ledger.md), [15-catalog](15-catalog.md) (кто владелец).
**Используют:** lens (ранжирование и пометки), compose (повтор решений), run (обучение), bench (эталоны).

## Модель

### 1. Участники и сессии

| Объект | Тело | Зачем |
|---|---|---|
| `core/actor` (сущность) | `{kind: human \| agent \| machine, name, model?}` | кто пишет; вид участника задаёт вес |
| `core/session` (сущность) | `{actor: ref, started, ended?, purpose?}` | единица независимости: два подтверждения одной сессии — одно |

Каждая ревизия несёт `by` = сессия.

### 2. Утверждение

```json
{ "id": "warrant/01J8…", "type": "core/assert@1", "version": 1, "by": "warrant/SES-…",
  "body": { "of": { "target": {"$ref": "warrant/01J8…member-fact"} }, "value": 0.5, "reason": "used in answer" } }
```

- `target` — любой факт или ревизия.
- `value` — надёжность −1…1.
- **Автор факта или ревизии неявно утверждает её с надёжностью +1.** Отдельного утверждения автора не пишется.
- От одной сессии по одной цели учитывается **последнее** утверждение (переобуться можно, накрутить нельзя).

### 3. Доверие — две оси

**Основание (`grounding`)** — откуда известно. Выбирается высшее выполненное:

| Значение | Условие (пороги — политика, п. 4) |
|---|---|
| `declared` | есть действующее «+» от человека-владельца или допущенного декларанта |
| `derived` | автор — `machine`, запись получена детерминированно из источника (разбор документа, правило) |
| `observed` | «+» из ≥ `observe_sessions` (по умолчанию 2) разных сессий |
| `inferred` | иначе: поддержка только от LLM-агентов или одной сессии |

**Состояние спора (`epistemic`)** — есть ли спор:

| Значение | Условие |
|---|---|
| `contested` | суммы «+» и «−» обе ≥ `contest_min`; или раскачка — историзуемый факт переключался ≥ `oscillation_cycles` раз |
| `unresolved` | модуль суммы < `resolve_min` |
| `settled` | иначе |

Сумма = Σ надёжность × вес вида участника. «−» от владельца (`declared` против) — решающее: факт считается
отозванным, какой бы ни была остальная поддержка.

### 4. Политика доверия — объект

```json
{ "id": "warrant/trust-policy", "type": "core/trust-policy@1",
  "body": { "weights": {"human": 1.0, "machine": 1.0, "agent": 0.5},
            "observe_sessions": 2, "contest_min": 0.5, "resolve_min": 0.5, "oscillation_cycles": 2,
            "calibration": { "add_min_verdicts": 1, "remove_unused_sessions": 3 } } }
```

Своя у каждого пространства имён (`namespace.policy`); по умолчанию — `std/trust-policy`.

### 5. Доверие составных вещей

- **Решение** (T82): доверие каждого членства отдельно; сводка решения — наименьшее основание среди членств и
  `contested`, если спорно хоть одно.
- **Блок:** основание ревизии (кто и как написал) + утверждения на ревизию + сводка вердиктов решений, где он
  участвовал ([22-run](22-run.md)).
- **Способность:** то же, плюс вердикты исполнения.

### 6. Чем доверие не является

- **Балл judge не превращается в утверждение.** Оценка — событие `std/measurement`, влияет на выдачу, но не на доверие.
- Число вызовов не является доверием: «18 000 оценок» ничего не говорит без вердиктов.
- Доверие не хранится — пересчитывается в индексе при каждом новом утверждении по затронутой цели.

### 7. Как доверие используется

| Где | Правило |
|---|---|
| повтор решения (recall) | `settled` и основание ≥ `observed` → выдать без поиска; `inferred` → выдать с пометкой «не подтверждено»; `contested` → всегда заново через LENS и Composer |
| выдача LENS | доверие — пометка и фильтр по политике, не множитель к баллу (порядок решает стенд) |
| эталоны стенда | решения `observed` / `declared` — кандидаты в эталоны |
| алиасы, подсказки | в силу — при основании, требуемом типом (`core/alias` — `declared`, `std/cue` — `observed`) |

## Операции

| Операция | Вход → выход |
|---|---|
| `assert(target, value, reason?, by)` | → событие `core/assert` |
| `trust(target)` | → `{grounding, epistemic, support: {plus, minus}, sessions}` |
| `explain(target)` | → список утверждений с весами — почему такое доверие |

## Решения

| ID | Решение | Почему |
|---|---|---|
| TR-01 | Доверие вычисляется из утверждений по двум осям | основание и спор — разные вопросы |
| TR-02 | Автор неявно утверждает +1; от сессии по цели учитывается последнее утверждение | без лишних строк, без накрутки |
| TR-03 | Независимость — по сессиям; вес — по виду участника | два «да» одной сессии — одно «да» |
| TR-04 | «−» владельца решающее | владелец отвечает за своё пространство |
| TR-05 | Пороги — объект политики пространства имён | разные проекты — разная строгость |
| TR-06 | Баллы judge и число вызовов — не доверие | P5 |
| TR-07 | `derived` — для детерминированного разбора источника | нормы, разобранные из документов парсером, надёжнее пересказа LLM |

## Вопросы для grilling

1. **Вес агента 0,5** — одинаковый для всех моделей или по модели (`actor.model`)? Рекомендация: одинаковый, пока
   нет данных; поле `model` пишется для будущего анализа.
2. **Разные сессии одного агента** — независимы? Два субагента одной задачи? Рекомендация: независимы разные
   сессии верхнего уровня; субагенты одной задачи — одна сессия (`session.parent`).
3. **Затухание доверия во времени** (старые подтверждения весят меньше)? Рекомендация: нет; устаревание решает
   статус snapshot'а (изменились версии членов), а не время.

## Вне объёма

- Криптографическая подпись утверждений.
