# 21. compose — потребности, решения, выбор

**Назначение.** Превратить задачу в атомарные потребности, найти для каждой сохранённое решение или собрать новое
из кандидатов LENS — только из блоков LATTICE (P6), с причиной для каждого члена.

**Зависит от:** kernel, identity-grain, trust, lens; порт `composer` ([30](30-adapters.md)). **Используют:** run.

## Модель

### 1. Объекты

| Объект | Тип | Вид | Тело / роли | Зерно |
|---|---|---|---|---|
| потребность | `std/need` | сущность | `{scope: ref, label, terms: [ref]}` | — (ключ потребности — индекс) |
| подсказка | `std/cue` | факт | `{of: {target: need \| block}, value: "текст"}` | накапливается |
| различие | `std/distinct` | факт | `{of: {a: need, b: need}, value: true}` | ключ `[a, b]` |
| решение | `std/solution` | сущность | `{need: ref, form: "set" \| "graph"}` | `[need]` — одно решение на потребность |
| членство | `core/member` | факт | `{of: {group: solution, member: block}, value: true \| false, reason}` | ключ `[group, member]` |
| связь | `std/link` | факт | `{of: {group: solution, from: block, to: block}, value: true \| false}` | ключ `[group, from, to]` |
| snapshot | `core/snapshot` | значение | `{of: solution, members: [ref@n], links: [[from@n, to@n]]}` | содержимое |
| пробел | `std/gap` | событие | `{need, scope, kind: "absent" \| "coverage", note}` | — |

- **Потребность** — единица повторного использования (P7). Её текстовые формулировки — подсказки; одна потребность —
  много перефразировок.
- **Ключ потребности** (T80) = `hash(область, отсортированные id терминов)` — быстрый поиск похожих; identity — ULID.
- **Решение** отвечает на **потребность, а не на задачу**: иначе разрастается до «всего, что понадобилось». Решение
  **достаточно** (по нему можно ответить) и **минимально** (у каждого члена своя причина, которую не покрывают
  остальные).
- Членство — факты: состав калибруется вердиктами без новых версий решения (P4). Snapshot фиксирует, что именно
  было выдано.
- Форма `set` — знания (набор без связей); `graph` — способности (связи с проверкой контрактов). Набор — частный
  случай графа без рёбер.

### 2. Путь одной потребности

```text
frame ─► recall ─┬─ fresh, доверие ок ─────────────────────────────► deliver (без LENS)
                 ├─ stale ─► recheck изменённых членов ─► новый snapshot ► deliver
                 ├─ broken ─► LENS по сохранённой потребности ─► select (замена пропавшего)
                 └─ нет ─► LENS ─┬─ кандидаты ─► select ─┬─ выбрано ─► check ─► deliver
                                 └─ no-match ─┐          └─ ничего не подходит ─┐
                                              └──────────► self-search (внутри LATTICE)
                                                              ├─ найдено ─► select (via: self-search) + сигнал промаха
                                                              └─ нет ─► gap: absent | coverage
```

### 3. Стадии compose

| Стадия | Кто | Что делает |
|---|---|---|
| `frame` | Composer | задача → 1…5 атомарных потребностей: одна потребность, одна область; термины из словаря; междоменная задача → несколько потребностей |
| `recall` | код + judge | ключ → потребности с тем же ключом (без `distinct`) → точный повтор нормализованного текста = та же; иначе `judge.verify("A — та же потребность, что B?")`: ≥ `same_hi` — та же; `same_lo…same_hi` — подтверждает Composer; ниже — новая |
| `recheck` | Composer | snapshot `stale`: только изменённые члены — «всё ещё отвечает на потребность?» |
| `select` | Composer | потребность + кандидаты (карточки) → 1…7 членов, у каждого причина-цитата; или «ничего не подходит» |
| `self-search` | Composer + порт `source` | промах LENS: поиск **внутри LATTICE** — по ID, в соседних доменах пространства, по тексту блоков; найденное обязано быть существующим блоком |
| `check` | код (правила) | размер 1…7; каждый член — из кандидатов или результатов self-search (закрытый мир); ссылки живые; для графа — контракты и ацикличность |

### 4. Закрытый мир (P6)

- Composer получает кандидатов и может сослаться **только на них** (или на найденное self-search). Любой другой `ref`
  отклоняет стадия `check`.
- «Ничего не подходит» различается на два случая (T93, T94):

| Случай | Что значит | Что делаем |
|---|---|---|
| **B — промах поиска** | блок есть, LENS не вернул | self-search находит → член `via: self-search`; потребность и блок → кандидат в ловушку стенда; текст потребности → кандидат в подсказку блока (`inferred`) |
| **C — пробел** | блока нет | `std/gap` `absent` — сигнал владельцу; пустое решение допустимо: snapshot закреплён на версии пула области, устаревает при любом изменении области |
| **покрытие** | в источнике проекта есть, блока нет | `std/gap` `coverage` — дыра нарезки/импорта; блок создаёт владелец или импорт, не Composer |

- Composer **никогда не создаёт блоки**. Новый блок — отдельный процесс владельца (предложение → публикация).

### 5. Формат выбора (выход Composer, проверяется схемой)

```json
{ "need": "warrant/NEED-01J8…",
  "outcome": "selected",
  "members": [ { "ref": "warrant/REQ-VER-007@4", "reason": "«Waiver применяется к проверке со статусом FAIL»" } ],
  "links": [],
  "task_only": ["warrant/ADR-0036"] }
```

`outcome`: `selected` · `none-fit` (→ self-search) · `absent` (после self-search).

## Операции

| Операция | Вход → выход |
|---|---|
| `frame(task, scopes)` | → потребности (новые или найденные) |
| `recall(need)` | → `{solution, snapshot, status}` или `none` |
| `select(need, candidates)` | → выбор |
| `selfSearch(need)` | → найденные блоки или `absent` / `coverage` |
| `check(selection)` | → нарушения |
| `materialize(need, selection, by)` | → решение, факты членства, snapshot (один коммит) |

## Решения

| ID | Решение | Почему |
|---|---|---|
| CP-01 | Потребность — сущность; формулировки — подсказки; ключ — индекс, не identity | перефразировки не плодят потребности |
| CP-02 | Одно решение на потребность (зерно `[need]`); состав — факты членства | калибровка без новых версий; одна точка доверия |
| CP-03 | Решение отвечает на потребность, не на задачу; достаточно и минимально; ≤ 7 членов | не разрастается; > 7 — разбить потребность |
| CP-04 | Набор и граф — одна модель (`form`), граф проверяется контрактами | знания и способности одним механизмом |
| CP-05 | «Та же потребность?» — сначала judge, в серой зоне — Composer | дёшево и точно |
| CP-06 | Закрытый мир: только кандидаты или self-search внутри LATTICE; проверка кодом | LLM не выдумывает блоки |
| CP-07 | Промах (B), пробел (C) и дыра покрытия — разные сигналы | B чинит поиск, C — каталог, покрытие — импорт |
| CP-08 | Причина-цитата у каждого члена обязательна | минимальность проверяема; объяснение для агента |

## Вопросы для grilling

1. **Пороги `same_hi` / `same_lo`** для «та же потребность» — начальные 0,85 / 0,5, калибровка на перефразах стенда?
   Рекомендация: да.
2. **Альтернативные решения** одной потребности (два разных набора, оба верны) — нужны? Рекомендация: нет; спор —
   через доверие членств, а не второе решение.
3. **Self-search в первом прогоне** — Composer с инструментами (поиск по ID, по тексту блоков) или только расширение
   области (все домены пространства)? Рекомендация: расширение области + поиск по тексту блоков через `source`;
   инструменты агента — позже.

## Вне объёма

- Промпты стадий — в данных конвейера (параметры стадий), черновик — при реализации среза S6.
